# Why it feels busy

It's mostly not the content. It's the **chrome**. Here's what's adding the noise, roughly from worst to least bad.

### 1. Borders nested three deep
You have the app frame, then a pane frame, then a box inside the pane. Each level costs 2 columns and 2 rows, and adds parallel lines your eye has to read past. In the Pipelines column, about 8 of the ~30 characters are border or padding. That's the main reason it feels cramped: borders are taking the space your data should have. The inner boxes don't group anything the pane borders don't already group.

**Rule of thumb:** use at most one level of separation. Whitespace and a single divider can do most of what borders do.

### 2. Everything is marked several times
- `✅ PASSED ✅` shows the same fact three times.
- `▶` appears on every row, so it doesn't mark anything. A cursor glyph is useful only when it's on the selected row alone.
- `[PASS]`, `[INFO]`, `[q]`, `:: … ::` and `...` are all punctuation used as decoration. Brackets around every token turn into texture.

### 3. Emoji break your alignment
`✅` is double-width in most terminals, which is part of why your right edges are jagged in the mockup. Use single-width glyphs (`✓ ✗ ● ○`) and let color carry the status. Measure with `lipgloss.Width()`, not `len()`.

### 4. Space goes to the wrong things
- **Logs get 3 lines**, but they're what you actually read when something fails.
- **Details takes a 7-row box** for five key/value pairs that fit in two lines.
- The logs belong to the selected job, yet they sit in a separate full-width region. Grouping them under Details makes that relationship clear.

### 5. Log lines repeat the same text
Every line repeats the date `2026-05-31` and `[INFO]`. Show only the time, and show the level only when it isn't INFO, coloring it rather than bracketing it.

### 6. Nothing has visual weight
Every element is the same brightness, so nothing stands out. A failing job should be the first thing you notice. Right now it looks the same as the passing ones.

# What I'd change it to

```
 CI Monitor                                               main · 5 pipelines · 1 failing

▌ ✓ build-api    3m 42s  │  build-api                                  ✓ passed · 3m 42s
  ✓ build-web    2m 05s  │  main · a3f9c2b
  ✗ test-unit    1m 10s  │
  ● test-e2e    running  │  14:22:01  Starting build-api
  ○ deploy-stg  waiting  │  14:22:03  Compiling sources
                         │  14:22:09  Running vet + lint
                         │
                         │
                         │

 ↑↓ navigate · enter open · tab switch pane · r refresh · q quit
```
*(Durations are made up, just for illustration.)*

What changed:
- **No outer frame and no boxes.** There's one vertical divider. The terminal window is already the frame.
- **One cursor** (`▌`, ideally plus a background highlight) on the selected row only.
- **Status is a colored glyph plus a word**: green ✓, red ✗, a yellow animated spinner for running, a dim ○ for waiting. The glyph scans quickly and the word keeps it readable without color.
- **Details shrank into a two-line header** above the logs. The logs now fill all remaining height.
- **A summary in the header bar** (`1 failing`) replaces the version number, which doesn't help anyone using the tool.
- **A dimmed help line**: keys in normal weight, descriptions faint, separated by `·`, with the most-used keys first and quit last.
- **Pane focus** (for Tab) can be shown by dimming the unfocused side or tinting the divider, without adding a border.

# Lipgloss / Bubbles specifics

- **Divider:** draw a right border only on the left pane:
  ```go
  lipgloss.NewStyle().
      Border(lipgloss.NormalBorder(), false, true, false, false).
      BorderForeground(subtle)
  ```
- **Layout:** `lipgloss.JoinHorizontal(lipgloss.Top, list, right)`, and compute the log height as `termHeight - lipgloss.Height(header) - lipgloss.Height(footer)` so it fills the screen at any size.
- **Hierarchy through brightness, not boxes:** use `Faint(true)` for timestamps, the commit hash and help descriptions. Use `lipgloss.AdaptiveColor` so it works on light and dark terminals.
- **Use the components:** `bubbles/viewport` for scrollable logs, `bubbles/spinner` for running jobs, and `bubbles/help` with `key.Binding` for the footer. The footer then looks like the second mockup with no extra work, and it also gives you short/full help toggling.
- **Optional:** sort failing pipelines to the top, or add a "failures first" toggle. On a monitoring screen, the red rows are usually the reason someone opened it.
