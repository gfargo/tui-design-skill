The main problem is **too many borders**. Most of the other noise comes from **repeating the same information**, plus a few **alignment bugs** that make the layout look slightly broken even when you can't see why.

## What's making it busy

### 1. Three levels of nested boxes
You have the app frame, then pane frames, then an inner box inside each pane. Each level costs 2 columns and 2 rows and adds more line-drawing characters. At the widest point there are six vertical bars (`│ │ │ … │ │ │`) before any content starts. Borders are supposed to separate things, but here they outnumber the things they separate. This is about 60% of the "cramped" feeling.

### 2. Every row has decoration, so none of it stands out
- `▶` appears on **every** pipeline row. A marker is only useful if it marks one thing, like the selected row.
- `[PASS]`, `[FAIL]` and `[....]` use brackets and all-caps text. That's 6 characters of punctuation-heavy text where one colored symbol would do.
- `✅ PASSED ✅` says the same thing three times.
- Each log line repeats `[INFO]`, the full date, and `::` separators. The useful part, the log message, is the least visible thing on the line.
- The footer puts brackets around every key, and keys and descriptions look the same.

### 3. Alignment drift
Look closely at your mockup:
- The pipeline rows are one column wider than their box's top border.
- `✅` is a double-width character in most terminals, so the Status line pushes its right border out by 2 cells.
- Log lines 2 and 3 are one column shorter than line 1.

Even when you can't see exactly what's wrong, borders that don't quite line up make a layout feel messy. In Lipgloss, always measure with `lipgloss.Width()` instead of `len()`, and avoid emoji in anything with a border.

### 4. Space goes to the wrong places
- The pipeline list sits in a tiny box.
- Details is mostly empty, and its "Job: build-api" just repeats what's selected in the list.
- Logs get only 3 lines, but logs are what you need most when something fails.
- At 120 columns, the mockup only uses about 80.

### 5. You can't tell which pane has focus
Every border looks the same, so `Tab` switches panes without any visible change.

What changed:
- **No nested boxes.** Whitespace and one horizontal rule do the separating. If you want borders, use one level, rounded, and only on panes.
- **Status is a colored symbol plus a word:** `✓` green, `✗` red, `●` yellow for running, `○` dim for queued. All are single-width, and the symbol still makes sense without color.
- **The selected row gets a background highlight** (`Reverse(true)` or a subtle background color) instead of a `▶` on every row.
- **Details drops the repeated job name from the body** and uses it as the heading. Labels are dim and values are normal weight.
- **Logs show the time only, with no level for INFO.** Show the level only for WARN and ERROR, and color it.
- **The footer uses bold keys and dim descriptions**, with no brackets.
- **The header shows useful summary info** ("1 failing") instead of a version number. Put the version in `--version` or a help screen.
- **Logs get most of the vertical space.** Let them grow with `msg.Height`.

## Lipgloss sketch

```go
var (
    dim     = lipgloss.NewStyle().Foreground(lipgloss.Color("244"))
    heading = lipgloss.NewStyle().Bold(true).Foreground(lipgloss.Color("245"))
    sel     = lipgloss.NewStyle().Background(lipgloss.Color("236")).Bold(true)

    statusStyle = map[Status]lipgloss.Style{
        Passed:  lipgloss.NewStyle().Foreground(lipgloss.Color("2")),
        Failed:  lipgloss.NewStyle().Foreground(lipgloss.Color("1")),
        Running: lipgloss.NewStyle().Foreground(lipgloss.Color("3")),
        Queued:  dim,
    }
    statusGlyph = map[Status]string{Passed: "✓", Failed: "✗", Running: "●", Queued: "○"}

    // Only the focused pane gets an accent; others get none (or a dim one).
    pane        = lipgloss.NewStyle().Padding(0, 1)
    focusedPane = pane.BorderStyle(lipgloss.NormalBorder()).BorderLeft(true).
                    BorderForeground(lipgloss.Color("63"))
)

func helpItem(key, desc string) string {
    return lipgloss.NewStyle().Bold(true).Render(key) + " " + dim.Render(desc)
}
```

For focus, a colored left border on just the active pane works well. It shows which pane is active without adding another box. To make sure everything fits, size panes from `tea.WindowSizeMsg` and subtract `style.GetHorizontalFrameSize()`.

If you change only one thing, remove the inner boxes. Most of the noise goes with them, and you get about 8 columns and 4 rows back for content.
