## 1. Pick a layout from the terminal width on every frame

Compute the mode from `frame.area()` inside your draw function. Ratatui redraws on `Event::Resize`, so tmux pane resizes are handled automatically as long as you don't cache the layout.

| Width | Layout |
|---|---|
| ≥ 120 | parent \| current \| preview, with the parent capped narrow |
| 90–119 | thin parent (about 16 cols) \| current \| preview |
| 60–89 | **drop the parent**: current \| preview, with the parent path shown as a breadcrumb in the header |
| 40–59 | **single column**: current only; a key (e.g. `p`/`Tab`) shows the preview full-screen |
| < 40 or < 10 rows | a "terminal too small (need 40×10)" message instead of a broken render |

The parent column matters least. It only gives context, and a breadcrumb gives the same context in one row. The preview comes next. The current directory is what users act on, so it never gets squeezed.

```rust
enum Mode { Three, ThreeSlim, Two, One, TooSmall }

fn mode_for(area: Rect) -> Mode {
    if area.width < 40 || area.height < 10 { return Mode::TooSmall; }
    match area.width {
        120.. => Mode::Three,
        90..=119 => Mode::ThreeSlim,
        60..=89 => Mode::Two,
        _ => Mode::One,
    }
}

fn columns(area: Rect, mode: &Mode) -> Vec<Rect> {
    use Constraint::*;
    let c: &[Constraint] = match mode {
        Mode::Three     => &[Max(28), Min(30), Fill(1)],
        Mode::ThreeSlim => &[Length(16), Min(30), Fill(1)],
        Mode::Two       => &[Length((area.width * 45 / 100).clamp(28, 40)), Fill(1)],
        Mode::One       => &[Fill(1)],
        Mode::TooSmall  => &[],
    };
    Layout::horizontal(c).split(area).to_vec()
}
```

Use `Length`, `Min`, `Max` and `Fill` instead of `Percentage`. Percentages are why the preview turns to mush: at 80 columns, 33% is 26 columns per pane before borders. With this setup the solver satisfies the fixed and minimum widths first, and `Fill` takes whatever is left.

## 2. Stop paying for borders

Three fully boxed panes use 6 columns and 2 rows on borders alone, which is 7.5% of an 80-column terminal. Use a single vertical divider between columns instead (`Block::new().borders(Borders::LEFT)` on panes 2 and 3) and no top or bottom borders. Put the title and path in a one-line header and the status in a one-line footer. At 80×24 that leaves you 22 rows for listings.

## 3. Truncate filenames by display width, keeping the useful ends

Truncating at the end throws away the extension, which is often the part that tells files apart. Cut from the middle instead, and measure with `unicode-width`, not `.len()` (which counts bytes) or `.chars()` (which gets CJK and emoji wrong):

```rust
use unicode_width::{UnicodeWidthChar, UnicodeWidthStr};

fn truncate_middle(name: &str, max: usize) -> String {
    if name.width() <= max { return name.to_string(); }
    if max <= 1 { return "…".into(); }
    // Keep the extension when there's room for it
    let tail_len = name.rfind('.')
        .map(|i| name[i..].width())
        .filter(|&w| w < max / 2)
        .unwrap_or((max - 1) / 2);
    let head_budget = max - 1 - tail_len;

    let mut head = String::new(); let mut w = 0;
    for ch in name.chars() {
        let cw = ch.width().unwrap_or(0);
        if w + cw > head_budget { break; }
        head.push(ch); w += cw;
    }
    let mut tail: Vec<char> = Vec::new(); let mut w = 0;
    for ch in name.chars().rev() {
        let cw = ch.width().unwrap_or(0);
        if w + cw > tail_len { break; }
        tail.push(ch); w += cw;
    }
    tail.reverse();
    format!("{head}…{}", tail.into_iter().collect::<String>())
}
```

That turns `quarterly_report_final_v3.xlsx` into `quarterly_re….xlsx`.

Truncate the breadcrumb from the **left** (`…/project/src/ui`), because the deepest directories are the ones that matter.

Drop metadata in stages too. If the list shows size and mtime, hide mtime below about 40 columns of list width and size below about 28. The filename should always get the space first.

## 4. Fit the preview to the space it actually has

- Pass the preview's real `Rect` to whatever generates it, and key your cache on `(path, width)` so the preview is rebuilt after a resize.
- Text and code: truncate lines rather than wrapping them. Wrapped code in a 30-column pane is hard to read. You could add line numbers only when the pane is wider than about 50 columns.
- Below about 25 columns of preview width, show metadata only (type, size, permissions, mtime). That's more useful than a few clipped characters of content.
- In `One` mode, show the preview as a full-screen overlay toggled by a key, and show a hint like `p: preview` in the status bar.

## 5. Handle height too

- At 24 rows or fewer, combine the header and footer into one line if you need the room.
- After a resize, make sure the selected entry is still visible. `List` with a `ListState` does this when rendering, but if you track your own scroll offset, clamp it against the new height.
- Error messages and prompts should take over the status line, not open as popups that won't fit.

## 6. Test the sizes, don't eyeball them

Render into Ratatui's `TestBackend` at a fixed set of sizes and compare snapshots (`insta` works well):

```rust
#[test]
fn layouts() {
    for (w, h) in [(220, 50), (120, 40), (100, 30), (80, 24), (60, 20), (45, 15), (30, 8)] {
        let mut term = Terminal::new(TestBackend::new(w, h)).unwrap();
        term.draw(|f| ui(f, &fixture_app())).unwrap();
        insta::assert_snapshot!(format!("{w}x{h}"), term.backend());
    }
}
```

Test the edges of each breakpoint (59/60, 89/90, 119/120), long names, names without extensions, and CJK or emoji names. For a manual check, `tmux split-window -h -l 60` and dragging the pane edge back and forth across the breakpoints will quickly show any flicker or panics. Add a `.saturating_sub()` wherever you subtract widths, because `Rect` arithmetic on `u16` is a common source of panics in tiny terminals.

## Order to tackle it

1. Switch from `Percentage` to `Length`/`Min`/`Fill`, replace boxed panes with single dividers, and add the too-small guard. That alone makes 80×24 usable.
2. Add the breakpoint modes and the breadcrumb.
3. Add width-aware filename truncation.
4. Add preview adaptation and the single-pane toggle.
5. Add snapshot tests so later changes don't break the narrow layouts.

The breakpoint numbers are starting points. Once the snapshots exist, adjust them against your real data, especially your typical filename lengths.
