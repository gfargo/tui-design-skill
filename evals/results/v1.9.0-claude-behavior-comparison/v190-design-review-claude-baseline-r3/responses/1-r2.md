The core problem is that fixed 33% columns assume width is plentiful. To fix it, decide which pane matters most, give each pane a minimum useful width, and drop or collapse panes, starting with the least important, when they can't all reach their minimums. Plan the layout from the terminal size on every frame rather than scaling one layout down.

## 1. Rank the panes and set breakpoints

For a file manager the **current** column matters most, **preview** comes second and **parent** last. The parent column mostly gives orientation, and a one-line path header does that job almost as well. Suggested tiers:

| Width | Layout |
|---|---|
| ≥ 120 | parent · current · preview, ratio about 1:2:3 (the ranger/lf style), parent capped at about 25 cols |
| 90–119 | thin parent (about 16–20 cols, names only) · current · preview |
| 60–89 | **drop parent**, show its path as a breadcrumb in the header · current · preview |
| 40–59 | **single pane**: current list only; a key (`Tab`/`p`) swaps it for a full-width preview |
| < 40 or < 10 rows | "Terminal too small (need 40×10, have 34×8)" message, no crash |

Height matters too. At 24 rows, a header, a status line and a border on each pane leave about 20 rows for the list. Don't spend rows you don't need to.

## 2. Make the layout a pure function of the area

```rust
use ratatui::layout::{Constraint, Layout, Rect};

pub enum Plan {
    TooSmall,
    Single { header: Rect, main: Rect, status: Rect },           // current OR preview
    Dual   { header: Rect, current: Rect, preview: Rect, status: Rect },
    Triple { header: Rect, parent: Rect, current: Rect, preview: Rect, status: Rect },
}

pub fn plan(area: Rect) -> Plan {
    if area.width < 40 || area.height < 10 {
        return Plan::TooSmall;
    }
    let [header, body, status] = Layout::vertical([
        Constraint::Length(1),
        Constraint::Min(0),
        Constraint::Length(1),
    ]).areas(area);

    match area.width {
        w if w >= 120 => {
            let [parent, current, preview] = Layout::horizontal([
                Constraint::Max(25).min(Fill(1)) ,  // see note below
                Constraint::Fill(2),
                Constraint::Fill(3),
            ]).areas(body);
            Plan::Triple { header, parent, current, preview, status }
        }
        w if w >= 90 => {
            let [parent, current, preview] = Layout::horizontal([
                Constraint::Length(18),
                Constraint::Min(30),
                Constraint::Fill(1),
            ]).areas(body);
            Plan::Triple { header, parent, current, preview, status }
        }
        w if w >= 60 => {
            let [current, preview] = Layout::horizontal([
                Constraint::Min(30),      // the list never drops below 30
                Constraint::Percentage(50),
            ]).areas(body);
            Plan::Dual { header, current, preview, status }
        }
        _ => Plan::Single { header, main: body, status },
    }
}
```

(Note: that first constraint isn't real API. Write it as `Constraint::Max(25)` alongside `Fill(2)`/`Fill(3)`, or compute `min(25, w / 6)` yourself and use `Length`. In current Ratatui, `Fill` with `Min`/`Max`/`Length` is the cleanest way to say "fixed-ish sidebar, the rest shared by weight.")

What this buys you:
- **Compute it inside `terminal.draw(|f| …)` from `f.area()` every frame.** Never cache it. Crossterm turns tmux pane resizes, zoom toggles and SSH window changes into `Event::Resize`, and you only need to redraw. Don't store column widths in app state.
- **It's unit-testable.** Assert `plan(Rect::new(0,0,80,24))` is `Dual`, and so on.
- **Let users override it.** Keep `show_preview: bool` / `show_parent: bool` in state. The plan picks the default for the size and the toggles override it, so someone in a narrow tmux split can still bring up the preview on demand.

## 3. Stop paying for borders

Three bordered panes cost 6 columns and 2 rows. At 60 columns that's 10% of your width. Below about 120 columns, drop `Borders::ALL` and use a single `│` separator between panes (Borders::LEFT on the second and third panes) plus the header line. Show focus with a highlighted title or a cursor-row color, not a box.

## 4. Make each pane degrade within its own width

Even at the right size, each pane has to respond to the width it gets:

- **Filenames: truncate in the middle and keep the extension.** `quarterly_report_final_v3.xlsx` should become `quarterly_rep…v3.xlsx`, not `quarterly_report_fi`. Measure with the `unicode-width` crate, not `.len()`, or CJK and emoji names will overflow or misalign.
- **Metadata columns are optional.** Show size and mtime only when the list pane is at least about 50 cols, size alone at about 35 or more, otherwise just icon + name. Drop columns before you truncate names.
- **Preview:** if it ends up narrower than about 30 cols, skip it (show the file type and size, not wrapped mush). Text previews should truncate long lines rather than soft-wrap code. Turn image protocols (sixel/kitty) off by default under tmux (`$TMUX` set), since they often break there.
- **Header breadcrumb:** when the parent column is gone, show the path, collapsing from the left: `…/src/components/forms`. Replace `$HOME` with `~`.
- **Status line:** order segments by priority and drop low-priority ones (permissions, git branch) before the selection count/position.

## 5. Handle the edge cases that crash TUIs

- Guard every `area.width - n` with `saturating_sub`. Small terminals cause underflow panics.
- Keep the selected row visible when the height shrinks: clamp the scroll offset against the new visible row count on every draw (`ListState` does this if you use it).
- Odd sizes like 47×13 or 61×19 are common in tmux. Test those, not just the round numbers.

## 6. Test across sizes automatically

Use `ratatui::backend::TestBackend` with snapshot tests (`insta` works well):

```rust
#[test]
fn renders_at_common_sizes() {
    for (w, h) in [(220, 50), (120, 40), (100, 30), (80, 24), (61, 19), (60, 20), (45, 15), (30, 8)] {
        let mut term = Terminal::new(TestBackend::new(w, h)).unwrap();
        term.draw(|f| ui(f, &fixture_app())).unwrap();
        insta::assert_snapshot!(format!("{w}x{h}"), term.backend());
    }
}
```

Use fixtures with long names, Unicode names and deep paths. These snapshots catch regressions you'd never notice on your ultrawide. For manual checks, run it in `tmux` and drag the split around, or `printf '\e[8;24;80t'` to resize terminals that support it.

## Priority order if you do this incrementally

1. Too-small guard + `saturating_sub`: no more crashes.
2. Width tiers with priority-based dropping (step 2): fixes 80×24 right away.
3. Remove borders at narrow widths.
4. Middle truncation that keeps extensions + optional metadata columns.
5. Preview toggle for the single-pane tier.
6. Snapshot tests at the sizes above.
