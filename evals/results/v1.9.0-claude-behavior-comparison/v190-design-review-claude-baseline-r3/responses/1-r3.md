The fix is to stop treating the layout as fixed. Pick a layout based on the current terminal size, decide which pane gets dropped first, and size columns by what they hold instead of by percentage. (I didn't find any Rust files in the working directory, so this is a general design plus Ratatui code you can adapt.)

## 1. Choose a layout mode on every draw

```rust
#[derive(Clone, Copy, PartialEq)]
enum LayoutMode {
    Full,     // >= 120 cols: parent | current | preview
    Compact,  // 90–119: narrow parent, current, preview
    TwoPane,  // 60–89: current | preview (parent becomes the breadcrumb)
    Single,   // 40–59: current only; preview opens full-screen on a key
    TooSmall, // < 40x10: show a "please resize" message
}

fn layout_mode(area: Rect) -> LayoutMode {
    match (area.width, area.height) {
        (w, h) if w < 40 || h < 10 => LayoutMode::TooSmall,
        (w, _) if w < 60 => LayoutMode::Single,
        (w, _) if w < 90 => LayoutMode::TwoPane,
        (w, _) if w < 120 => LayoutMode::Compact,
        _ => LayoutMode::Full,
    }
}
```

Call this inside `terminal.draw(|f| ...)` using `f.area()` (`f.size()` on older Ratatui). Ratatui resizes its buffer automatically, but you still need to handle `Event::Resize` and redraw right away. Otherwise tmux pane resizes look laggy until the next keypress.

**Rank the panes by importance:** current > preview > parent. The current directory is what users navigate with, so never shrink it to make room for the others. The parent column is the least necessary because a breadcrumb path in the header gives the same information in one row.

## 2. Use constraints instead of percentages

```rust
fn columns(area: Rect, mode: LayoutMode, longest_name: u16) -> Vec<Rect> {
    // Size the current column to fit its names, within limits
    let cur = (longest_name + 4).clamp(20, area.width * 2 / 5);
    let constraints: Vec<Constraint> = match mode {
        LayoutMode::Full => vec![
            Constraint::Fill(1).max(32), // parent never needs to be wide
            Constraint::Fill(2),
            Constraint::Fill(3),         // preview gets the extra space
        ],
        LayoutMode::Compact => vec![
            Constraint::Length(18),
            Constraint::Length(cur),
            Constraint::Min(30),
        ],
        LayoutMode::TwoPane => vec![Constraint::Length(cur), Constraint::Min(28)],
        LayoutMode::Single => vec![Constraint::Fill(1)],
        LayoutMode::TooSmall => return vec![],
    };
    Layout::horizontal(constraints).spacing(1).split(area).to_vec()
}
```

At 80 columns this gives the current column about 30 cells and the preview about 49, instead of three 26-column slices.

## 3. Stop spending space on borders

Three bordered panes use 6 columns and 2 rows on borders alone. At 80x24 that's 8% of the width. Instead:
- Separate panes with a single `│` column (`spacing(1)` plus a drawn separator), or use `Borders::LEFT` only.
- Use one header row (breadcrumb) and one status row. That leaves 22 rows for the listing at 24 rows high.
- Below about 16 rows, merge the header into the status line.

## 4. Truncate names in a way people can still read

Plain right-truncation is what turns names into mush. Cut from the middle and keep the extension:

```
quarterly-financial-report-2026-final.pdf  →  quarterly-fin…final.pdf
```

- Measure display width with the `unicode-width` crate, not `.len()`. CJK characters and emoji take two cells, and byte length will break alignment.
- Show metadata columns (size, mtime, permissions) based on the current column's width. For example, show size only above 35 cells and mtime above 50. Remove them before you shorten names.
- Breadcrumbs should truncate from the left, since the end of the path matters most: `…/src/components/forms`.

## 5. Adapt the preview to its width

- Don't soft-wrap code. Truncate each line horizontally so the file's structure stays visible.
- Below about 28 cells, a text preview isn't useful, so show compact metadata instead (type, size, line count).
- In `Single` mode, bind a key (`p` or `Enter` on a file) to open the preview full-screen, with `Esc` to go back.
- Let users toggle panes and override the automatic choice (e.g. `P` hides the preview, `-` hides the parent). Some people in tmux splits will want two panes even at 100 columns.

## 6. Handle smaller details that break on resize

- **Scroll offset:** when the height changes, recalculate the offset so the selected item stays visible.
- **Hysteresis:** if users often resize right at a breakpoint, consider a gap of 2–3 columns before switching modes so the layout doesn't flicker back and forth.
- **Too small:** draw a centered `Terminal too small (52x8) — need 40x10`. Don't let `Rect` math underflow. Use `saturating_sub` everywhere you subtract from widths.
- **SSH:** this is about latency rather than size. Only redraw on events, and load previews off the UI thread so a slow `cat` over SSH doesn't block navigation.

## 7. Test every size with snapshots

Render with `TestBackend` at each size and snapshot the result with `insta`:

```rust
#[test]
fn layouts() {
    for (w, h) in [(220, 50), (120, 40), (100, 30), (80, 24), (70, 20), (60, 20), (45, 15), (30, 8)] {
        let mut t = Terminal::new(TestBackend::new(w, h)).unwrap();
        t.draw(|f| ui(f, &fixture_app())).unwrap();
        insta::assert_snapshot!(format!("{w}x{h}"), t.backend());
    }
}
```

Use a fixture directory with long names, Unicode names and deep paths. Run this list in CI, and resizing bugs will show up as snapshot diffs.

**If you only do three things:** pick the layout from the terminal size, drop the parent column below 90 columns and show it as a breadcrumb, and replace `Percentage(33)` with content-sized constraints. Those three alone make 80x24 work well. The rest makes 60 columns and tmux splits work properly too.
