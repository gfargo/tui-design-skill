I've read through the skill's guidance on layout, clutter, and Bubble Tea. Here's the review.

**Short version:** it feels busy because almost half the screen is borders, and each pipeline's status is shown four or five times. It feels cramped because the logs, which are the part you actually read when something fails, get only 3 rows, while a Details pane repeats what the list could already show. My recommendation: delete the nested boxes, merge Details into the list as table columns, and give the logs the rest of the screen.

## The clutter, counted

| What | Count | Problem |
|---|---|---|
| **Boxes inside boxes** | Pipeline rows sit inside **3 borders**: the outer frame, the Pipelines panel and the inner list box. Details is the same. | One border is the useful maximum. The outer frame repeats the terminal's own edge. The inner boxes separate nothing. |
| **Rows that are only border** | **8 of 17 rows** contain nothing but box lines | That alone is about 47% of the height. |
| **Border characters per line** | Each Pipelines/Details line has **10 `│` characters** to show 2 columns of data | This makes the screen look like a grid, not a dashboard. |
| **Ways build-api shows "passed"** | `[PASS]`, `✅`, `PASSED`, `✅`. That's **4**, or 5–6 if they're also colored | Aim for one color plus one non-color cue at most. Passing jobs ideally get almost none, so failures stand out. |
| **Markers on every row** | `▶` on **5 of 5** pipeline rows, `[INFO]` on **3 of 3** log lines | A marker on every row marks nothing. |
| **Text repeated on every line** | The full date `2026-05-31` on every log line, `::…::` around messages, trailing `...`, `[ ]` around every status and key | Each costs cells and shows nothing new. |
| **Duplicated fields** | `Job: build-api` repeats the list row. Branch and commit are probably the same for every pipeline in a run. | A column with the same value on every row belongs in the header, once. |

## Other problems, in order of harm

1. **You can't tell which pipeline is selected.** Details shows build-api, but nothing in the list marks it. The `▶` that should do that job is on every row. Use reverse video (inverted colors) on the selected row only, and only while that pane has focus.
2. **Logs get too little space.** The main thing you do in this tool is "something's red, why?", and that answer is in the logs. With 3 visible lines you'll be scrolling all the time. When a failed job is selected, the log should open on the first failure line.
3. **No visible focus.** The footer says `[Tab] Switch Pane`, but nothing shows which pane has focus. Use a bold title or marker on the focused pane, with the accent color as a second cue that isn't the only signal.
4. **Mixed status words.** `PASS` vs `PASSED`, `WAIT`, and `[....]`. The last one looks like a loading placeholder, not "running". Pick one set: `passed / FAILED / running / queued`.
5. **The header wastes its line.** `v2.1` isn't useful while monitoring; it belongs in `?` help or `--version`. Use the header for context and freshness instead: repo, branch, commit, `updated 4s ago`. If you're not sure the data is current, it's not much of a monitor.
6. **The footer lists obvious keys.** `↑/↓ Navigate` and `Enter Select` take space, and there's no `?` for help. Change the hints with focus, put the most frequent first and `? help` last.
7. **Width bugs to check.** `✅` is 2 cells wide and `▶` is ambiguous-width (1 or 2 depending on terminal and locale), so they can push the right borders out of line. Your sketch is also only about 79 columns wide. If the real app looks like that in a 120-column window, the panes aren't being sized from `tea.WindowSizeMsg`.

## What I'd change it to

**120 columns.** The table goes on top and the log takes the remaining height. A single titled divider line replaces the boxes:

```
 CI Monitor  acme/platform · main @ a3f9c2b                                         updated 4s ago
 PIPELINE      STATUS     DURATION  STARTED
 build-api     passed        3m42s  14:22
 build-web     passed        2m10s  14:22
 test-unit     FAILED        1m05s  14:26        ← selected: reverse video; FAILED in red
 test-e2e      running       0m48s  14:27        ← yellow; duration keeps counting
 deploy-stg    queued            –      –        ← dim
 ── test-unit log ─────────────────────────────────────────────────────── following · 212 lines ──
 14:26:01  go test ./...
 14:26:44  --- FAIL: TestParseConfig (0.02s)                                 ← red; opened here
 14:26:44      config_test.go:41: expected 3 stages, got 2
 14:27:06  FAIL  github.com/acme/platform/config  1.204s
 …
 j/k move ⋅ tab focus log ⋅ enter full log ⋅ r refresh ⋅ / filter ⋅ ? help ⋅ q quit
```

What changed:
- **No boxes at all.** One divider line separates the table from the log.
- **Status is one word plus color.** Passing jobs stay quiet, so red is the first thing you see.
- **Only warnings and errors get a level tag**, and the time is shown without the date.
- **Pipelines stay in stage order** (build → test → deploy) and don't re-sort on refresh.
- **Branch and commit live in the header.** If pipelines can come from different branches, bring those columns back.

**80×24.** Same layout, nearly unchanged. Drop `STARTED` if needed. The log gets about 13 rows.

**60 columns (tmux split):**

```

 PIPELINE      STATUS    DURATION
 build-api     passed       3m42s
 test-unit     FAILED       1m05s
 test-e2e      running      0m48s
 ── test-unit log ──────────────────────── following ──
 14:26:44 --- FAIL: TestParseConfig (0.0…
 14:26:44     config_test.go:41: expected…
 j/k move ⋅ enter log ⋅ ? help
```

The stacked layout handles narrow widths easily, because only columns and the ends of log lines need to go. `w` toggles wrapping.

**Height is the real limit at small sizes:**
- The table takes at most about 40% of the height and scrolls, with a position like `3/24` in the divider.
- Below about 16 rows, switch to one pane: the table only, `Enter` opens the log full-screen, `Esc` returns.
- Below 40×10, show `Terminal too small: CI Monitor needs 40×10 (now 36×8)` and nothing else.

## Bubble Tea / Lipgloss notes

- **Sizing.** Calculate every height and width from the cached `tea.WindowSizeMsg`. In Lipgloss v2, `Width`/`Height` include the border, so `Width(w-2)` carried over from v1 comes out 2 cells too narrow.
- **Measuring text.** Use `lipgloss.Width()`, never `len()`, for anything with symbols. Using words instead of `✅`/`▶` avoids most width problems anyway.
- **Selection.** Track the selected pipeline by its ID, not its row number, so a refresh doesn't move it out from under you.
- **Logs.** Use `bubbles/viewport` with a follow mode:
  - It sticks to the bottom by default.
  - Scrolling up pauses it and shows `▾ 37 new`.
  - `G` or `F` re-pins it to the bottom.
  - Cap retained lines with a ring buffer.
- **Footer.** Build it with `bubbles/help` from a `key.KeyMap`, so it changes with focus and always matches the real keys.
- **Polling.** Fetch with `tea.Tick` and commands, never inside `Update`.
- **Styles.** Define named styles by meaning (`statusFailed`, `statusRunning`, `textMuted`) and use `LightDark` for light and dark terminals. Under `NO_COLOR` the status words still carry the meaning.
- **States to sketch next:**
  - First load: show a loading message.
  - Empty: `No pipelines for main`.
  - API unreachable: keep the old data, dimmed, with `✗ API unreachable · last update 2m ago` in the header.
  - Queued job: `No log yet — job is queued`.

The biggest single improvement is dropping the outer frame and the two inner boxes. That removes 6 of the 8 border-only rows and most of the line-drawing, before you touch anything else.
