## Diagnosis

Three things make it feel busy. Your data sits inside **three nested borders**, **status is shown 3–4 times over**, and the **logs are mostly boilerplate**, even though they're what you most need when something fails. The fix is mostly deleting things. I'd keep all the information you show today and remove most of the decoration around it.

Your sketch is about 79 columns wide, not 120, so I've treated it as your 80-column layout and shown below what 120 could look like.

## Clutter audit

**1. Border nesting is 3 deep. Aim for 1.**
- Start at the terminal edge and work in to the pipeline names: `CI MONITOR` frame → `Pipelines` panel → an untitled inner box. Details has the same three layers, and Logs has two.
- The outer frame repeats the terminal edge. The inner boxes sit inside panels that already have borders, so they don't separate anything or show focus. Delete both.
- 8 of the 17 rows are pure border. Every pipeline row starts with `│ │ │` and every Details row sits between six vertical bars. That proportion of border to data is most of the "cramped" feeling.

**2. You can't see which row is selected.**
- `▶` appears on all 5 of 5 rows, so it doesn't mark anything. Details shows `build-api`, but nothing in the list tells you that's the selected row.
- Drop the `▶` and use **reverse video** on the selected row only.
- Show focus with a **thick border on the focused pane** (`lipgloss.ThickBorder()`) plus your accent color. Tab switches panes, so the user needs a focus cue that still works without color.

**3. Status is shown 3–4 times. Aim for one color plus one word.**
- `Status: ✅ PASSED ✅` uses two checkmarks, a word, and probably a color for one fact. The list then repeats it with `[PASS]`.
- Use the bare word plus a color: `PASS` dim or green, `FAIL` red and bold, `RUN` yellow, `WAIT` dim. Drop the brackets.
- `[....]` reads as "loading/unknown", not "running", so say `RUN`.
- **Fix the emoji bug too.** `✅` is 2 cells wide, so that Status line is 2 cells wider than its neighbors. The right edges of the pipeline rows and log lines are also ragged by a cell. Ragged edges look noisy even when nobody can say why. Measure everything with `lipgloss.Width()`, never `len()`, and prefer narrow symbols (`✓ ✗`) or words.

**4. Log lines are about 60% boilerplate.**
- In `[INFO] 2026-05-31 14:22:01 :: Starting build-api ::`, only the 18-character message is real content.
- The date never changes, `[INFO]` appears on every line, and the `::` fences add nothing.
- Show only `HH:MM:SS` (dimmed). Reserve a 3-column level slot that stays blank for INFO and fills in only for `WRN`/`ERR`, so the messages stay aligned and the exceptions stand out.

**5. The panels are sized backwards.**
- Logs get 3 rows. On a failure, the log is the main thing you want to read.
- Details uses five labeled rows for facts that fit on one line, or are already visible elsewhere: the job name is the selected row, and the status is in the list.

**6. The header and footer use space poorly.**
- The header's most prominent spot holds a version number. It has no repo, no branch, and no data freshness, so a stalled poll looks exactly like "all green."
- The footer's `[key]` brackets are clutter, and `↑/↓ Navigate` explains itself. There's also no `?` for help.

## Proposed layout (120 columns)

There's one border level. Details merges into the log pane as a title plus one summary line, and the log fills the rest of the height. The pipeline list gains a duration column, using the space the inner boxes used to take.

```
 ci-monitor  acme/platform ⋅ main                                                                       updated 3s ago 
┏━ Pipelines ━━━━━━━━━━━━━━━━━━━━━━━━┓┌─ test-unit ────────────────────────────────────────────────────────────────────┐
┃ PASS  build-api             3m 42s ┃│ a3f9c2b on main ⋅ fix token refresh race ⋅ started 14:21:01                    │
┃ PASS  build-web             2m 10s ┃│                                                                                │
┃ FAIL  test-unit             1m 08s ┃│ 14:21:01       Starting test-unit                                              │
┃ RUN   test-e2e              0m 52s ┃│ 14:21:03       go test ./... -race                                             │
┃ WAIT  deploy-stg                   ┃│ 14:21:40       ok  internal/api  0.42s                                         │
┃                                    ┃│ 14:22:08  ERR  auth_test.go:88: expected 200, got 401                          │
┃                                    ┃│ 14:22:09  ERR  --- FAIL: TestRefresh (0.31s)                                   │
┃                                    ┃│                                                                                │
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛└────────────────────────────────────────────────────────────────────────────────┘
 j/k move ⋅ tab switch pane ⋅ enter full log ⋅ f follow ⋅ r refresh ⋅ q quit ⋅ ? help
```

- **Selection:** `test-unit` is drawn in reverse video (plain text can't show it). Only the focused pane shows a reverse-video selection.
- **What happened to Details:** the job name became the pane title. Status and duration live in the list. Branch and commit went onto one summary line, which also has room for the commit message.
- **Status:** each state is one word plus one color, with nothing else on passing rows.
- **Stable order:** keep pipelines in stage order rather than sorting failures to the top. Rows that jump around during live updates break spatial memory. Selecting the first failure on startup is a nice touch.

## At smaller sizes

**80×24:** keep both panes, about 30 columns for the list and 50 for the log. The commit message in the summary line truncates at the end with `…`. Drop the duration column before the names truncate.

**60 columns (tmux split):** the list takes the whole screen and needs no border, since there's no other pane to separate it from. `Enter` opens the job's summary and log full-screen, and `Esc` returns.

```
 ci-monitor ⋅ main                           updated 3s ago 

 PASS  build-api                                     3m 42s 
 PASS  build-web                                     2m 10s 
 FAIL  test-unit                                     1m 08s 
 RUN   test-e2e                                      0m 52s 
 WAIT  deploy-stg

 j/k move ⋅ enter open ⋅ r refresh ⋅ q quit ⋅ ? help
```

**Below about 40×8:** show `Terminal too small: need 40×8 (now 34×6)` instead of a broken layout. Recompute pane widths on every `tea.WindowSizeMsg`. In Lipgloss v2, `Width()` includes the border, so don't carry over v1-style `w-2` math.

## Bubble Tea notes

- **Footer:** build it from a `key.KeyMap` with `bubbles/help`, so the hints can't drift from the real bindings. It also handles short versus full help for `?`.
- **Log pane:** use `bubbles/viewport` with a follow mode (`f`). New lines auto-scroll only while following, and scrolling up pauses it.
- **Colors:** define semantic tokens such as `statusFail`, `statusPass`, `textMuted`, and `borderFocus` instead of literal colors, and resolve them with `lipgloss.LightDark`. Words carry the status, so the UI still makes sense under `NO_COLOR`.
- **Stale data:** "updated 3s ago" should turn yellow with a `!` once polling falls behind, so stale data never looks like a healthy board.
