## Recommendation

Stop treating three columns as the layout. Treat it as the widest step of a **four-step ladder**: three columns, then two, then one, then a "too small" message. Make one pure `fn(Rect) -> Columns` pick the step on every frame, from the current terminal size.

The good news is that Miller columns are only a *view* of "a cursor somewhere in a directory tree." Your navigation state (`cwd`, selection, `h`/`l`/`j`/`k`) doesn't change between steps. Only rendering does. That's why this layout degrades well, as long as you stop splitting the width into equal thirds.

When width runs out, hide the preview first, then the parent column. The current column is where the user works, so it always stays and always gets the most width.

## The ladder

| Width | Layout | What happens to the hidden pane |
|---|---|---|
| **≥ 100** | parent \| current \| preview, about `1 : 4 : 3` (yazi's default) | — |
| **80–99** | parent \| current | Preview opens full-body on `p` (or `l` on a file); `Esc` returns |
| **32–79** | current only | The parent column becomes a breadcrumb in the header; preview works as above |
| **< 32×8** | "terminal too small: need 32×8" | `q` and `Ctrl+C` still work |

The thresholds come from content minimums: parent ≥ 14 cells, current ≥ 40, preview ≥ 30, plus 1-cell gutters. You saw the preview fall apart below about 90 columns, so 100 is the three-column cutoff with some margin. Tune the numbers against your real filenames, but keep the shape.

## Implementation (Ratatui)

### 1. One pure layout function that you test without a terminal

```rust
use ratatui::layout::{Constraint, Layout, Rect};

pub const MIN_W: u16 = 32;
pub const MIN_H: u16 = 8;

pub enum Columns {
    Three { parent: Rect, current: Rect, preview: Rect },
    Two { parent: Rect, current: Rect },
    One { current: Rect },
    TooSmall,
}

pub fn columns(body: Rect) -> Columns {
    match body.width {
        100.. => {
            let parent_w = (body.width / 8).clamp(14, 30);
            let [parent, current, preview] = Layout::horizontal([
                Constraint::Length(parent_w),
                Constraint::Fill(4),
                Constraint::Fill(3),
            ])
            .spacing(1)
            .areas(body);
            Columns::Three { parent, current, preview }
        }
        80..=99 => {
            let [parent, current] = Layout::horizontal([
                Constraint::Length((body.width / 5).clamp(14, 24)),
                Constraint::Fill(1),
            ])
            .spacing(1)
            .areas(body);
            Columns::Two { parent, current }
        }
        MIN_W.. => Columns::One { current: body },
        _ => Columns::TooSmall,
    }
}
```

At 100 columns this gives 14 / 48 / 36. At 220 it gives 27 / 109 / 82. At 80 it gives 16 / 63.

In `draw`, check `frame.area()` against `MIN_W`/`MIN_H` first and render the too-small message if it fails. Otherwise split off the header and status rows, call `columns(body)`, and match on the result. If `app.preview_open` is set and the layout isn't `Three`, render the preview across the whole body. Recompute this on every draw and never cache `Rect`s between frames. A tmux pane resize is just a new `frame.area()`.

### 2. Make the columns themselves responsive, not just their count

- **Metadata columns drop by priority.** The name column always shows. Show size when the column is ≥ 36 cells and mtime when it's ≥ 56. The parent column shows names only. This is what fixes "filenames truncate to mush": you lose metadata before you lose filename characters.
- **Truncate filenames in the middle and keep the extension**, e.g. `a_really_long_genera…name.rs`. **Start-truncate the header path**, e.g. `…/src/app`, so the current directory name survives. Measure in cells with `Line::width()` or `cell_width()`, never `.len()`, and reserve one cell for `…`. Test with CJK and emoji filenames.
- **Truncate, never wrap**, inside list rows.

### 3. Spend fewer cells on chrome (clutter audit)

I haven't seen your render code, so check this. If each column is a `Block::bordered()`, that costs 6 columns and 2 rows across three panes. An outer frame on top of that adds another level of nesting and buys nothing, because the terminal edge already frames the app. At 80 columns, those borders take width the filenames need.

- Replace the per-pane boxes with `.spacing(1)`. A blank gutter, or a single `│` before the preview, is enough to separate Miller columns.
- Mark the selected row with reverse video only. Mark the current directory in the parent column the same way. Don't put a marker on every row.
- Use one header row (path, position `3/42`) and one status row. At 24 rows that leaves 22 rows for files.

### 4. Make the preview cheap and size-aware

- Only request a preview when one is visible. At 80 columns and below, don't generate previews nobody can see. That's wasted work, and over SSH it's noticeable.
- Do preview I/O off the UI thread, debounce it while the selection moves, and include the target `Rect` size in the request. On resize, re-request if the cached preview was generated for a different size (syntax-highlighted line count, image scaling).
- Keep the preview toggle stable across resizes. If someone widens from 70 to 120 columns while the full-body preview is open, drop into the three-column view with the same selection.

### 5. Keep keys identical at every width

- `h`: go to the parent directory.
- `l`/`Enter`: enter a directory, or open the preview for a file.
- `p`: toggle the preview.
- `Esc`: close the preview.

The footer hint can name `p preview` only when the preview is hidden, as in the sketches. At 60 columns the breadcrumb (`…/src/app`) is the only parent context left, so keep it in the header.

## Testing

1. **Unit-test `columns()` at each boundary:** 31/32, 79/80, 99/100, plus 220 and a height of 7. Assert which variant comes back and that no pane is narrower than its minimum. This needs no terminal.
2. **Snapshot test rendered frames** with `TestBackend` and `insta` at 220×50, 100×30, 80×24, 60×24, 32×8, and 31×8. Use size-suffixed snapshot names like `browser_60x24`, and include a directory with long, CJK, and emoji filenames.
3. **Run one manual or PTY smoke pass** inside `tmux split-window -h`, dragging the split across each breakpoint. That catches resize issues the snapshots can't.

The yazi case study in the skill (`references/exemplar-apps.md`) is worth reading. The parts that apply here are its `[1, 4, 3]` ratios and its async-first preview pipeline. Its configuration doesn't fall back to one pane at narrow widths, though, so the ladder above is the part you'll need to build yourself.
