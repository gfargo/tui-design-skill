---

**Short answer:** don't size the panes with percentages. Choose the layout from the current width. Show three panes when there's room, two at a standard 80-column terminal, and only the current pane in a 60-column split, with the preview one key away. Below the smallest size you actually support, show an honest "too small" message instead of a garbled screen. Write the layout as one pure function of the screen area, so you can test it at every size without a terminal.

## The breakpoint ladder

| Width | Layout | What gives way |
|---|---|---|
| **≥ 100 cols** | parent │ current │ preview, weighted 1:4:3. Parent is held to 14–28 cols | Nothing |
| **80–99** | current │ preview, about 50/50 | **Parent goes first.** A path header at the top replaces it |
| **40–79** | current only; `p` (or `l` on a file) opens the preview full-width, `Esc` goes back | Preview becomes on demand. The size and date columns go before the filename |
| **< 40 × 8** | `terminal too small: need 40×8 (now 34×6)`; `q` and `Ctrl+C` still work | Everything |

**Why drop the parent before the preview:** a path header like `…/src/app/` tells you where you are almost as well as the parent pane does, and `h` still goes up. A file's preview can't be shrunk into one line like that. Generic advice says the preview usually goes first, but in a file manager the preview is often why the user is there. If your users disagree, make it a setting. Either way, pick one rule and keep it.

**The current pane is the one that always stays.** It's where the user works, which is why it's the widest column (yazi defaults to `[1, 4, 3]`).

## Cut the borders first

I haven't seen your code. If each pane is a `Block::bordered()`, that's 6 columns and 2 rows of chrome in a 3-pane layout, and your 80-column terminal is really 74 usable columns. Count it:
- **Border depth:** keep it at 0 or 1. An outer frame around the whole app is always redundant; the terminal edge already frames it.
- **Separators:** use a single `Borders::LEFT` line between panes. Mark focus with reverse video on the selected row, not with a box around the pane.
- **Per-row icons and markers:** check whether a marker appears on every row. If so it carries no information, so drop it. Mark only the exceptions: the selection, broken symlinks, and so on.

## Implementation (Ratatui)

```rust
use ratatui::layout::{Constraint, Layout, Rect};

pub const MIN_W: u16 = 40;
pub const MIN_H: u16 = 8;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Plan {
    TooSmall,
    Three { parent: Rect, current: Rect, preview: Rect },
    Two { current: Rect, preview: Rect },
    One { main: Rect },
}

/// Pure: no terminal and no app state, so it can be tested at any size.
pub fn plan(body: Rect) -> Plan {
    let (w, h) = (body.width, body.height);
    if w < MIN_W || h < MIN_H {
        return Plan::TooSmall;
    }
    if w >= 100 {
        let parent_w = (w / 8).clamp(14, 28);
        let [parent, current, preview] = Layout::horizontal([
            Constraint::Length(parent_w),
            Constraint::Fill(4),
            Constraint::Fill(3),
        ])
        .areas(body);
        Plan::Three { parent, current, preview }
    } else if w >= 80 {
        let [current, preview] =
            Layout::horizontal([Constraint::Fill(1), Constraint::Fill(1)]).areas(body);
        Plan::Two { current, preview }
    } else {
        Plan::One { main: body }
    }
}
```

In `draw`, split off a 1-row header and a 1-row footer, then `match plan(body)`:
- **`One`:** the app state field `preview_open: bool` decides whether the list or the preview fills `main`. That flag only matters in this mode. If the terminal widens, you go back to showing both, and the selection is kept.
- **`TooSmall`:** render the message and return. Keep the key handling independent of layout so `q` and `Ctrl+C` still work. If you add mouse hit-testing, use the rects from the same `plan()`, not cached ones.
- **Header:** when the parent pane is hidden, show the path, cutting from the start so the deepest folder stays visible (`…/src/app/`).
- **Footer:** show `p preview` only in `One` mode. Below about 12 rows, drop the hint bar and leave `?` for help.

**Resize** needs no special code. Ratatui re-reads the size every `terminal.draw`, so redrawing on `Event::Resize` is enough. One catch: if a preview job renders to a fixed width (syntax highlighting, wrapped text, scaled images), store that width with the result. Re-request it after the size changes, debounced, and keep the old preview on screen until the new one arrives.

**Filenames:** this is the "mush" you're seeing. Columns within a pane need priorities, just like the panes do. Drop mtime when the pane is under ~50 cells and size under ~30, so the name gets the space. When a name still doesn't fit, cut it in the middle and keep the extension, measuring in terminal cells rather than bytes:

```rust
use ratatui::buffer::CellWidth; // 0.30.1+; otherwise use unicode-width

fn fit_name(name: &str, max: usize) -> String {
    if name.cell_width() as usize <= max {
        return name.to_string();
    }
    let (stem, ext) = match name.rfind('.') {
        Some(i) if i > 0 && name.len() - i <= 6 => name.split_at(i),
        _ => (name, ""),
    };
    let budget = max.saturating_sub(ext.cell_width() as usize + 1); // 1 cell for …
    let mut out = String::new();
    let mut used = 0;
    for ch in stem.chars() {
        let cw = ch.to_string().cell_width() as usize;
        if used + cw > budget {
            break;
        }
        out.push(ch);
        used += cw;
    }
    out.push('…');
    out.push_str(ext);
    out
}
```

Test it with CJK names and emoji. `.len()` would put the cut in the wrong place for those.

## Height counts too

A tmux split stacked top-and-bottom gives you width but few rows. At 24 rows you have 1 header + 1 footer + 22 list rows, which is fine. Below 12 rows, drop the footer. Below 8 rows, show the "too small" message. Keep the list scrolled so the selection stays visible after the terminal shrinks.

## Tests

1. **Unit-test `plan()`** at the widths on either side of each threshold: 220, 100, 99, 80, 79, 60, 40, 39, plus height 7. These are plain asserts and need no terminal.
2. **Snapshot frames** with `TestBackend` and `insta` at `220x50`, `80x24`, `60x24`, `60x24` with the preview open, `40x8` and `39x8`, each saved under a size-suffixed name. Snapshots capture text only, so use a `Buffer` comparison for the selection highlight.
3. **Fit names:** run CJK, emoji and very long names through `fit_name` and check the results.
4. **Check by hand** with `tmux split-window -h`, dragging the divider back and forth.

To sum up: at 80×24 you get current │ preview with the path in the header. At 60 columns you get one pane with the preview behind `p`. Below 40×8 the user sees a message naming the size they need, not a broken screen.
