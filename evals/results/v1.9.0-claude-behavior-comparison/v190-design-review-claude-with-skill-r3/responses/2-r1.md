## Verdict

Change the layout before you write any code. A fixed 2×2 grid built for one 160×50 window will fail in three ways:

- **It doesn't fit the data.** The pod list gets a quarter of the screen while the namespace list wastes a quarter.
- **It breaks at other sizes.** At 80×24 or in a tmux split there's nowhere for the panels to go.
- **The details panel can't hold what you're putting in it.** Annotations alone can fill it.

My recommendation: make the **pod table the main view**, give it **one tabbed pane below it** (Logs / Details / Events), turn the **namespace list into a picker**, and **switch to drill-down below 120 columns**. That's actually closer to how k9s works: one full-width table, with detail views you open and close.

## Proposed layout

**Wide (≥120 cols, ≥30 rows), sketched at about half scale:**
```
 prod-eu  ctx admin@prod-eu  ns payments                 42 pods   synced 2s
+- Pods ----------------------------------------------------- 3/42 -+
| NAME                 READY  STATUS            RESTARTS  AGE  NODE  |
| api-7d9f-x2k         1/1    Running                  0  4d   n-a   |
| api-7d9f-q8p         0/1    CrashLoopBackOff        17  4d   n-b   |  <- only this row is colored
+--------------------------------------------------------------------+
#= [1 Logs] 2 Details 3 Events == api-7d9f-q8p/app ======= FOLLOWING =#
# 14:02:11 starting server on :8080                                  #
# 14:02:12 panic: missing DATABASE_URL                               #
#====================================================================#
 l logs  d describe  s shell  / filter  n namespace  : resource  ? help
```
(`#`/`=` marks the focused pane's thick border.)

- Logs now get the full 160 columns instead of 78. Real log lines are often 100–200 characters.
- Events gets its own tab. For Pending and CrashLoop pods, events are usually the first thing you need, and your current design leaves them out.

**Standard (80×24):** The pod table takes the full screen. `Enter` opens the tabbed pane full-screen and `Esc` goes back. Stacking both at 24 rows leaves about 9 rows each, which is too few for either.

**Narrow (60 cols):**
```
 prod-eu / payments          3/42
 NAME                READY STATUS           AGE
 api-7d9f-q8p        0/1   CrashLoopBackOff 4d
 Enter open  / filter  n ns  ? help
```
- Columns drop in this order: NODE, then IP and QoS, then RESTARTS. NAME and STATUS are never dropped.
- Truncate names at the end with `…`, measured with `cell_width()`.

**Below your minimum** (pick one, e.g. 50×12): show `terminal too small: need 50x12` and keep `q` and `Ctrl+C` working.

## Issues, highest impact first

**1. The status colors will mislead people.**
- Coloring by pod phase marks a pod as green "Running" even when it shows `0/1` ready or 40 restarts.
- Show kubectl's computed reason as text (`CrashLoopBackOff`, `ImagePullBackOff`, `OOMKilled`, `Terminating`, `Completed`, `Evicted`) and let the color back it up.
- **Don't color healthy rows.** In a healthy namespace, 95% green rows is texture rather than information. Color only the exceptions, so the red row stands out.
- Word plus color is the right budget. Don't add icons on top.
- Red vs green is the pair people with red-green color blindness can't tell apart, and `NO_COLOR` strips color entirely, so the text has to carry the meaning on its own.

**2. Nothing shows which panel has focus.** All four rounded borders look the same, so the user can't tell where `j`/`k` will go.
- Use `BorderType::Thick` for the focused pane (it still shows with `NO_COLOR`) plus an accent color, and keep `Rounded` for the rest.
- Show the reverse-video selection only in the focused pane.

**3. The details panel can't hold "every field."** One `kubectl.kubernetes.io/last-applied-configuration` annotation can be thousands of characters on one line.
- In the Details tab, show a curated summary: status, ready, restarts, last termination reason, age, node, IPs, QoS, owner.
- Collapse labels and annotations to `labels (7) ▸`, `annotations (12) ▸`.
- Put the full YAML or describe output behind `d` or `y` as a scrollable view.

**4. The namespace panel is about 90% empty.** Ten short names in a 78×22 box is roughly 200 cells of data out of about 1,700.
- Make it an fzf-style picker on `n` or `:ns`, with an "all namespaces" entry.
- Show the current namespace in the header, which you already do.

**5. 14 keybindings won't fit in the footer even at 160 columns.**
- At about 12–14 cells per `key action ⋅` hint, 14 hints need roughly 180 cells.
- Show 5–7 hints that change with the focused pane and keep `? help` last. Drop hints from the right as the width shrinks.
- Put all 14 in a `?` modal, generated from the same keymap table so the help can't drift out of date.
- Check the keymap for these problems:
  - `Esc` should never quit.
  - `q` should go back one level, and quit only at the root.
  - `Ctrl+C` should always quit.
  - Don't bind `Ctrl+B` or `Ctrl+A`, which tmux and screen take.
  - Delete and kill need a `[y/N]` confirmation.

**6. A live log tail needs follow mode and a cap.**
- Show `FOLLOWING` vs `PAUSED ▾ 37 new` in the pane. Scrolling up pauses it; `G` or `F` re-pins it to the bottom.
- Keep a ring buffer of 10k–50k lines.
- Multi-container pods need a container picker.
- Debounce stream switching (about 200 ms) and cancel the old stream when the selection moves. Otherwise scrolling through 40 pods opens 40 log streams.
- **Strip or parse control characters in log lines**, e.g. with `ansi-to-tui`. Raw escape sequences from a container's output will corrupt your frame.

**7. Rows will jump under the cursor as data refreshes.**
- Track the selection by pod UID, not row index.
- If the selected pod disappears, select its neighbor.
- Don't re-sort on refresh.

**8. Your design only covers the happy path.** Design these states before you build:
- **Connecting:** show the frame immediately with elapsed time.
- **Empty namespace:** name the namespace and offer `n` to switch.
- **RBAC partial:** e.g. pods load but `✗ forbidden: pods/log` in the Logs tab.
- **API server unreachable:** keep the last list visible, dimmed, with `STALE 45s  reconnecting  r retry`. Don't blank the screen.

## Rust and Ratatui notes for the build

- **Startup:** use `ratatui::run()` and install `color_eyre` *before* it so the panic hook restores the terminal. If you enable mouse capture, you have to disable it yourself, because `restore()` won't.
- **Background work:** run `kube-rs` watchers and reflectors in Tokio tasks that send results over an `mpsc` channel. Redraw only when something changed (a dirty flag), not on every tick.
- **Rendering:** use `Table` + `TableState` for the pod list. `Ctrl+Z` does nothing unless you bind it yourself.
- **Layout:** write a pure `fn layout(area: Rect) -> Layout` and test the breakpoints without a terminal.
- **Tests:** snapshot frames with `TestBackend` + `insta` at 160×50, 80×24, 60×20, and your minimum.

To sum up: keep the header, the footer, and the color meanings, but put the pod table first, the other views in tabs, and the namespaces in a picker, and plan what happens at 80 and 60 columns. If you send me your 14 keybindings, I can check them for conflicts and pick which ones go in the footer.
