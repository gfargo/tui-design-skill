**Recommendation:** don't build the fixed 2×2 grid. Make the pod list the main view and drop the namespace panel; the namespace can live in the header and change through a picker. Details and logs should share one pane at wide sizes and open as a full-screen view at narrower ones. The grid only works at 160×50, and it spends a quarter of the screen on a value you change a few times per session.

Here's the reasoning, roughly in order of how much each issue would hurt users.

## 1. The grid breaks below your own window size

A layout built for one window size isn't finished. Teammates, laptops, tmux splits and SSH sessions to a bastion host won't be 160×50. Here is your grid at 80×24, after the header, footer and four border rows:

- Each quadrant has about **38×8 usable cells**.
- **Pod list:** a typical name like `payments-api-7d9f8b6c5-x2kqz` is 28 columns, which leaves about 10 for READY, STATUS, RESTARTS and AGE. That doesn't fit.
- **Details:** 8 rows covers name through node. Labels, annotations and conditions are cut off.
- **Logs:** 38 columns means nearly every line is truncated or wraps three times.
- **At 60 columns** a 2×2 grid has nowhere to go. It needs a single-pane fallback.

A drill-down layout handles this well because only one main thing is ever on screen; when the window narrows, it just gets narrower. That's also how k9s actually works: the list is full-screen and Enter drills in. Your grid is closer to lazygit's layout than to k9s.

### Proposed layout

```
 esc back ⋅ tab next tab ⋅ y yaml ⋅ ? help
```

**Narrow (60 columns):** same model, with lower-priority columns dropped (READY, then AGE).

```
 payments                          4 pods  ? help
 NAME            STATUS            RST
 api-7d…x2kqz    CrashLoopBackOff   14
 enter open ⋅ / filter ⋅ ? help
```

**Too small (e.g. under 40×10):** show `terminal too small: need 40x10` and keep `q` and Ctrl+C working.

Two related details:
- **Truncate pod names in the middle.** The unique hash is at the end, so cutting the tail makes every replica look the same.
- **Namespace:** use `n` or `:ns` to open a filterable picker overlay, plus an "all namespaces" option. You're already showing the namespace in the header, so the panel was saying the same thing twice.

## 2. The details panel will overflow

"Every field" includes annotations, and `kubectl.kubernetes.io/last-applied-configuration` alone is often several KB of JSON. Show a fixed summary instead: status, ready, restarts, node, IPs, QoS, age and owner. Show labels and annotations as counts, with the full values one key away (`d` for describe, `y` for YAML). Truncate inside the panel rather than wrapping.

## 3. Color coding: color alone, and phase is the wrong signal

- **Color can't be the only signal.** About 8% of men have red-green color blindness, and Crossterm drops all color when `NO_COLOR` is set. Keep the STATUS text column. That's the right budget: the word plus one color. Don't add an icon as a third signal.
- **Color by health, not phase.** Three colors don't cover real pod states:
  - `Running` with `0/1` ready, or with 14 restarts, is unhealthy but would show green.
  - `Completed` would be wrongly flagged as a failure if colored red; make it dim.
  - Also decide on `Terminating`, `ContainerCreating`, `ImagePullBackOff`, `OOMKilled`, `Evicted` and `Unknown`.
- **Define semantic tokens** (`status.ok`, `status.warn`, `status.error`, `text.muted`) mapped to ANSI colors, not RGB values, so they follow the user's terminal theme.

## 4. Focus is unspecified

With four panes, the user has to be able to see which one takes keystrokes. You only described rounded borders, which have no heavy variant. I'd use `BorderType::Plain` for unfocused panes and `BorderType::Thick` for the focused one, with the accent color added on top. Only the focused pane should show the reverse-video selected row.

## 5. Fourteen keybindings in the footer

That's about 140+ cells, which barely fits at 160 and won't at 80. Show the 5–6 most-used keys for the focused pane, with `?` last, and drop hints from the right as the width shrinks. Put all 14 behind `?`. Ratatui doesn't generate a footer for you, so define the keymap once and build both the footer and the help screen from it.

## 6. Live data and logs: details that will bite

- **Track the selected pod by its UID, not its row number.** Otherwise each watch update moves the cursor. If the pod disappears, select its nearest neighbor. Don't re-sort on every refresh.
- **The log pane follows the selection.** When the user scrolls quickly through the list, wait about 200 ms before opening a stream, and cancel the previous one. Otherwise you'll open dozens of streams.
- **Crashlooping pods need previous logs.** The live tail of a restarting container is usually empty. Those red pods are exactly the ones you'll open, so add `p` for previous-container logs.
- **Multi-container pods:** show which container you're viewing in the pane title and add a key to cycle containers.
- **Follow mode:** follow by default. Any upward scroll pauses it and shows `▾ 37 new`, and `G` or `F` resumes. Keep logs in a fixed-size buffer and say when old lines are dropped.

## 7. Clutter audit

- **Border nesting:** one level, which is fine.
- **Screen cost of chrome:** header, footer and borders take 6 of 50 rows at 160×50 (12%), but 6 of 24 at 80×24 (25%).
- **Namespace panel:** about 24% of the screen for a rarely changed value already shown in the header. Cut it.
- **Always-on content:** labels and annotations shown for every pod. Cut them to counts.

## 8. States to design up front

- **Loading:** resolving the context, or the first list call.
- **Empty namespace:** for example "No pods in payments. n change namespace".
- **RBAC forbidden:** very common with namespace-scoped roles. Don't show this as an empty list.
- **API unreachable:** keep the last known rows, dimmed, with a `STALE 2m` marker.
- **Pod deleted while open.**
- **Log stream ended, or container not started yet.**
- **Too small.**

## Rust/Ratatui notes for when you start

- **Never fetch in `draw`.** Run kube-rs watchers in Tokio tasks and send results over an `mpsc` channel. Redraw only after an event or data change.
- **Startup:** call `color_eyre::install()`, then `ratatui::run(...)`, so panics restore the terminal.
- **Shell (`s`, i.e. `kubectl exec`):** stop the input reader, restore the terminal, run the child process, re-enter, `terminal.clear()`, then reload the data. Ctrl+Z suspend isn't handled for you in raw mode, so bind it yourself.
- **Layout:** write a pure `fn layout(area: Rect) -> Plan` returning Wide, Standard, Narrow or TooSmall. Snapshot it with `TestBackend` and `insta` at 160×50, 80×24, 60×20 and your minimum. `insta` snapshots ignore color, so use `Buffer` comparisons to check status styling.

One question before you lock the keymap: which of the 14 bindings are destructive, such as deleting a pod? Put those on a key that isn't next to a read-only action like describe, and require a confirmation.
