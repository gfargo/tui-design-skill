I'd change the layout before writing any code. A fixed 2×2 grid built around a 160×50 window has nowhere to go when the terminal gets smaller. It also gives a permanent quarter of the screen to namespaces, which you switch rarely, and it starts a log stream for every pod your cursor passes over.

My recommendation: one main pod list, plus a single tabbed pane (**Logs | Details | Events**) beside it on wide terminals. On narrower ones, Enter opens that pane full-screen and Esc comes back. Namespaces become a picker you open with a key, and the current namespace shows in the header. Most of what's good about k9s comes from this drill-down shape.

## Proposed layout

**Wide (≥120 cols)**, shown at roughly half scale:

```
 prod-eu  ctx: admin@prod-eu  ns: payments                    42 pods  live
+- Pods 3/42 ---------------------------++- [Logs 1] Details 2  Events 3 -------+
| NAME              READY STATUS    RST ||  api-7d9f8b-x2k4p / app   following   |
| api-7d9f8b-x2k4p  1/1   Running     0 || 14:02:11 GET /health 200 1ms          |
| worker-5c4-ab12   0/1   CrashLoop  12 || 14:02:12 GET /orders 200 14ms         |
| batch-91x-zz8     0/1   Pending     0 || 14:02:12 POST /pay 502 upstream...    |
|                                       ||                                       |
+---------------------------------------++---------------------------------------+
 enter open  l logs  / filter  n namespace  d describe  ? help
```

**Standard, 80×24:** the list fills the screen. Enter or `l` opens the pane full-screen, and Esc goes back.

```
 prod-eu / payments                                        42 pods  live
+- Pods 3/42 --------------------------------------------------------------+
| NAME                     READY  STATUS            RESTARTS  AGE           |
| api-7d9f8b-x2k4p         1/1    Running                  0  4d            |
| worker-5c4-ab12          0/1    CrashLoopBackOff        12  2h            |
+---------------------------------------------------------------------------+
 enter open  l logs  / filter  n namespace  ? help
```

**Narrow, 60 cols (a tmux split):** the same single pane. Low-priority columns drop in this order: NODE, IP, AGE, READY. Long names are cut in the middle, so both the deployment prefix and the replica hash stay visible.

```
 payments                                    42 pods  live
+- Pods 3/42 ------------------------------------------+
| NAME                 STATUS            RESTARTS      |
| api-7d9…x2k4p        Running                  0      |
| worker-5…ab12        CrashLoopBackOff        12      |
+------------------------------------------------------+
 enter open  l logs  / filter  ? help
```

**Below your declared minimum** (I'd pick about 50×12): don't draw the frame. Show `terminal too small: need 50x12`, and keep `q` and Ctrl+C working.

## Changes, most harmful first

**1. The layout only works at 160×50.**
- At 80×24, each of the four panels gets about 38×9 usable cells. That's nine pods at once, pod names cut at 38 characters, and a details panel that ends after roughly IP and node.
- In a 60-column split, a 2×2 grid doesn't work at all.
- You'll only ever see this at your own window size, so plan the fallback sizes now and give each its own Ratatui `TestBackend` snapshot: 160×50, 80×24, 60×20, and your minimum.

**2. Don't show every field in the details panel.**
- Annotations alone can be thousands of characters. `kubectl.kubernetes.io/last-applied-configuration` is a whole JSON document and will fill the panel.
- Status, ready, restarts and age are already columns in the list, so repeating them is redundant.
- Keep the Details tab to a short summary: node, pod IP, host IP, QoS, owner, and conditions as one line each.
- Put labels, annotations and the full object behind `d` (describe) and `y` (YAML), shown full-screen and scrollable.

**3. Don't stream logs for whatever the cursor is on.**
- Pressing `j` five times would open and close five log streams against the API server.
- Either stream only when the Logs tab is visible, waiting about 300 ms after the selection settles (and cancelling the previous stream), or stream only when the user explicitly asks.
- The log pane also needs:
  - **Follow mode:** follow by default. Any upward scroll pauses it and shows `▾ 37 new`; `G` or `F` resumes.
  - **Ring buffer:** cap it at something like 10–50k lines.
  - **Container picker:** needed for multi-container pods.
  - **Previous-container logs (`p`):** for CrashLoopBackOff, the logs of the container that crashed are usually what you need, and the current container often has only a few lines.

**4. Make namespaces a picker, not a panel.**
- Open it with `n` or `:ns` and filter as you type.
- Many users aren't allowed to list namespaces cluster-wide (RBAC). The picker must handle a `Forbidden` error by letting the user type a namespace name and remembering the ones they've used.

**5. The footer can't hold 14 keys.**
- 14 hints at about 12 characters each is around 170 columns, which overflows even your 160-column window.
- Show 4–6 hints for whichever pane has focus, most frequent first and `?` last. Drop hints from the right as the width shrinks.
- `?` opens the full list, grouped by pane. Generate both the footer and the help screen from one keymap table so they can't drift apart.

**6. Color.**
- **Healthy rows:** if 40 of 42 rows are green, the green tells you nothing. Leave Running+Ready in the default color and color only the exceptions. Apply color to the STATUS cell, not the whole row.
- **Text plus color:** the status word is already your non-color signal, so color plus the word is enough. Don't add icons on top.
- **Missing states:** map all of these. Running with 0/1 ready is yellow, not green. Also cover Completed (dim), Terminating, ImagePullBackOff and ErrImagePull (red), Evicted, and Unknown. Restart counts that are going up are often the real signal, so consider highlighting a non-zero RESTARTS cell.
- **Color setup:** define named style tokens (`status.error` and so on) rather than literal colors. Crossterm already drops colors when `NO_COLOR` is set, which only works if your states stay readable without color.

**7. Borders.**
- Nesting depth is 1, which is fine, and going from four panels to two cuts the border cost in half.
- Rounded corners have no heavy version, so the focused pane needs another cue. Either switch it to a heavy border (`┏━┓`) or bold its title, and use the accent color as a second cue.
- Box-drawing characters can render double-width in some East Asian locale settings, so keep an ASCII border set behind `--ascii`.

**8. Interaction basics to decide now:**
- **Selection on refresh:** track the selected pod by UID, not row number. When that pod disappears, move to its nearest neighbor rather than jumping to the top.
- **Keys:**
  - `/` filters the list.
  - Tab or `1`–`3` switch panes or tabs.
  - Esc backs out one level and never quits.
  - `q` quits at the top level.
  - Ctrl+C always quits.
  - Bind Ctrl+Z yourself: Ratatui doesn't handle suspend, so call the restore, SIGTSTP, then re-init sequence.
- **Destructive actions:** confirm delete and kill, with No as the default.
- **Later:** if you add more resource types, `:` command mode (`:svc`, `:deploy`) handles that better than more panels.

**9. Design these states as well as the normal one:**
- **Connecting:** draw the frame right away with a delayed spinner.
- **No pods:** say `No pods in "payments"`, followed by `n change namespace`.
- **RBAC forbidden.**
- **Container not started yet:** show this in the log pane.
- **Cluster unreachable:** keep the last rows, dimmed, mark them `STALE 2m`, and offer `r` to retry. The header's right side (`live` / `STALE` / `reconnecting`) is a good place for this.

## Rust-specific notes
- **Async data:** run kube-rs watchers and log streams in tokio tasks. Send results to the main loop over an `mpsc` channel, and redraw only when something changed. Don't redraw on a fixed timer.
- **Startup:** start with `ratatui::run` and install `color-eyre` before it. If you turn on mouse capture, turn it off yourself on exit and on panic, because `restore()` doesn't.
- **Testing:** unit-test the state logic first (selection by UID, filtering, follow and pause), then the size snapshots.
