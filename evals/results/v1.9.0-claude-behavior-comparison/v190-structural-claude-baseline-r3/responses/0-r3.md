# Don't ship this: the `defer` breaks the terminal instead of protecting it

## What's wrong

`RestoreTerminal` doesn't do what its name suggests. It's the counterpart to `ReleaseTerminal()`, which you use to hand the terminal to something else temporarily, like `$EDITOR`. `RestoreTerminal` puts the terminal back into **Bubble Tea's** state: raw mode, alt screen if you use it, mouse/focus reporting, the input reader, and a repaint of the last view. It does not return the terminal to how the shell left it.

So the `defer` runs after `Run()` has already cleaned up, and then sets up the TUI terminal state again. With no program left to undo it, the user can end up with a shell in raw mode, no echo, maybe stuck on the alt screen, until they run `reset`. That's the exact problem you were trying to prevent.

## It also doesn't help with panics

- **Panics in `Update`/`View` (the event loop):** `Run()` already recovers these by default. It restores the terminal, prints the stack trace and returns an error. Your `defer` adds nothing here, except breaking the terminal again afterwards.
- **Panics in your own goroutines:** a deferred call in the goroutine that called `Run` never sees these. A panic in another goroutine kills the process without running `main`'s defers, so this `defer` can't help in that case either.

## What to use instead

```go
p := tea.NewProgram(model)
_, err := p.Run()
return err
```

That's all you need. `Run` restores the terminal when it exits normally, on error, when killed, and after a recovered panic.

## Checks before shipping

1. **Don't pass `tea.WithoutCatchPanics()`.** It turns off the built-in recovery.
2. **Add recovery to goroutines you start yourself** (anything outside `tea.Cmd`s), and shut the program down cleanly from there:
   ```go
   go func() {
       defer func() {
           if r := recover(); r != nil {
               p.Kill() // or p.Send(errMsg{...}) and quit from Update
               // log r / debug.Stack() somewhere
           }
       }()
       work()
   }()
   ```
   Whether panics inside `tea.Cmd` functions are also recovered depends on your Bubble Tea version, since newer releases added it. Check your version's `tea.go`, or keep long-running Cmd bodies trivial.
3. **Only use `RestoreTerminal()` after `ReleaseTerminal()`**, while the program is still running. For shelling out to an editor or similar, `tea.ExecProcess` handles both calls for you.
4. **Don't write to stdout yourself during or after a crash.** If you need logs, use `tea.LogToFile` so stray output doesn't mess up the screen.
