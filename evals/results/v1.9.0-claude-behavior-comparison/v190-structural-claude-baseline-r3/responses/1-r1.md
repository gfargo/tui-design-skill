I'm going on your description here, since I haven't seen the code. In order of impact:

## 1. Add responsive behavior (this is what blocks release)
Wide monitors don't mean wide terminals. People will run this in tmux splits, on laptops, in IDE terminals, and over SSH. At 140 columns your three panes get about 45 columns each, and that's already tight for YAML. At 100 columns the layout will break.

Suggested breakpoints:
- **≥140 cols:** all three panes. Give them unequal widths: namespaces fixed at about 20, resources flexible, YAML about 40%.
- **100–139:** drop the namespace pane. Show the current namespace in the header and switch it with a picker (`n` or `:ns`).
- **<100:** one pane at a time. Enter drills into a resource's YAML and Esc goes back.
- **Below a minimum (say 60×15):** show a "terminal too small" message instead of a broken layout.

Also handle resize events live, plan for height as well as width, and truncate long names with `…` so the status column never gets pushed off screen.

## 2. Remove the outer double-line frame
It costs 2 rows and 4 columns and adds nothing. Combined with the pane borders, you have boxes inside a box. Use single-line pane borders and show focus by highlighting the active pane's border or title. Right now I can't tell how a user knows which pane has focus, and that matters more than any frame.

## 3. Make status a column that stays quiet when things are healthy
A green `[READY]` and a ✓ on every row says the same thing twice, on the row type that needs attention least. In a list where 95% of rows are healthy, the user's eye should go to the problems.
- Use a plain STATUS column with kubectl-style values (`Running`, `1/1`, `Pending`, `CrashLoopBackOff`).
- Keep healthy rows in the default color. Reserve yellow and red for abnormal states, and make them bold.
- Never rely on color alone. The text should carry the meaning, and the app should respect `NO_COLOR` and light themes.
- Drop the ✓. Glyph width varies across fonts and terminals and can misalign columns.

## 4. Drop the bullets
They cost 2 columns per row and don't tell the user anything. Use that space for a selection marker (`▶` or reverse video) on the current row only.

## 5. Cut the shortcut bar from 18 to about 6
Nobody reads two rows of 18 shortcuts. Show one row with the 5–7 actions that apply to the focused pane, change it when focus changes, and put the full list behind `?`. That also gives you back a row.

## 6. Add a header showing cluster context
This is a safety issue, not polish. Show the current **kube context and namespace** prominently at the top. Consider giving production-looking contexts a distinct color, and include the context in any confirmation prompt for a destructive action.
