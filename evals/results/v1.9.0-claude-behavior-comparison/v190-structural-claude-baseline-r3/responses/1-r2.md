I'd fix five things before release, in order of priority.

## 1. Add responsive behavior

Wide monitors don't mean wide terminals. People run tools like this in tmux splits, IDE terminal panels, laptop screens over SSH, and with larger fonts. If 140 columns is the only layout you test, the narrower cases will wrap or overlap and look broken. You don't need much:

- **≥120 cols:** three panes, as now.
- **80–119 cols:** drop the namespace pane. Show the current namespace in the header and switch it with a key (e.g. `n` opens a picker). Resources and YAML stay side by side.
- **<80 cols:** one pane at a time. `Enter` opens the YAML and `Esc` goes back.
- **Below a minimum** (around 60×15): show "Terminal too small (need 60×15)" instead of a broken render.
- Re-layout on resize (SIGWINCH), and handle height too. Short terminals should shrink the footer before they shrink the list.

## 2. Remove the outer double frame

The frame wraps three panes that already have borders. That's two layers of box-drawing, which costs 2 columns and 2 rows and adds clutter. The terminal edge already works as a frame. I'd keep single-line pane borders and use them to show focus: bright or accent color on the active pane, dim on the others.

## 3. Show status only when it matters

When every row says `• … [READY] ✓`, the status tells the user nothing, and that's about 12 columns per row spent on it. In a cluster browser, the point is to make the broken things stand out.

- **Drop the bullet.** Show the cursor with a highlighted selection row.
- **Use a STATUS column with kubectl's own words:** `Running`, `Pending`, `CrashLoopBackOff`, `0/3`. Users already know them, and they say more than READY.
- **Make healthy rows quiet.** Use default or dim color. Save color and weight for warnings and errors so they're easy to spot.
- **Don't rely on color alone.** The text has to make sense without it, for colorblind users and for `NO_COLOR`. A glyph like ✓ can be dropped or kept as a small extra, not as the only signal.

## 4. Cut the footer to one context-aware row

Nobody reads 18 shortcuts, and they take a row you need on short terminals. Show the 5–7 that apply to the focused pane, plus `? help`. For example:

```
↑↓ move  ⏎ view  / filter  l logs  d describe  n namespace  ? help
```

Put the full list in a `?` overlay, grouped by area (navigation, actions, views).

## 5. Smaller fixes

- **Truncate long names with an ellipsis.** Pod names are long. Consider middle-truncation (`api-server-…-x7k2p`) so the distinguishing suffix stays visible.
- **Let the user resize or hide the YAML pane.** A zoom toggle (e.g. `z`) for full-screen YAML helps most at narrow widths.
- **Plan for limited terminals.** Some lack box-drawing characters or Unicode symbols, so have an ASCII fallback. Check that the colors work on light themes too.
- **Show context in the header:** cluster/context name, namespace, resource type, and item count. This matters most once the namespace pane collapses.
