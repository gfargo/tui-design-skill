## Summary

The layout spends too much space on decoration and repeats the same information in several places. The biggest pre-release risk is having no responsive behavior.

## 1. Remove the double-line outer frame

The terminal window already acts as a frame. The outer border costs 2 columns and 2 rows. It also puts a double line right next to each pane's own border, which looks like nested boxes. Let the panes reach the screen edges.

To go further, drop most pane borders too. Use one vertical separator between panes and show focus with a highlighted title or border on the active pane only. Three fully boxed panes cost about 6 columns and 2 rows, and they make it hard to see which pane is active.

## 2. Remove the bullet from every row

A marker that appears on every row tells the user nothing. Use that column only for the cursor or selection (`▸` or reverse video) and leave it blank on other rows. You get 2 columns back, and the eye finds the selection immediately.

## 3. Rethink `[READY]` + ✓

This is the most important content change:

- **It says the same thing three times.** Green, the word READY, and the checkmark all mean the same thing. Keep one text signal and use color as reinforcement.
- **Everything looks equally important.** In a healthy cluster, 95% of rows shout green, so the one `CrashLoopBackOff` doesn't stand out. Keep the healthy state quiet (dim or plain text) and give color to the problem states.
- **It's too simple for Kubernetes.** "Ready" means different things for different resources. Pods have `Running` / `Pending` / `CrashLoopBackOff` / `Completed`, Deployments have `2/3`, and Jobs have completions. Use kubectl-style columns, because users already read those fluently: `NAME  READY  STATUS  RESTARTS  AGE`.
- **Glyph width.** `✓` has an ambiguous width in some fonts and terminals, which can misalign columns. Test it, or offer an ASCII fallback. Also respect `NO_COLOR`.

## 4. Cut the 18 shortcuts to about 6, and make them depend on context

Two rows of 18 shortcuts is reference material, not a hint bar. Show the 5–7 that matter in the focused pane (e.g. `enter` open, `/` filter, `l` logs, `d` describe, `tab` switch pane, `?` help), and move the full list to a `?` overlay. That saves a row and makes the shortcuts easier to read.

## 5. Add responsive behavior; don't ship without it

"Most of us use wide monitors" isn't the same as "most terminals are wide." A wide monitor still gives you narrow terminals in tmux splits, IDE terminals, laptops during on-call, and SSH sessions on a jump host. A Kubernetes browser gets opened during incidents, often in a cramped terminal. Suggested breakpoints:

| Width | Layout |
|---|---|
| ≥ 140 | Three panes, as you have now |
| 100–139 | Namespaces become a picker (`:ns` or a key) or a collapsed rail; resources + YAML side by side |
| < 100 | One pane at a time; YAML opens as a full-screen drill-in, `esc` goes back |
| < ~60×15 | "Terminal too small" message instead of broken rendering |

Handle height as well (drop the hint bar on short terminals) and redraw on SIGWINCH.

## 6. Plan for long names

Pod names like `payments-api-7d9f8c6b5-x2kqp` can run to 60+ characters. Truncate in the middle (`payments-api-7d…-x2kqp`), because the hash suffix is what tells replicas apart. Give the name column the space you freed by removing the frame, bullets, and status decoration.

## 7. Add one thing: cluster and context in a header line

Something like `ctx: prod-us-east │ ns: payments │ pods (42)`. The current cluster is the most important safety information in a Kubernetes tool, and a production context should look visibly different (e.g. a red label). It fits in one row, which is less than the outer frame was using.

## Space budget at 140 columns

| | Now (approx.) | Proposed |
|---|---|---|
| Columns used by chrome | ~8 (frame + borders) + ~11 per row (bullet + status) | ~2–4 |
| Rows used by chrome | ~6 (frame, borders, 2 hint rows) | ~3 (header, column titles, 1 hint row) |

On a 40-row terminal, that's about 3 more visible resources and roughly 15 more characters for names.

**Priority order:** responsive breakpoints → status column redesign → context header → shortcut reduction → removing the frame and bullets. The last two are quick and free up the space the others need.
