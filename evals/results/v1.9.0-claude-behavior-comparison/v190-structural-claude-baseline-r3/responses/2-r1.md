**Short answer:** use Bubble Tea, but not full-screen. Run it inline (no alt screen), draw the UI on the terminal directly (`/dev/tty`), and write only the branch name to stdout. The alt screen would erase the picker when it exits, which is the opposite of what you want in scrollback. And because `$(...)` captures stdout, any UI drawn there would end up as the argument to `git checkout`.

## Output contract

| Stream | Content |
|---|---|
| **stdout** | Exactly one line: the branch name plus `\n`, and only on success. Nothing else, ever. |
| **tty / stderr** | All UI: prompt, list, a final one-line summary, and error messages. |
| **exit code** | `0` = branch selected · `1` = cancelled with Esc or no match · `130` = Ctrl-C · `2` = error (not a git repo, no tty, git failed) |

On cancel, stdout stays empty and the exit code is non-zero. Bare `git checkout $(branchpick)` then turns into `git checkout` with no argument. That's harmless but sloppy, so document this form:

```sh
b=$(branchpick) && git checkout "$b"
# or a shell function:
gco() { local b; b=$(branchpick) || return; git switch "$b"; }
```

## Terminal mode

- **Inline rendering:** don't pass `tea.WithAltScreen()`. Your shell prompt and the `git checkout $(branchpick)` line stay where they are, and the picker draws below them.
- **Open `/dev/tty` for both input and output:** `tea.WithInput(tty)` and `tea.WithOutput(tty)`. Stdout is a pipe, and stdin may be one too. Use stderr as the fallback output if `/dev/tty` can't be opened. If there's no tty at all (CI, for example), exit 2 with a clear message instead of hanging.
- **Fix color detection:** lipgloss detects color support from stdout by default, which is a pipe here, so you'd get no colors. Create the renderer from the tty (`lipgloss.NewRenderer(tty)`, or the v2 equivalent) and respect `NO_COLOR`.
- **Keep the list short:** cap it at about 10 rows, or fewer on small terminals, so inline redraws don't scroll the screen.
- **Control the last frame:** Bubble Tea leaves the final `View()` in scrollback. On quit, make `View()` return a single summary line such as `✓ feature/login-redirect` (or `✗ cancelled`) so the full list doesn't stay behind. Scrollback then reads: command, then chosen branch.

## Key implementation choices

1. **Loading branches:**
   `git for-each-ref refs/heads --sort=-committerdate --count=50 --format='%(refname:short)%00%(committerdate:relative)'`
   Use a NUL separator, not whitespace. Mark the current branch (or put it last), since switching to it does nothing. Add an optional `--remote` flag for `refs/remotes` that strips the `origin/` prefix in the output.
2. **Ranking:** use fuzzy matching (`sahilm/fuzzy` or your own subsequence scorer) and break ties by recency. With an empty query, show plain recency order. Write this as a pure function: `Rank(branches, query) []Match`.
3. **Structure:** keep four pieces separate:
   - `git.go`: runs git behind a small interface so tests can fake it
   - `rank.go`: the pure ranking function
   - `model.go`: the Bubble Tea `Update`/`View`
   - `main.go`: tty wiring, printing to stdout, exit codes
   
   Print the selection to stdout in `main` only after `p.Run()` returns, never from inside the model.
4. **Keys:** typing filters the list. ↑/↓ and Ctrl-P/Ctrl-N move the cursor, Enter selects, Esc cancels. Ctrl-C arrives as a key message in raw mode, so record it and exit 130. Truncate long names to the terminal width and handle `WindowSizeMsg`.
5. **Non-interactive flags:** `--list` prints the ranked branches. `--query foo --first` prints the best match without a UI. Both are useful for scripts and make testing easier.

## Testing

- **Ranking:** table-driven tests covering exact vs. fuzzy matches, recency tie-breaks, an empty query, and no matches.
- **Parsing:** feed canned `for-each-ref` output to the parser, including odd but valid names like `feat/a.b-c` and names with unicode.
- **Model:** call `Update` directly with sequences of `tea.KeyMsg` and check the cursor, the filtered list, the final selection and the cancel/Ctrl-C state. No terminal is needed.
- **Rendering:** use `teatest` with a fixed terminal size for golden-file snapshots. Include a snapshot of the final summary frame, since that's what ends up in scrollback.
- **End-to-end (the most important one):** build the binary and create a temp repo with `git init`. Make several branches with fixed `GIT_COMMITTER_DATE` values so the order is deterministic. Run the binary under a pseudo-terminal (`creack/pty`) with stdout captured separately, then type a query and Enter. Check that:
  - stdout is exactly `branchname\n`
  - no ANSI escape codes leaked into stdout
  - the exit code is 0
  
  Repeat with Esc (empty stdout, exit 1), with Ctrl-C (exit 130), and with no tty and outside a repo (exit 2, message on stderr).

Overall: an inline Bubble Tea UI on `/dev/tty`, a clean stdout carrying just the name, exit codes that tell scripts what happened, and a short last frame so scrollback shows the command and the chosen branch.
