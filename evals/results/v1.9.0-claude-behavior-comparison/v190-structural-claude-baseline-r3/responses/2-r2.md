**No, don't make it full-screen.** Use Bubble Tea in its default **inline mode** (no `tea.WithAltScreen()`). The alternate screen gets thrown away when the program exits, so the picker would leave nothing in scrollback. Inline mode draws a small picker under the prompt. When it exits, it replaces the picker with a one-line summary. Scrollback then shows:

```
$ git checkout $(branchpick)
✓ feature/login-redesign
Switched to branch 'feature/login-redesign'
```

## Output contract

This is the key design point. `$(…)` captures stdout, so stdout is only for the result.

| Stream | Content |
|---|---|
| **stdout** | The chosen branch name and `\n`, and nothing else. No colour codes, no prompts, no log lines. |
| **TTY (`/dev/tty`)** | All the UI: the picker, the final `✓ branch` summary line and any error messages for the user. |
| **stderr** | Errors when there's no TTY or the repo is missing. |

The summary line has to go to the TTY. The branch you print to stdout gets swallowed by `$(…)`, so it never appears on screen by itself.

**Exit codes:**
- `0`: a branch was chosen.
- `1`: the user cancelled with Esc. stdout is empty.
- `130`: the user pressed Ctrl-C. stdout is empty.
- `2`: an error, such as not being in a git repo, having no branches, or having no TTY.

**Cancelling is a problem with the exact command you gave.** If the user cancels, `git checkout $(branchpick)` runs `git checkout` with no arguments. That's harmless but untidy. Document this pattern instead:
```sh
b=$(branchpick) && git checkout "$b"
```
Or ship a shell function or git alias (`git pick`) that does the same thing.

## Terminal mode

- Open `/dev/tty` and pass it as both input and output: `tea.WithInput(tty)` and `tea.WithOutput(tty)`. This is how fzf does it. It still works when stdout is a pipe and stderr is redirected (`2>/dev/null`). Fall back to stderr only if `/dev/tty` can't be opened. If neither works, exit with code 2 and a clear message.
- **Base colour detection on the TTY, not stdout.** Stdout is a pipe, so lipgloss will detect "no colour" if it looks there. In lipgloss v1, use `lipgloss.NewRenderer(tty)`. In v2, pass the TTY as the output so detection follows it.
- Bubble Tea puts the terminal in raw mode, so Ctrl-C arrives as a key message, not a signal. Handle it yourself: quit and exit with code 130.
- Keep the picker small: a prompt plus about 10 rows, capped to fit `WindowSizeMsg.Height`. Leaving the screen alone and keeping it short is the point of inline mode.
- To finish: set `m.done` or `m.cancelled`, return `tea.Quit`, and have `View()` return just the summary line (or `""` on cancel). Bubble Tea draws that final view and leaves it in place. Only after `p.Run()` returns, write the branch to stdout from `main`. Never write to stdout from inside the model.

## Implementation choices

- **Where "recent" comes from:**
  - Default: `git for-each-ref --sort=-committerdate --format=%(refname:short) refs/heads/`.
  - Optional: read the reflog (`checkout: moving from X to Y`) to rank by when you last *visited* a branch. This often matches what "recent" means to the user better. Remove duplicates, drop branches that have since been deleted, and leave out the current branch.
- Run git through `exec.Command("git", …)` with no shell, and limit the list to around 50 branches.
- **Fuzzy matching:** `sahilm/fuzzy` or a small subsequence scorer. With an empty query, show branches in recency order. When two matches score the same, break the tie by recency, so the ranking doesn't jump around as the user types. Highlight the matched characters.
- **Keys:**
  - Type to filter.
  - ↑/↓ and Ctrl-P/Ctrl-N to move.
  - Enter to select.
  - Esc or Ctrl-C to cancel.
  - Enter with no matches does nothing.
- **Optional flags:**
  - `--filter <q>`: no UI. Print the best match, or exit 1 if nothing matches. Useful for scripts and tests.
  - `-n <limit>`.

## Test choices

1. **Ranking as pure functions.** Keep `rank(query, branches) []Match` free of any Bubble Tea code and test it with tables: recency order when the query is empty, tie-breaking, unicode, and no-match cases.
2. **Model `Update` tests.** Send `tea.KeyMsg`s directly and check the cursor, the filtered list, `done`/`cancelled`, and that Enter or Esc returns `tea.Quit`. No terminal is needed.
3. **Golden files for the view.** Use `x/exp/teatest` with a fixed terminal size and `lipgloss.SetColorProfile(termenv.Ascii)` so the output is the same on every machine. The most important golden file is the **final** view: it must be exactly the summary line, with no leftover picker rows.
4. **The git source against a real temp repo.** `git init` in `t.TempDir()`, and make commits with fixed `GIT_COMMITTER_DATE` values so the order is predictable. Isolate the user's git config with `GIT_CONFIG_GLOBAL=/dev/null`.
5. **End-to-end check of the output contract.** This is the test that matters most. Build the binary and run it under a pty (`creack/pty`) as the controlling terminal, with stdout attached to a *pipe*. Type a query and Enter, then assert:
   - stdout is exactly `"feature/x\n"`;
   - the pty output contains the UI and the `✓` line;
   - the exit code is 0.
   Run the same setup with Esc and assert empty stdout and exit code 1.
6. **No-TTY check.** Run with no controlling terminal and assert exit code 2, a message on stderr, and empty stdout.
