# branchpick: design

**Short answer:** use Bubble Tea, but don't make it full-screen. Run it **inline** with no alternate screen. Draw the UI on the terminal (`/dev/tty`) and write only the branch name to stdout. The alternate screen would hide the prompt line while the picker is open and wipe out anything the tool draws. Inline mode leaves the `git checkout $(branchpick)` line in place and lets you leave a one-line result under it.

## Output contract

| Stream | Content |
|---|---|
| **stdout** | Only the selected branch name plus `\n`. Nothing else, ever: no colour, no logs. `$(...)` captures this. |
| **stderr** | Error messages (not a repo, no branches, no TTY). |
| **/dev/tty** | The interactive UI and the final summary line. |

Exit codes:
- `0`: a branch was selected and printed.
- `1`: error (not a git repo, git failed, no TTY available). stdout stays empty.
- `130`: cancelled with Esc or Ctrl-C. stdout stays empty.

Watch out for this: if the user cancels, `git checkout $(branchpick)` becomes plain `git checkout`, which is harmless but confusing. Document the safer form and maybe ship it as a shell function:

```sh
b=$(branchpick) && git checkout "$b"
# or
gco() { local b; b=$(branchpick "$@") || return; git switch "$b"; }
```

What ends up in scrollback:
```
$ git checkout $(branchpick)
  ✓ feature/login-refactor
Switched to branch 'feature/login-refactor'
```

## Terminal mode

- **No alt screen.** In v1, don't pass `tea.WithAltScreen()`. In v2, leave the view's alt-screen setting off. Inline is the default in both versions.
- **Do I/O through `/dev/tty`, not stdin/stdout.** Command substitution turns stdout into a pipe. Open `/dev/tty` and pass it as both input and output (`tea.WithInput(tty)`, `tea.WithOutput(tty)`). If it won't open (CI, no terminal), exit 1 with a clear message on stderr. You can also add a non-interactive `--filter <query>` that prints the best match.
- **Detect colour from the tty, not stdout.** Lipgloss/termenv check stdout by default, find a pipe, and strip all styling. Build the renderer or colour profile from the tty handle.
- **Keep the height fixed and small**, e.g. 1 input line plus up to 10 result rows. Inline redraws then cover a small area that doesn't move, and the picker never scrolls your history. Use `WindowSizeMsg` only to cut long branch names to the terminal width.
- **Collapse the UI when you quit.** On Enter, set `m.chosen` and return `tea.Quit`. `View()` should then return only `"  ✓ <branch>\n"`. Bubble Tea leaves the last frame on screen, so the list shrinks to that one line. On cancel, return `""` (or `"  ✗ cancelled"`) so nothing extra is left behind.
- After `p.Run()` returns, write the branch to `os.Stdout`. Do it after the terminal has been restored, never from inside the program.
- Raw mode means Ctrl-C arrives as a key message, not as SIGINT. Handle it yourself and map it to exit 130.
- Turn off mouse support. It isn't needed and it interferes with scrollback.

## Key implementation choices

**Getting the branch list.** Call git with `exec.Command` and explicit arguments, never through a shell.
- Baseline: `git for-each-ref --sort=-committerdate --format='%(refname:short)%00%(committerdate:relative)' refs/heads/`
- For "recent" in the sense of *branches I recently switched to*, parse `git reflog` for `checkout: moving from X to Y`. Put those branches first, in order, then the remaining branches sorted by commit date. Remove duplicates, leave out the current branch, and cap the list (`--limit 50`).
- Split fields on NUL so unusual branch names can't break parsing.

**Fuzzy matching**
- With an empty query, show the recency order unchanged.
- With a query, rank by fuzzy score (`sahilm/fuzzy` is fine) and break ties by recency. Highlight the matched characters.
- Write a small custom model (a `textinput` plus a hand-drawn list) instead of `bubbles/list`. The list component's built-in filter mode, pagination and status bar are more than you need, and they make the inline height harder to control.

**Keys**
- Typing filters the list.
- ↑/↓ and Ctrl-P/Ctrl-N move the selection.
- Enter selects. Pressing Enter with zero matches does nothing.
- Esc or Ctrl-C cancels.
- Clamp the cursor whenever the filtered list changes.

**Structure.** Keep three pure pieces you can test separately:
1. `parseBranches(forEachRefOut, reflogOut) []Branch`
2. `rank(query, []Branch) []Match`
3. The tea model.

`main` only wires the tty, runs git, runs the program, and maps the result to stdout and an exit code.

## Test choices

1. **Unit tests, no terminal:**
   - `parseBranches` with recorded git output, including reflog entries for deleted branches, detached HEAD, and duplicates.
   - `rank`: tie-breaking order, and that an empty query keeps recency order.
2. **Model tests.** Call `Update` directly with key messages and assert on `m.chosen`, `m.cancelled` and the cursor. Check that the final `View()` after selection is exactly the one summary line. Use `teatest` with a fixed terminal size and the ASCII colour profile for golden snapshots of the list view.
3. **Contract or integration tests (the important ones):**
   - Build the binary and create a real repo in `t.TempDir()`. Make commits with fixed `GIT_COMMITTER_DATE` so the order is deterministic.
   - Run the binary under a pty (`creack/pty`) for the tty side, with **stdout connected to a separate pipe**.
   - Type `log\r` and assert:
     - stdout is exactly `feature/login-refactor\n`
     - the exit code is 0
     - the pty output ends with the `✓` line
   - Esc: exit 130, stdout empty.
   - Outside a repo: exit 1, message on stderr, stdout empty.
   - No tty (run without a pty): exit 1, stdout empty.

These integration tests protect the promise that stdout carries only the branch name. That promise is what makes `$(branchpick)` safe, and it's the part most likely to break without anyone noticing. A stray debug print or a colour code on stdout would break the tool.
