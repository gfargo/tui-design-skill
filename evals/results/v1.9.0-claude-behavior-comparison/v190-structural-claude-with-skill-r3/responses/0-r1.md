No, the defer is wrong, and you can delete it. Don't ship it as written. `p.Run()` already restores the terminal on every exit path, and the extra call can make things worse.

## Why it's wrong

1. **`RestoreTerminal()` does the opposite of what you want.** It pairs with `ReleaseTerminal()` and is meant for a temporary handoff, such as giving the terminal to a child process. It turns Bubble Tea's terminal modes back on. It does not return the terminal to the user's shell. Running it after `Run()` has already cleaned up can put raw mode, the alternate screen, or hidden-cursor state back after the program has exited. That's the broken terminal you were trying to prevent.

2. **The panic case is already handled.** `Program.Run()` restores the terminal after a normal quit, after an error, and after a panic it recovers. It catches panics by default unless you turned that off with `tea.WithoutCatchPanics()`. Your defer adds no protection.

3. **One gap remains, and the defer doesn't close it.** A panic in a goroutine you start yourself, outside a `tea.Cmd`, can crash the process before any deferred call in this function runs. Send async work through `tea.Cmd`, or recover inside your own goroutines and report the failure to the program as a message.

## What to use instead

Let `Run()` own cleanup and handle what it returns:

```go
func run() error {
    p := tea.NewProgram(model{})
    _, err := p.Run()
    if errors.Is(err, tea.ErrInterrupted) {
        // the user pressed Ctrl+C and the model returned tea.Interrupt
        return err // or map it to exit code 130
    }
    return err // the terminal is already restored here, panic paths included
}
```

Related rules from the same lifecycle contract:

- **Quitting:** return `tea.Quit` (or `tea.Interrupt` when the caller needs to tell Ctrl+C apart) from `Update`. Never call `os.Exit` from `Update`, because it skips cleanup.
- **Opening an editor or shell:** use `tea.ExecProcess(exec.Command(...), callback)`. Don't call `ReleaseTerminal`/`RestoreTerminal` by hand. In the callback, reload any data the child process may have changed, because a repaint alone redraws the old model.
- **Signals:** Bubble Tea already handles SIGINT/SIGTERM, so don't add your own `signal.Notify`.
- **Your own cleanup boundary:** add one only if you turn off the built-in recovery with `WithoutCatchPanics`. Then you are responsible for restoring the terminal, and it still shouldn't be done with `RestoreTerminal`.

## Verify before shipping

Run a small PTY smoke test, or do it by hand: quit normally, press Ctrl+C, return an error from `Init`, and `panic()` inside `Update`. After each, check that the shell echoes what you type, the cursor is visible, the alternate screen is gone, and mouse reporting is off. That covers the paths your defer was meant to protect.
