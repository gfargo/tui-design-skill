Don't ship this. Remove the defer, because it makes the panic case worse, not safer.

## The problem

`RestoreTerminal()` doesn't put your shell's terminal back to normal. It's the partner of `ReleaseTerminal()`: you call `ReleaseTerminal()` to hand the terminal away for a while, and `RestoreTerminal()` takes it back by turning Bubble Tea's terminal modes on again (raw mode, the screen and input modes, a fresh redraw).

So your defer runs after `Run()` has already cleaned up, and it switches Bubble Tea's modes back on just as you return to the shell. On a normal exit, an error, or a panic, the user can end up with exactly the broken terminal you were trying to prevent.

## What already covers panics

`Program.Run()` handles cleanup itself. It restores the terminal when the program quits normally, when it returns an error, and when it recovers a panic in your `Init`, `Update`, `View` or a `tea.Cmd`. A recovered panic comes back as a non-nil error from `Run()`. You don't need a guard of your own.

## Use this instead

```go
p := tea.NewProgram(model)
if _, err := p.Run(); err != nil {
    if errors.Is(err, tea.ErrInterrupted) {
        return err // caller maps this to exit status 130
    }
    return fmt.Errorf("run TUI: %w", err)
}
return nil
```

## Real gaps to check

1. **Goroutines you start yourself.** Bubble Tea only recovers panics in code it runs. A bare `go func() { ... }()` that panics kills the process without any cleanup. Run that work as a `tea.Cmd`, or add a `recover()` inside the goroutine and report the failure with `p.Send(errMsg{...})`.
2. **`os.Exit` anywhere while the program is running.** It skips cleanup completely. Return `tea.Quit` (exits with status 0) or `tea.Interrupt` (makes `Run()` return `tea.ErrInterrupted`) from `Update`. Only call `os.Exit` after `Run()` has returned.
3. **`tea.WithoutCatchPanics()`.** If you use it, you've turned off the built-in recovery and need your own cleanup. Without it, leave everything to Bubble Tea.
4. **Opening an editor or shell from the app.** That's the one case where release and restore matter. Use `tea.ExecProcess(exec.Command(...), callback)`, which pauses the program, releases the terminal, waits for the child, takes the terminal back and redraws. Reload any data the child might have changed in the callback. Call `ReleaseTerminal`/`RestoreTerminal` directly only when `ExecProcess` can't do the job, and always as a pair around the handoff.

## How to check it before shipping

Add a temporary key that panics inside `Update`, run the binary in a real terminal, and press it. Then check that your typing shows up, line editing works, the cursor is visible and the main screen is back. Repeat with Ctrl+C and with `kill -TERM <pid>` from a second shell. Run the same test with a panic in a goroutine you started yourself, which is how you'll catch gap 1.
