# Review: Kubernetes resource browser

**My recommendation:** you can keep the three-pane idea at wide sizes. Before release, cut the decoration that repeats the same information, replace the 18-shortcut footer with a short footer that changes with focus, and add a responsive plan. Of these, the missing responsive plan is the change that matters most, even though you didn't ask about it.

## 1. Responsive behavior is the blocker (highest user harm)

"Most of us use wide monitors" describes your own setup, not what users will have. A kube browser often runs in a tmux split next to `kubectl`, over SSH from a jump host, or in a laptop terminal during an incident. Here's what your current layout does at 80×24:

- **Columns:** the outer frame takes 2 columns and the pane borders take 6, leaving about 72 for content. Three equal panes get about 24 columns each. Pod names like `api-gateway-7d9f8b6c4-x2kqp` (27 characters) get cut off, and YAML in 24 columns is unreadable.
- **Rows:** the outer frame takes 2 rows, the pane borders 2 more, and the footer 2. That's 6 of 24 rows (25%) gone before any data shows.
- **At 60 columns** each pane is about 17 columns wide and nothing works.

Use a width ladder where each pane disappears at a set width instead of shrinking forever:

| Width | Layout |
|---|---|
| **120+** | namespaces · resources · YAML (what you have now) |
| **80–119** | The namespace becomes a header label you change with a picker (`n` or `:ns`). Resources take the full width. YAML opens on `Enter` as its own view or a right pane of at least 40 columns. |
| **60–79** | One pane at a time. `Enter` goes from resources to YAML, `Esc` comes back. Hide less important columns (AGE, then RESTARTS). |
| **< 50×12** (or whatever you test) | Show `terminal too small: need 50x12` and keep `q` and `Ctrl+C` working. |

Build the layout from the size the terminal reports on resize, using ratios and min/max widths rather than fixed column counts. Then add golden-frame tests at 140×40, 80×24 and 60×20.

## 2. Clutter audit

| Finding | Count | Change |
|---|---|---|
| Border nesting depth | **2** (double outer frame, then pane borders) | Delete the outer frame. The terminal edge already frames the app. Double lines also read as DOS-era style; use single or rounded borders, and a heavier border on the focused pane only. |
| Signals for "ready" | **4** (bullet, `[READY]`, green, ✓) | The budget is at most one color cue plus one non-color cue. Use a `READY 1/1` column, which is also more useful because it shows counts. |
| Markers on every row | the bullet is on **100%** of rows | Delete it. A marker on every row marks nothing. Show the selected row with reverse video only. |
| Signals on the normal case | every healthy row is loud | "Ready" is the normal state, so leave it plain. Spend color and a symbol only on the exceptions: `! CrashLoopBackOff` in yellow or red, `0/1` in red. With 50 healthy pods, 50 green checkmarks drown out the one broken one. |
| Chrome per row | about 12 cells (`• ` + ` [READY] ✓`) | That's about 12 columns per row given back to the name. At 80 columns that space decides whether the pod hash shows or gets cut off. |

Also check which checkmark you use. `✓` (U+2713) is narrow, but `✅` takes two cells, and `✔️` takes one or two depending on the terminal, which misaligns columns.

## 3. Footer: 18 shortcuts across 2 rows

- **What's wrong:** nobody reads 18 hints. They take a whole row away from data at 24 rows, and they can't fit at 80 or 60 columns.
- **Change:** show one row of the 3–5 most-used actions for the focused pane, with `?` last. Build the hints from your keymap so they never drift out of date. When the line doesn't fit, drop hints from the right and keep `?`.
- **Put the full list in a `?` help screen,** grouped by pane.
- **Add a k9s-style `:` command line,** since you're close to 20 actions. `:pods`, `:deploy`, `:ns payments` scales better than a separate key for each resource type.

## 4. Other things to check before release

- **Live data under the cursor:** watches reorder and remove rows. Keep the selection on the same resource (by UID), not the same row number, so `d` never deletes the wrong pod.
- **Kubernetes-specific states:**
  - **Loading:** keep the old rows visible while refreshing.
  - **Empty:** `No pods in payments. n to change namespace`.
  - **RBAC forbidden:** treat it as a partial result, not a crash.
  - **Watch disconnected or stale:** show "⟳ 2m ago" and a reconnect message in the header.
- **`NO_COLOR` and monochrome:** after the cuts above, failures still show as `!` plus a status word and `0/1`, so meaning doesn't depend on color. Verify it with a test.
- **Terminal cleanup:** make sure every exit restores the terminal, including errors, panics, and `Ctrl+C` during a slow API call. And make sure no kube API call blocks the render or input thread.

## Priority order

1. Responsive ladder plus the too-small screen.
2. Remove the outer frame, the bullets, and the duplicate ready signals.
3. Short focus-aware footer plus `?` help and a `:` command line.
4. Stable selection under live updates.
5. Design the error and stale states, and add golden tests at 140, 80 and 60 columns.
