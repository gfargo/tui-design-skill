**No, don't make it a full-screen app.** Use Bubble Tea, but run it **inline**, keep the alternate screen off, and draw the UI on the terminal (`/dev/tty`). Stdout gets only the branch name. The alternate screen has no scrollback and gives back the old screen on exit, so the picker and the chosen branch would leave no trace. That's the opposite of what you asked for. A branch picker is a summon–choose–exit tool, the same shape as fzf with `--height`.

## Output contract

| Stream | Contents |
|---|---|
| **stdout** | Only the selected branch name and one `\n`. No ANSI codes, nothing else. Write it **after** `p.Run()` returns, once the terminal is restored. |
| **UI** (`/dev/tty`, fallback stderr) | The prompt, the list, and the receipt line that stays on exit. |
| **stderr** | Errors, such as `branchpick: not a git repository`. |

Exit codes:

| Code | Meaning |
|---|---|
| 0 | Branch selected |
| 1 | Nothing to pick (no other branches, or Enter with no matches) |
| 2 | Usage error, not a git repo, or no terminal available |
| 130 | Cancelled with Esc or Ctrl+C |

130 is what matters for scripts. `cmd && next` stops when it sees it, and exit 0 would let them carry on.

**Shell usage caveat:** with `git checkout $(branchpick)`, a cancel still runs a bare `git checkout`. That's harmless but noisy. Put this in the README:

```sh
b=$(branchpick) && git switch "$b"
# or a function: gco() { local b; b=$(branchpick "$@") || return; git switch "$b"; }
```

## Terminal mode

- **Inline with a height cap.** The UI shows at most about 10 result rows plus a prompt line, below the shell prompt, and never more than the terminal height minus one row. In Bubble Tea v2 inline is the default, so just leave `v.AltScreen` unset.
- **Render to `/dev/tty`, not stdout.** Open the tty and pass `tea.WithOutput(tty)`, falling back to `os.Stderr`. Inside `$(...)` stdout is a pipe, so anything painted there becomes part of the branch name. Using the tty instead of stderr also means `2>/dev/null` won't blank the UI. For input, Bubble Tea v2 opens `/dev/tty` itself when stdin isn't a TTY.
- **Leave a one-line receipt on exit.** When the user presses Enter, set `m.chosen` and return `tea.Quit`. The final `View()` then renders only the receipt, so the list collapses to one line:

```
~/src/api $ git switch "$(branchpick)"
✓ feature/rate-limit
Switched to branch 'feature/rate-limit'
```

  On cancel, render `✗ cancelled` or nothing at all. Never leave a half-drawn list behind.
- **No terminal at all** (cron, CI): fail fast with exit 2 and a message that points to `--list`, which prints branch names one per line for scripts.

## Layout

At 80 columns:
```
> rate█                                                      3/41
▌ feature/rate-limit                                     2 hours ago
  fix/ratelimit-headers                                  3 days ago
  chore/rate-docs                                        2 weeks ago
```
At 60 columns, the relative dates drop first and the names get truncated with `…`:
```
> rate█                                    3/41
▌ feature/rate-limit
  fix/ratelimit-headers
  chore/very-long-branch-name-about-ra…
```

- **Clutter:** no borders, no help footer (the keys are standard picker keys), and one marker for the selected row.
- **Highlighting:** matched characters are bold or underlined, not just colored, so they still show under `NO_COLOR`. Dates are dim.
- **Truncation** is measured with `lipgloss.Width`, which counts terminal cells, not bytes. Stdout always gets the full name.
- **Very short terminals:** with fewer than 3 rows, show the prompt plus one row.
- **Empty states:** "no matches" when the filter hides everything; exit 1 with a message when there are no other branches.

## Most important implementation choices

1. **Load branches before `p.Run()`.** Use `git for-each-ref --sort=-committerdate --format='%(refname:short)%09%(committerdate:relative)' refs/heads`. This takes milliseconds, and errors like "not a repo" go to stderr with exit 2 before any UI appears. Hide the current branch, since switching to it is pointless. If "recent" should mean recently *checked out* rather than recently committed, parse `git reflog` entries like `checkout: moving from X to Y` instead.
2. **Startup time is the feature.** It's a single static binary with no network calls and no background-color query blocking the first frame. Render a default palette first.
3. **Fuzzy matching:** use `sahilm/fuzzy` with smart case (case-insensitive until the query has an uppercase letter). Rank exact matches first, then prefix, then substring, then fuzzy, and break ties by recency. With an empty query, the list is just the recency order. Filter in `Update` on every keypress; a few hundred refs is far under 100 ms.
4. **Keys:** typing filters. Navigate with ↑/↓, Ctrl+P/N or Ctrl+K/J. Enter selects, Esc or Ctrl+C cancels. Bare `j`/`k`/`q` must not be bound, because they're query text. On cancel, return `tea.Interrupt`, map `tea.ErrInterrupted` to exit 130 in `main`, and never call `os.Exit` inside `Update`. Use the real terminal cursor in the input (`SetVirtualCursor(false)`, `v.Cursor`) so IMEs and screen readers can follow it.
5. **Useful flags:** `-q/--query` to pre-fill the filter, `-1/--select-1` to auto-pick when there is exactly one match (no UI), and `--list` for plain output.
6. **Structure:** put `run(args, stdout, stderr io.Writer, tty io.ReadWriter) int` behind `main`. Then the stream contract can be tested without a real terminal.

## Tests (most tests at the bottom, fewest at the top)

1. **Unit tests**, most of the suite:
   - Parsing the `for-each-ref` output.
   - Ranking and smart case.
   - `Update` transitions using `tea.KeyPressMsg` literals: typing narrows the list, the cursor stays in bounds when the list shrinks, Enter sets `chosen` and returns `tea.QuitMsg`, Enter with no matches does nothing, Esc cancels.
2. **Golden tests of `View()`:**
   - Sizes 80×24, 60×24 and a 3-row terminal.
   - Color profile pinned with `tea.WithColorProfile(colorprofile.ASCII)`.
   - CJK and emoji branch names to check truncation.
   - One `teatest/v2` run checking the final output is only the receipt line. Always pass `WithFinalTimeout`.
3. **Contract tests on `run()`** with buffers:
   - stdout is exactly `name\n` with no escape codes.
   - Cancel gives exit 130 and empty stdout.
   - Not a repo gives exit 2 and stderr text.
   - Use a temporary git fixture with fixed `GIT_COMMITTER_DATE`s so the recency order is deterministic.
4. **One PTY smoke test** (`creack/pty`): run `sh -c 'b=$(branchpick); echo "[$b]"'`, type a query and Enter, then check that the PTY shows the receipt and the captured value is clean. This is the only test that proves the `/dev/tty` versus stdout split works for real.
