**No, don't make it full-screen.** This is a summon, choose, exit tool. Run it as an inline Bubble Tea v2 program with a height cap, like `fzf --height`. Draw the UI on `/dev/tty`, print only the branch name to stdout, and leave a one-line receipt behind. The alternate screen would hide the `git checkout $(branchpick)` line while you pick, and the picker would leave nothing in scrollback when it closes.

## Output contract

| Channel | Contents |
|---|---|
| **stdout** | Only the chosen branch name and a newline. No ANSI codes and nothing else. `$(...)` removes the trailing newline. |
| **UI (`/dev/tty`, or stderr if that fails)** | The picker while it runs, then a one-line receipt such as `✓ feature/login-redirect` (`> ` when Unicode isn't safe). |
| **stderr** | Errors such as `branchpick: not a git repository`. |

| Exit code | Meaning |
|---|---|
| 0 | A branch was chosen |
| 1 | No other branches, or git failed |
| 2 | Bad flags, or no terminal available for the picker |
| 130 | Cancelled with Esc or Ctrl+C. Nothing goes to stdout. |

The cancel case matters for the usage you described. If the user cancels, `git checkout $(branchpick)` still runs, as a bare `git checkout`. That does no harm, but it's sloppy. Document a wrapper that stops on cancel:

```sh
gco() { local b; b=$(branchpick "$@") || return; git switch "$b"; }
```

`git switch` avoids the case where a branch and a file share a name, which makes `git checkout name` ambiguous.

Without a terminal (CI, no `/dev/tty`), don't show a prompt. Exit 2 with a message that names the non-interactive options:
- `--list` prints the ranked branches as plain text.
- `--filter QUERY` prints the best match.
- `--select-1` picks automatically when only one candidate matches.

## Terminal mode and layout

- Inline, never `v.AltScreen`. Show at most `min(10, rows/2)` candidates, below the prompt that invoked it.
- Pass `tea.WithOutput(tty)`. Inside `$(...)`, stdout is captured, so anything drawn there would end up in the result. Opening `/dev/tty` instead of using stderr keeps the UI visible even after `2>/dev/null`. Bubble Tea v2 already reads keys from the terminal.
- No mouse, so the terminal's own selection and scrollback keep working.

Layout at 80 columns:
```
$ git checkout $(branchpick)
> log▏                                          3/42  ↵ select · esc cancel
▸ feature/login-redirect                2 hours ago
  fix/logout-race                       3 days ago
  chore/log-rotation                    2 weeks ago
```
At 60 columns the hints go first, then the dates shorten (`2h`, `3d`). Branch names are cut in the middle by display width, e.g. `feature/…-redirect`:
```
> log▏                                  3/42
▸ feature/login-redirect             2h
  fix/logout-race                    3d
```
What stays in scrollback afterwards:
```
$ git checkout $(branchpick)
✓ feature/login-redirect
Switched to branch 'feature/login-redirect'
```
**Clutter audit:**
- No borders.
- The selected row has two signals, `▸` and reverse video, so it still reads under `NO_COLOR`.
- Matched characters are bold or underlined, not only colored.
- The current branch is the only row with a marker (`*`).
- Dates are dim.

**Small terminals:** below about 3 rows or 20 columns, show only the prompt and the selected row.

## Most important implementation choices

1. **Get branches before starting the program.** Use:
   ```
   git for-each-ref --sort=-committerdate --format='%(HEAD)%09%(refname:short)%09%(committerdate:unix)' refs/heads/
   ```
   It's one fast subprocess. Failures like "not a repo" or "no branches" then go to stderr with an exit code before any UI appears. If the repo has thousands of branches, move this into a `tea.Cmd`, because `Update` must never block. "Recently checked out" via the reflog could be an optional `--by-checkout` flag.
2. **Start on the right row.** Show the current branch, marked `*`, but put the cursor on the most recent other branch, as `git checkout -` would.
3. **Matching.** Use `sahilm/fuzzy` with smart case, re-filtering on every key press. Rank exact matches, then prefix, then substring, then fuzzy, and break ties by recency. Show the match count, and keep the cursor in range when the list shrinks.
4. **Keys.**
   - Printable keys go to the query. That includes `q` and `j`/`k`, so there's no `q` to quit.
   - `↑`/`↓`, `Ctrl+P`/`Ctrl+N` and `Ctrl+K`/`Ctrl+J` move the cursor.
   - `Enter` selects and `Ctrl+U` clears the query.
   - `Esc` and `Ctrl+C` return `tea.Interrupt`, which `main` maps to exit 130.
5. **Write stdout only after `Run` returns:**
   ```go
   final, err := p.Run()
   if errors.Is(err, tea.ErrInterrupted) { os.Exit(130) }
   if err != nil { fmt.Fprintln(os.Stderr, "branchpick:", err); os.Exit(1) }
   fmt.Println(final.(model).chosen)
   ```
   Once a branch is chosen, `View()` returns only the receipt line, so the last frame shrinks to that line. Don't use `fmt.Print` inside `Update` or `View`. Don't add your own signal handling either, since `Run()` already cleans up the terminal.
6. **Startup time is part of the experience.** Aim for under 50 ms from launch to first frame. Don't use a color query that waits for a reply; draw with default styles first. Use `lipgloss.Width` for all width measurement.

## Most important test choices

1. **Unit tests (most of the suite):**
   - Parse `for-each-ref` fixtures.
   - Ranking and smart case.
   - Moving and clamping the cursor.
   - `Update` with v2 key literals: `Enter` sets `chosen` and returns a quit command; `Esc` returns an interrupt; typing `q` adds to the query; `tea.WindowSizeMsg` changes the height cap.
2. **Golden frames** of `View()` at 80×24, 60×24 and the minimum size. Pin `colorprofile.ASCII` so the files don't change between machines. Include a CJK or emoji branch name to check that truncation measures display width.
3. **Black-box tests of the built binary** against a fresh `git init` repo in `t.TempDir()`:
   - stdout is exactly `name\n` with no ESC bytes.
   - The exit code is right for each case: chosen, cancelled, no branches, not a repo.
   - With no terminal it exits 2 with the message.
   - `--list` and `--filter` work, including under `NO_COLOR`.
4. **One PTY smoke test** (e.g. `creack/pty`), only if you want proof that the UI draws on the terminal while captured stdout stays clean. Use teatest v2 for the middle layer, not a stack of PTY tests.
