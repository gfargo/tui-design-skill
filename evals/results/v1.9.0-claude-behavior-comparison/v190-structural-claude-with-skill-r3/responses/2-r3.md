**No, don't make it full-screen.** This is a summon, choose, exit tool. Use Bubble Tea v2 in its default **inline mode**, drawn on **stderr**, with a height cap. Print only the branch name to **stdout**, after the program has exited. The alternate screen has no scrollback, so it would wipe out exactly what you want to keep: the command you typed and the branch you picked.

## Output contract

| Stream / code | Contents |
|---|---|
| **stdout** | The chosen branch name plus `\n`, and nothing else. No ANSI, no prompts. Write it with `fmt.Println` only after `p.Run()` returns. |
| **stderr** | All the interactive UI: `tea.WithOutput(os.Stderr)`. When it closes, the UI is replaced by a one-line receipt: `✓ feature/login-flow`. |
| **exit 0** | A branch was selected. |
| **exit 130** | The user cancelled (Esc or Ctrl+C). stdout stays empty. |
| **exit 1** | Not a git repo, git failed, or there are no other branches. One line on stderr. |
| **exit 2** | Bad usage, or interactive mode was needed but no terminal is available. The message names `--list`. |

This works because `$(...)` captures only stdout. The UI and the receipt go to stderr, so they land in the terminal and stay in scrollback. Afterwards you see:

```
$ git checkout $(branchpick)
✓ feature/login-flow
Switched to branch 'feature/login-flow'
```

**One shell gotcha to document:** after a cancel, `$(branchpick)` expands to nothing, so `git checkout` runs with no arguments. Ship a tiny wrapper so a cancel stops cleanly:

```sh
gco() { local b; b=$(branchpick "$@") && git checkout "$b"; }
```

**Plain modes for scripts and accessibility:**
- `branchpick --list` prints the ranked recent branches, one per line, with no TUI. It composes with `fzf` or `grep`.
- `--query <q>` pre-fills the search box.
- `-n <N>` limits how many branches are shown.

## Terminal mode and layout

- Leave `v.AltScreen` unset (inline is the default in v2). Bubble Tea v2 reads keys from `/dev/tty` itself, so the picker still works inside `$(...)`.
- If stderr isn't a terminal (for example `2>log`), open `/dev/tty` for output instead. If that fails, exit 2.
- Cap the frame at about 10 result rows plus the prompt and footer. If the terminal is shorter than that, shrink to fit, down to a minimum of 3 rows.

80 columns:
```
> feat▏                                              3/14
▸ feature/login-flow                          2 hours ago
  feature/billing-v2                           yesterday
  fix/feature-flag-timeout                    3 days ago
↑↓ move · enter checkout · esc cancel
```
60 columns (the date column stays down to about 44 columns, then disappears):
```
> feat▏                                3/14
▸ feature/login-flow            2 hours ago
  feature/billing-v2              yesterday
  fix/feature-flag-time…         3 days ago
↑↓ move · enter checkout · esc cancel
```

**Clutter audit:**
- No borders at all.
- The selected row has one marker, `▸`, which also shows up in reverse video. It doesn't depend on color, so it survives `NO_COLOR`.
- Matched characters are bold, plus an accent color.
- Dates are dim and right-aligned.
- Most of the cells are branch names.
- The match count replaces any title.

Long names are cut off with `…`, measured in terminal cells with `lipgloss.Width`, not `len`. The full name always appears in the receipt.

## Key implementation choices

1. **Define "recent" by your own checkout history, not just commit dates.** Parse `git reflog` for `checkout: moving from X to Y`, remove duplicates, drop branches that have been deleted, and leave out the current branch. Then fill in from `git for-each-ref --sort=-committerdate refs/heads --format=...`. Load all of this **before** `p.Run()`. That way, errors like "not a git repo" print as plain text and the picker never flashes a loading state. It also doesn't block the event loop, because the loop hasn't started yet.
2. **Build a custom model, not `bubbles/list`.** The list component brings its own title, paginator, status bar and help. Use `textinput` plus a slice of branches plus `sahilm/fuzzy`. Rank exact matches first, then prefix, then fuzzy, and break ties by recency. Use smart-case matching (case-sensitive only if the query has a capital letter).
3. **Keys:** the search box owns every printable key, so `q` and `j`/`k` are just text.
   - Move: `↑`/`↓`, `Ctrl+N`/`Ctrl+P`, `Ctrl+J`/`Ctrl+K`
   - Select: `Enter` (does nothing when there are zero matches)
   - Cancel: `Esc` or `Ctrl+C`
   - Suspend: `Ctrl+Z` returns `tea.Suspend`
   
   When the filter narrows the matches, keep the cursor within the list.
4. **Show the real cursor:** call `input.SetVirtualCursor(false)` and set `v.Cursor = m.input.Cursor()` (Y offset 0). This helps IME input and screen readers.
5. **Exit:** on Enter, set `m.chosen`. The final `View()` then returns only the receipt line, which stays on screen inline. On cancel, return an empty view so nothing is left behind. After `Run()`, inspect the final model: print the branch and exit 0, or exit 130. Never call `os.Exit` inside `Update`.
6. **Styles:** use a few named style tokens (match, selected, dim). Bubble Tea's color-profile writer adjusts colors for stderr and respects `NO_COLOR`. stdout never goes through lipgloss at all.

## Tests (most tests at the bottom layer)

1. **Pure unit tests (most of the suite):**
   - Reflog parsing, using fixture text. Cover duplicates, deleted branches, the current branch, and detached HEAD.
   - The ranking order.
   - `Update` transitions, using `tea.KeyPressMsg` values: typing filters, the cursor stays in range, Enter with no matches does nothing, Esc gives a cancelled state plus `tea.Quit`.
   - Hide git behind an injected `runGit` function so these tests never shell out.
2. **Golden frames** with `teatest/v2` and `tea.WithColorProfile(colorprofile.ASCII)`:
   - Sizes 80×24, 60×24 and 40×8.
   - The no-matches state.
   - Branch names with CJK characters or emoji.
   - The receipt frame and the empty frame after cancel.
3. **One integration test** that builds the binary and runs it against a temporary git repo created in `t.TempDir()`. Connect stdin and stderr to a PTY (`creack/pty`) and stdout to a pipe:
   - Type `feat` and press Enter. Assert stdout is exactly `feature/x\n`, exit is 0, and stdout contains no escape codes.
   - Press Esc. Assert stdout is empty and exit is 130.
   - With no TTY at all, assert exit 2 with a message on stderr.
   - `--list` produces plain lines.

The design follows fzf in `--height` mode: UI on the terminal, answer on stdout. gum uses the same arrangement with `tea.WithOutput(os.Stderr)`, which is why `x=$(gum choose …)` works.
