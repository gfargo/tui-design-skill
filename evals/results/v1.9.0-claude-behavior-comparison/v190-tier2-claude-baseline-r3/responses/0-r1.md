## Bubble Tea apps are easy to test

Testing a TUI sounds hard because you picture faking a terminal. With Bubble Tea you mostly don't need to. Your whole app is three functions:

- `Init()`
- `Update(msg) (Model, Cmd)`: takes the current state and a message (like a key press) and returns the new state
- `View() string`: turns the state into text

So "user presses Tab" is just a value you pass to `Update`, and you can then check the model it returns. No terminal, no timing.

I'd build the tests in three layers, cheapest and most valuable first.

## Layer 1: Unit-test `Update` with key messages (start here)

This is the layer that would have caught your Tab bug. It's fast and stable, and it checks behavior instead of how the screen looks.

```go
// model_test.go
package main

import (
	"testing"

	tea "github.com/charmbracelet/bubbletea"
)

// press feeds a sequence of keys through Update and returns the resulting model.
func press(t *testing.T, m tea.Model, keys ...tea.KeyMsg) model {
	t.Helper()
	for _, k := range keys {
		m, _ = m.Update(k)
	}
	return m.(model)
}

var (
	tab      = tea.KeyMsg{Type: tea.KeyTab}
	shiftTab = tea.KeyMsg{Type: tea.KeyShiftTab}
)

func TestTabCyclesColumns(t *testing.T) {
	m := newModel(testBoard()) // 3 columns: Todo, Doing, Done

	tests := []struct {
		name string
		keys []tea.KeyMsg
		want int
	}{
		{"starts on first column", nil, 0},
		{"tab moves right", []tea.KeyMsg{tab}, 1},
		{"tab wraps around", []tea.KeyMsg{tab, tab, tab}, 0},
		{"shift-tab wraps left", []tea.KeyMsg{shiftTab}, 2},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			got := press(t, m, tt.keys...)
			if got.focused != tt.want {
				t.Errorf("focused = %d, want %d", got.focused, tt.want)
			}
		})
	}
}
```

For each key binding your team depends on, write a test like this: Tab, moving cards, creating and deleting, quitting. A table of "key sequence → expected state" covers most of a kanban app quickly.

**Version note:** that code is for Bubble Tea v1. In v2 the key type is `tea.KeyPressMsg{Code: tea.KeyTab}`. Check which one your `go.mod` uses.

**If `Update` reads or writes files directly**, move that work behind an interface or into a `tea.Cmd` so tests can use an in-memory board. This is usually the only refactor you need to make an app testable.

## Layer 2: Snapshot-test `View()` with golden files

These catch rendering regressions, like a broken layout or a missing focus highlight. Charm's `teatest` package runs your real program against a fake terminal:

```go
import (
	"testing"
	"time"

	"github.com/charmbracelet/lipgloss"
	"github.com/charmbracelet/x/exp/teatest"
	"github.com/muesli/termenv"
)

func init() {
	// Without this, colors depend on the terminal and CI output won't match.
	lipgloss.SetColorProfile(termenv.Ascii)
}

func TestBoardRender(t *testing.T) {
	tm := teatest.NewTestModel(t, newModel(testBoard()),
		teatest.WithInitialTermSize(100, 30))

	tm.Send(tab)
	tm.Send(tea.KeyMsg{Type: tea.KeyRunes, Runes: []rune("q")})

	tm.WaitFinished(t, teatest.WithFinalTimeout(2*time.Second))
	final := tm.FinalModel(t).(model)
	if final.focused != 1 {
		t.Errorf("focused = %d, want 1", final.focused)
	}

	// Writes or compares testdata/TestBoardRender.golden
	out := readAll(t, tm.FinalOutput(t))
	teatest.RequireEqualOutput(t, out)
}
```

When you change the UI on purpose, run `go test ./... -update` to regenerate the golden files, then review the diff in your PR. That review step is where you'd spot "the Done column vanished."

Things that make snapshots flaky (ban or fake them in tests):
- Terminal size: always set it.
- Color profile: force ASCII as shown above.
- `time.Now()`: inject a clock.
- Spinners and animations.
- Map iteration order when rendering lists.

Keep snapshots few, maybe 3–6 key screens. Too many and every small visual tweak becomes a chore to update.

## Layer 3: End-to-end flows (optional)

`teatest` can also drive whole sessions: type a card title, press Enter, then `teatest.WaitFor` until the card shows up in the output. Save this for the two or three workflows people use most. Layer 1 already covers most of the same ground more cheaply.

## CI

```yaml
# .github/workflows/test.yml
name: test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version-file: go.mod }
      - run: go test -race ./...
```

Add a `.gitattributes` with `*.golden -text` so line-ending changes don't break the snapshots.
