The good news: Bubble Tea is easier to test than most TUIs. Your whole app is basically a function, `Update(msg) → (model, cmd)`. You can call it in a test with a fake keypress and check the new state. You don't need a terminal at all.

## Layer 1: Test `Update` directly (start here)

This layer would have caught your Tab bug. It's plain `go test`, needs no extra libraries, and runs in milliseconds.

```go
package main

import (
	"testing"

	tea "github.com/charmbracelet/bubbletea"
)

// helper: send a key, get the concrete model back
func press(t *testing.T, m model, key tea.KeyMsg) model {
	t.Helper()
	next, _ := m.Update(key)
	return next.(model) // Update returns tea.Model; assert back to your type
}

func TestTabCyclesColumns(t *testing.T) {
	m := newModel() // however you construct your initial state
	tab := tea.KeyMsg{Type: tea.KeyTab}

	want := []int{1, 2, 0} // assuming 3 columns, wraps around
	for i, w := range want {
		m = press(t, m, tab)
		if m.focusedCol != w {
			t.Fatalf("after %d tabs: focusedCol = %d, want %d", i+1, m.focusedCol, w)
		}
	}
}

func TestShiftTabCyclesBackwards(t *testing.T) {
	m := newModel()
	m = press(t, m, tea.KeyMsg{Type: tea.KeyShiftTab})
	if m.focusedCol != 2 {
		t.Fatalf("focusedCol = %d, want 2", m.focusedCol)
	}
}

// Regular characters look like this:
// tea.KeyMsg{Type: tea.KeyRunes, Runes: []rune{'j'}}
```

Write one test like this for every keybinding your team depends on: move card, add card, delete, column navigation, quit. A table-driven test makes that quick. That list doubles as a spec of what the app is supposed to do.

**Version note:** this is Bubble Tea v1 syntax. In v2 (`charm.land/bubbletea/v2`), key events are `tea.KeyPressMsg` with a different shape. Check your `go.mod`.

## Layer 2: Snapshot (golden) tests for `View()`

These catch "the layout broke" regressions:

```go
func TestViewSnapshot(t *testing.T) {
	lipgloss.SetColorProfile(termenv.Ascii) // strip colors so output is stable across machines/CI
	m := newModelWithFixtureData()
	m, _ = updateTyped(m, tea.WindowSizeMsg{Width: 100, Height: 30})
	golden.RequireEqual(t, []byte(m.View())) // github.com/charmbracelet/x/exp/golden
}
```

Run `go test -update` once to write `testdata/*.golden`, then commit those files. When a refactor changes the rendering, the test fails with a diff. If the change was intentional, regenerate.

Always send a fixed `WindowSizeMsg` and use deterministic fixture data (no `time.Now()`). Otherwise the snapshots will flake.

## Layer 3: End-to-end with `teatest` (a few tests, not many)

`github.com/charmbracelet/x/exp/teatest` runs the full program, including commands, in a virtual terminal:

```go
func TestEndToEnd_AddCard(t *testing.T) {
	tm := teatest.NewTestModel(t, newModel(), teatest.WithInitialTermSize(100, 30))
	tm.Type("a")                       // open add-card prompt
	tm.Type("Fix login bug")
	tm.Send(tea.KeyMsg{Type: tea.KeyEnter})
	tm.Send(tea.KeyMsg{Type: tea.KeyRunes, Runes: []rune{'q'}})

	final := tm.FinalModel(t, teatest.WithFinalTimeout(2*time.Second)).(model)
	if got := final.columns[0].cards[len(final.columns[0].cards)-1].title; got != "Fix login bug" {
		t.Fatalf("last card = %q", got)
	}
}
```

Use this for a handful of critical flows, especially anything that goes through `tea.Cmd`s like saving to disk or async loading. Layer 1 can't see those because it ignores the returned cmd.

## CI (GitHub Actions)

```yaml
# .github/workflows/test.yml
name: test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version-file: go.mod }
      - run: go test -race ./...
```

Then turn on branch protection so PRs can't merge while this check is red. That's the step that actually stops a silent break from sitting there for two days.
