## The approach

Textual has a headless test harness. `App.run_test()` is an async context manager that runs your app without a real terminal. It gives you a `Pilot` object that can click, type and press keys. You then check the app's state with `query_one(...)`.

To check that a message was posted, mount your form inside a small test app that has a handler for that message, and record what it receives.

### Assumed app shape (`entry_form.py`)

```python
from textual.app import ComposeResult
from textual.containers import Vertical
from textual.message import Message
from textual.widgets import Button, Input, Label, Select


class EntryForm(Vertical):
    class Submitted(Message):
        def __init__(self, name: str, role: str) -> None:
            super().__init__()
            self.name = name
            self.role = role

    def compose(self) -> ComposeResult:
        yield Input(placeholder="Name", id="name")
        yield Select([("Admin", "admin"), ("User", "user")], id="role", allow_blank=False)
        yield Label("", id="error")
        yield Button("Submit", id="submit")

    def on_button_pressed(self, event: Button.Pressed) -> None:
        name = self.query_one("#name", Input).value.strip()
        error = self.query_one("#error", Label)
        if not name:
            error.update("Name is required")
            return
        error.update("")
        self.post_message(self.Submitted(name, self.query_one("#role", Select).value))
```

### Tests (`test_entry_form.py`)

```python
from textual.app import App, ComposeResult
from textual.widgets import Input, Label, Select

from entry_form import EntryForm


class FormHarness(App):
    """Minimal host app that records messages posted by the form."""

    def __init__(self) -> None:
        super().__init__()
        self.submitted: list[EntryForm.Submitted] = []

    def compose(self) -> ComposeResult:
        yield EntryForm()

    def on_entry_form_submitted(self, message: EntryForm.Submitted) -> None:
        self.submitted.append(message)


async def test_empty_name_shows_error():
    app = FormHarness()
    async with app.run_test() as pilot:
        await pilot.click("#submit")
        await pilot.pause()  # let the handlers run

        error = app.query_one("#error", Label)
        assert "Name is required" in str(error.render())
        assert app.submitted == []


async def test_submit_posts_message():
    app = FormHarness()
    async with app.run_test(size=(80, 30)) as pilot:
        await pilot.click("#name")
        await pilot.press(*"Ada")              # types A, d, a
        app.query_one("#role", Select).value = "user"
        await pilot.click("#submit")
        await pilot.pause()

        assert len(app.submitted) == 1
        msg = app.submitted[0]
        assert (msg.name, msg.role) == ("Ada", "user")
```

## Tips

- **Message handler names** follow the pattern `on_<widget_snake_case>_<message_snake_case>`, so `EntryForm.Submitted` becomes `on_entry_form_submitted`. If your form is a `Screen`, the message won't bubble up to the app. In that case, push the screen in the harness's `on_mount`, then either handle the message on the screen or set the values directly and assert on them.
- **Wait with `await pilot.pause()`** after any interaction before you assert. Otherwise the event handlers may not have run yet.
- **Use `size=(w, h)` in `run_test`** if a widget doesn't fit the default 80×24. Clicking something that's off-screen raises `OutOfBounds`.
- **Typing:** `pilot.press(*"text")` works for letters, but keys like space need their key names (`"space"`, `"enter"`, `"tab"`). It's often simpler to set `input.value = "Ada Lovelace"` directly, unless the typing itself is what you're testing.
- **Select:** setting `.value` directly is the most reliable option. Driving the dropdown with clicks and arrow keys works, but those tests break more easily.
- **Using Textual's built-in validators** (`Input(validators=[Length(minimum=1)])`)? Then assert `app.query_one("#name").has_class("-invalid")`, or check `input.validate(input.value).is_valid`. Note that validation only runs on the events listed in `validate_on`, so an untouched empty field won't be marked invalid until one of them fires.
- **Snapshot tests:** for visual regressions, add `pytest-textual-snapshot` and use its `snap_compare` fixture.
