There's no project in this directory, so this answer is general. Both symptoms have a small set of known causes, and you can check each one directly.

## 1. Garbled output: stop logging to the terminal Ink draws on

Ink redraws its output by moving the cursor up and erasing the lines it wrote last frame. Ink patches `console.*` by default so that logs print above the UI. Anything that skips that patch moves the cursor in ways Ink doesn't track, and the next redraw garbles the screen. Common culprits:

- `process.stdout.write` / `process.stderr.write` called directly. The `debug` package, some loggers and child processes with inherited stdio all do this.
- Logs written before `render()` or after unmount.
- `render(..., { patchConsole: false })`.
- UI taller than the terminal. Ink can't erase lines that have scrolled off, so it clears the whole screen every frame, which causes flicker and duplicated output.

**Fix: log to a file and watch it in another pane.**

```ts
// debug.ts
import fs from 'node:fs';
export const dlog = (...args: unknown[]) =>
  fs.appendFileSync('/tmp/ink-debug.log',
    `${new Date().toISOString()} ${args.map(a =>
      typeof a === 'string' ? a : JSON.stringify(a)).join(' ')}\n`);
```

```sh
tail -f /tmp/ink-debug.log          # pane 1
node dist/cli.js 2>/tmp/ink-err.log # pane 2: also keeps stray stderr off the UI
```

## 2. State that never appears: find where the update stops

The update has to get through five steps: reducer → new state → component re-render → Ink frame → terminal. Log at each step to find the one where it stops.

```ts
function reducer(state: State, action: Action): State {
  const next = realReducer(state, action);
  dlog('action', action.type, 'changed?', next !== state);   // step 1-2
  return next;
}

function Panel() {
  const [state] = useReducer(reducer, init);
  dlog('render Panel', state.items.length);                   // step 3
  ...
}
```

Then work out what failed:

| What you see in the logs | Likely cause |
|---|---|
| Reducer runs, `changed? false` | You **mutated** state and returned the same reference, so React skips the re-render. Return new objects and arrays. |
| `changed? true`, but no `render` log | The component reads a different state: a duplicate provider, a context value from a stale `useMemo`, a `React.memo` child getting mutated props, or a value copied into a `useRef`/module variable. |
| Render log shows the new value, screen doesn't | Ink-specific causes, listed below. |

Ink-specific causes when the render happens but the screen doesn't change:

- **`<Static>`**: it renders each item **once** and never updates it. Anything that changes must live outside `<Static>`.
- **Clipping**: a parent `<Box height={…}>` (or the terminal height) cuts the content off.
- **Exiting too early**: calling `process.exit()` right after a dispatch kills the process before the frame flushes. Use `useApp().exit()` and `await waitUntilExit()` instead.
- **Two Ink instances**: `render()` was called twice, so you're looking at the wrong one.

## Tools that help

- **`render(<App />, { debug: true })`**: Ink prints every frame in full instead of overwriting it, so you can scroll back and see exactly what each render produced.
- **React DevTools**: `npm i -D react-devtools-core`, run `npx react-devtools`, then `DEV=true node dist/cli.js`. You get the component tree and live state/props for your terminal app.
- **`ink-testing-library`**: reproduces the problem in a test, with no terminal involved:
  ```ts
  const { stdin, lastFrame, frames } = render(<App />);
  stdin.write('j');
  await new Promise(r => setTimeout(r, 0));
  expect(lastFrame()).toContain('item 2');
  ```
  If `lastFrame()` is correct but your real terminal isn't, the bug is in output handling (part 1). If `lastFrame()` is wrong, it's in your state or rendering (part 2).

**Short version:** send all debug output to a file and check whether `next !== state`. In practice, the "reducer runs but nothing shows" bug is usually mutation or `<Static>`. If you share the reducer and the component that should update, I can point at the specific line.
