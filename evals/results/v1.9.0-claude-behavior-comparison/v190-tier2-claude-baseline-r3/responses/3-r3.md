Both problems come from how Ink draws the screen, so it's worth knowing that first.

## How Ink renders

Ink doesn't print output and move on. On every render it moves the cursor up by the number of lines it drew last time, erases them, and writes the new frame. It keeps track of how many lines it owns. Anything else that writes to the terminal throws that count off, so the next erase lands in the wrong place. That causes the garbling in problem 1. It also means "the screen didn't change" can have several causes, which is problem 2.

---

## Problem 1: console.log garbling the UI

`render()` defaults to `patchConsole: true`, which catches `console.*` calls and prints them above the UI. That covers plain `console.log`, but these still get through:

- `process.stdout.write` / `process.stderr.write` called directly, by your code or a library (spinners, progress bars, `debug`, some loggers)
- Child processes with `stdio: 'inherit'`
- Logs printed before `render()` or after unmount
- A frame taller than the terminal. Ink then has to clear the whole screen, so it flickers and interleaves even without any stray writes.

**Recommended workflow: keep debug output off the terminal Ink is drawing to.**

```ts
// debug.ts
import { appendFileSync } from 'node:fs';
export const dlog = (...args: unknown[]) =>
  appendFileSync('/tmp/ink-debug.log',
    `[${new Date().toISOString().slice(11, 23)}] ${args.map(a =>
      typeof a === 'string' ? a : JSON.stringify(a)).join(' ')}\n`);
```

Run `tail -f /tmp/ink-debug.log` in another pane. This is synchronous, so the order is reliable, and it can't interfere with Ink's line count.

Other options:
- **`<Static>`**: if you want logs inside the UI, keep an array of log lines in state and render them with `<Static items={logs}>`. Ink prints each one once above the live area.
- **`useStdout().write()` / `useStderr().write()`**: Ink-aware writes that keep its bookkeeping correct.
- **`2> debug.log`**: write debug output to stderr and redirect it, as long as you aren't relying on Ink's patching of stderr.

## Problem 2: the reducer runs but the screen doesn't change

Work down these layers in order. Each one tells you where the update stops.

**Layer 1: Did the state actually change?**
React skips the re-render if the new state is `Object.is`-equal to the old one. This is the most common cause:
```ts
case 'add': state.items.push(action.item); return state;          // ❌ same reference, no re-render
case 'add': return { ...state, items: [...state.items, action.item] }; // ✅
```
Log `prev === next` from inside the reducer to check.

**Layer 2: Did the component re-render?**
Put `dlog('render <Foo>', relevantState)` at the top of the component that should show the change. If the reducer runs but this never logs:
- The component may be reading a different instance: a second context Provider, a different `useReducer` instance, or a stale closure.
- You may have two copies of React. Run `npm ls react ink` and check for duplicates. This happens a lot with linked packages and monorepos.
- External stores need `useSyncExternalStore`. Mutating a module-level object won't trigger a render.

**Layer 3: Did Ink write the frame?**
Render with `render(<App />, { debug: true })`. In debug mode Ink prints every frame in full, one after another, instead of erasing and redrawing, so you can scroll back through every frame it committed. Things to check:
- **Event loop blocked**: synchronous work right after `dispatch` delays the commit. Debug mode will show the frame arriving late.
- **Exiting too early**: Ink throttles rendering, so `process.exit()` right after a dispatch can drop the last frame. Use `useApp().exit()` and `await waitUntilExit()` instead.
- **CI mode**: if `CI` is set in your environment, Ink only writes the final frame when the app exits. Check with `env | grep CI`.

**Layer 4: The frame was written but you can't see the change**
- **`<Static>` never re-renders items it has already printed.** Changing an existing item does nothing; only appended items show up. Live-updating content has to go outside `<Static>`.
- It's clipped by layout: a `<Box height={n}>`, `overflow="hidden"`, `<Text wrap="truncate">`, or a frame taller than the terminal.
- It's rendered conditionally from a different piece of state than the one you updated.

**React DevTools** also work with Ink. Install `react-devtools-core`, run `npx react-devtools` in another terminal, and start your app with `DEV=true`. You can then inspect the component tree, props, and hook state live, which helps with Layer 2.

## Short version

1. Send all debug output to a file and `tail -f` it. Never write to the terminal Ink is drawing to.
2. For a missing update, check each layer in turn: new state reference? component re-rendered (render log)? frame committed (`debug: true`)? frame visible (Static/layout/clipping)?
