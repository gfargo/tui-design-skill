**Recommendation: don't take over the screen. Render inline, below the prompt, the way `fzf --height=40%` does.**

## Why not full-screen

Full-screen apps like lazygit use the terminal's **alternate screen buffer**. That's a separate canvas, and when the app exits the terminal throws it away and shows your old screen again. That works for lazygit because you stay in it for a while and it's a workspace. For a picker you open for two seconds, it causes problems:

- Nothing it showed ends up in scrollback. That conflicts with what you want.
- The screen flashes to blank and back, which is jarring for something this quick.
- The user loses sight of the command output they were just looking at, which is often why they're switching branches.

Inline rendering avoids all three. You draw into the normal buffer under the cursor, so the shell history above stays visible the whole time.

## What the terminal should look like after exit

```
~/repo $ git switch $(gb)
Switched to branch 'feature/login-fix'
~/repo $
```

Or, if your tool does the switch itself:

```
~/repo $ gb
→ feature/login-fix
Switched to branch 'feature/login-fix'
~/repo $
```

The rules that get you there:

1. **Erase the picker UI when it exits.** Leaving 12 rows of a stale list in scrollback is just clutter. The useful record is the command plus the result.
2. **Print the selection as a single plain line**, or let `git switch` print its own message. Both the command and the branch then stay in scrollback permanently.
3. **On cancel (Esc / Ctrl-C), erase the UI and print nothing.** Exit non-zero (130 for Ctrl-C, 1 for Esc is fine) so `git switch $(gb)` doesn't run with an empty argument. You can also guard it in a wrapper: `b=$(gb) && git switch "$b"`.
4. **Cap the height**, for example `min(10, rows/2)` rows. That way it doesn't push the prompt off a short terminal or scroll the history away.

## Go specifics

The main decision is to **draw the UI to the TTY or stderr and write only the result to stdout.** That's what lets `$(gb)` work, and it's how fzf does it.

With Bubble Tea:

```go
p := tea.NewProgram(model,
    tea.WithOutput(os.Stderr), // UI goes to stderr; stdout stays clean
    // no tea.WithAltScreen() → renders inline
)
m, err := p.Run()
if err != nil { os.Exit(2) }
if sel := m.(model).selected; sel != "" {
    fmt.Println(sel)          // the only thing on stdout
} else {
    os.Exit(130)
}
```

Bubble Tea leaves the last frame of `View()` on screen. To make the UI erase itself on exit, set a flag before you quit and return an empty view:

```go
case "enter":
    m.selected = m.items[m.cursor]
    m.quitting = true
    return m, tea.Quit
...
func (m model) View() string {
    if m.quitting { return "" }
    ...
}
```

Two edge cases to handle:

- **stderr redirected** (`gb 2>/dev/null`): open `/dev/tty` directly for both input and output (`tea.WithInput(tty)`, `tea.WithOutput(tty)`). Then the UI works no matter how the user's streams are wired.
- **stdout is a TTY** (the user ran `gb` bare): you can choose to do the `git switch` yourself and print `→ branch`. If stdout is piped or captured, print only the bare branch name.

If you'd rather not use Bubble Tea, the same approach by hand is: save the cursor position, draw N lines, and on exit move back up and clear those lines with `\x1b[NA` + `\x1b[J`. Bubble Tea's inline renderer just does that bookkeeping for you.
