## 1. Don't take over the whole screen

Render inline, under the prompt, like `fzf --height=40%` or `gh`'s prompts. Don't use the alternate screen the way lazygit does.

- **Alternate screen fits apps you stay in**, like lazygit, vim and htop. You live in them for a while, and when you quit, they disappear and your scrollback comes back exactly as it was. That's why it's the wrong choice for you: nothing done in the alternate screen stays in scrollback.
- **A picker is used for about two seconds.** Taking over the screen hides what the user was just looking at, and the screen flashing in and out is jarring for something that quick.
- **Keep it short.** Use about 10 rows, or a third of the terminal height on small terminals. Recent branches rarely need more, and filtering covers the rest. The output then scrolls up only a little.

In Bubble Tea, inline is the default. Just don't pass `tea.WithAltScreen()`.

## 2. After it exits

The goal is that scrollback looks as if a normal command ran:

```
$ gco
✓ feature/login-redirect
$
```

To get that:

1. **Erase the picker when it closes.** Have `View()` return `""` once you're quitting. Bubble Tea then redraws an empty frame, which clears the picker's rows and leaves the cursor where the picker began.
2. **Print one summary line after the program exits** (after `p.Run()` returns), such as `✓ feature/login-redirect` or `switched to feature/login-redirect`. Together with the prompt line already above it, the command and the chosen branch both stay in history.
3. **On cancel (Esc / Ctrl-C):** clear the picker the same way. Then either print nothing or a dim `cancelled` line, and exit non-zero (130 is the usual code for Ctrl-C). Don't leave a half-drawn list behind.

## 3. Send the UI and the result to different places

Decide this before writing any code, because it determines whether the tool works in pipelines:

- **Draw the UI on stderr or `/dev/tty`** (`tea.WithOutput(os.Stderr)`, or open `/dev/tty` for both input and output).
- **Print only the branch name on stdout.**

Then `git switch "$(pick-branch)"` and `pick-branch | xargs ...` work, and the summary line from step 2 also goes to stderr so it doesn't end up in captured output. A reasonable split:

- **Mode A, the tool switches branches itself** (e.g. a `gco` alias): print the `✓` line to stderr, print nothing to stdout.
- **Mode B, plain picker:** print the bare branch name to stdout. If stdout isn't a TTY, skip the decorated line, since the caller will show or use the result.

## Smaller points

- **Picker near the bottom of the terminal:** inline rendering prints newlines to make room, which pushes earlier output up into scrollback. That's expected. Just keep the height small.
- **Resizing:** handle `tea.WindowSizeMsg` and limit the height to the current number of rows.
- **Nothing to pick** (zero recent branches, or not in a repo): don't start the UI. Print a one-line error to stderr and exit 1.
- **One branch only:** consider selecting it directly without showing the picker, or add a `--select-1` flag like fzf's.
