## Should it take over the screen?

**No.** Render it inline, below the prompt, like `fzf --height=40%` does. Lazygit uses the alternate screen because it's a workspace you stay in for a while. Your picker is a single quick question, and that changes the tradeoffs:

- **The alternate screen keeps nothing in scrollback.** When the program exits, the terminal restores the old screen and everything drawn in the alt screen disappears. That's the opposite of what you want.
- **Inline keeps context.** While picking, the user can still see the command they typed and whatever output came before it.
- **A small UI suits a small task.** About 10 rows is enough for "recent branches," and a full-screen flash for a two-second choice feels heavy.

Cap the height at something like `min(len(branches)+2, 12, termRows/2)` so it still fits in short terminals.

## What the terminal should look like after it exits

The goal is for scrollback to read like a normal command ran:

```
$ gb
✓ feature/login-redirect
$ _
```

To get that:

1. **Erase the picker area when it exits.** Leave no half-drawn list, cursor, or highlight behind.
2. **Print one plain result line.** Show the picked branch, or the `git switch` output if you run the checkout yourself. This line is the part that should stay in scrollback.
3. **Cancel (Esc/Ctrl-C):** erase the picker, print nothing (or a dim `cancelled`), and exit non-zero. 130 is the convention for Ctrl-C, so `gb && …` chains behave.
4. **Leave the cursor at the start of a fresh line** so the shell prompt doesn't land in the middle of a line.

## Go specifics (Bubble Tea)

- **Don't pass `tea.WithAltScreen()`.** Without it, Bubble Tea renders inline by default.
- **Bubble Tea leaves the last frame from `View()` on screen.** So once the user has picked or cancelled, set a `done` flag and have `View()` return just the result line (or `""`), then return `tea.Quit`. This one detail handles both the "erase the picker" and "leave the result" steps.
- **Draw the UI on stderr or `/dev/tty` and print the selection to stdout.** For example, `tea.WithOutput(os.Stderr)` plus `fmt.Println(branch)` after `p.Run()`. Then `git switch "$(gb)"` and pipes work, which is a big reason fzf-style tools are pleasant to use. If stdout is a TTY you can print the friendly `✓ branch` line; if it's piped, print the bare name.
- **Read input from the tty** (`tea.WithInput(tty)`) when stdin isn't a terminal, so the picker still works in pipelines.

My recommendation: inline rendering with a capped height, UI on stderr, the bare branch name on stdout, and a final `View()` that collapses to one result line. You keep the scrollback you want, and the tool stays composable.
