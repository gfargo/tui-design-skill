## The core idea

Over SSH, the clipboard and the editor sit on different machines from your process:

- **Copy:** don't call a clipboard tool. Send an **OSC 52** escape sequence, and the user's *local* terminal puts the text on its clipboard. It travels through SSH like any other output.
- **Open:** don't ask the local OS to open a file. The file is on the remote host. **Run `$EDITOR` in the same terminal** by pausing the TUI, or open it in a new tmux window.

## 1. `y` to copy: OSC 52, with a tmux path

```rust
use base64::{engine::general_purpose::STANDARD, Engine};
use std::{env, io::{self, Write}, process::{Command, Stdio}};

pub enum CopyMethod { Native, TmuxBuffer, Osc52, Osc52Passthrough }

pub fn copy_to_clipboard(text: &str, out: &mut impl Write) -> io::Result<CopyMethod> {
    let over_ssh = env::var_os("SSH_CONNECTION").is_some() || env::var_os("SSH_TTY").is_some();

    if env::var_os("TMUX").is_some() {
        // tmux >= 3.2: saves a tmux buffer and passes it to the outer terminal
        // as OSC 52. Works with tmux's default `set-clipboard external`.
        if pipe_to("tmux", &["load-buffer", "-w", "-"], text).is_ok() {
            return Ok(CopyMethod::TmuxBuffer);
        }
        // Older tmux: DCS passthrough (needs `allow-passthrough on` on 3.3+).
        // Every ESC inside the wrapper must be doubled.
        let b64 = STANDARD.encode(text);
        write!(out, "\x1bPtmux;\x1b\x1b]52;c;{b64}\x07\x1b\\")?;
        out.flush()?;
        return Ok(CopyMethod::Osc52Passthrough);
    }

    if !over_ssh {
        // Local session: use the real clipboard (arboard crate). This also
        // works in terminals that don't support OSC 52.
        if let Ok(mut cb) = arboard::Clipboard::new() {
            if cb.set_text(text).is_ok() {
                return Ok(CopyMethod::Native);
            }
        }
    }

    write!(out, "\x1b]52;c;{}\x07", STANDARD.encode(text))?;
    out.flush()?;
    Ok(CopyMethod::Osc52)
}

fn pipe_to(cmd: &str, args: &[&str], input: &str) -> io::Result<()> {
    let mut child = Command::new(cmd).args(args)
        .stdin(Stdio::piped()).stdout(Stdio::null()).stderr(Stdio::null())
        .spawn()?;
    child.stdin.take().unwrap().write_all(input.as_bytes())?;
    let status = child.wait()?;
    if status.success() { Ok(()) } else { Err(io::Error::other("tmux failed")) }
}
```

Call it with ratatui's writer so it doesn't get mixed into a frame halfway through drawing:

```rust
KeyCode::Char('y') => {
    if let Some(id) = app.selected_request_id() {
        let method = copy_to_clipboard(id, terminal.backend_mut())?;
        app.flash(match method {
            CopyMethod::Native | CopyMethod::TmuxBuffer => format!("Copied {id}"),
            _ => format!("Sent {id} to terminal clipboard"),
        });
    }
}
```

**Things to know about tmux and terminals:**

- **Why `tmux load-buffer -w` comes first:** shelling out is fine here because tmux runs on the same host as your app. With tmux's default `set-clipboard external`, tmux ignores OSC 52 sent by apps but forwards its own copies. Raw OSC 52 inside tmux therefore fails silently with default settings, while `load-buffer -w` works. As a bonus, the ID is also in the tmux buffer, so `prefix ]` pastes it.
- **tmux runs locally and SSH runs inside a pane:** `$TMUX` isn't set on the remote host, so your app sends plain OSC 52. Local tmux only passes it on if the user has `set -g set-clipboard on`. You can't detect this case, so document it.
- **Outer terminal isn't `xterm*`:** tmux may not know it supports the clipboard. Users add `set -as terminal-features ',alacritty:clipboard'` (or their terminal's TERM).
- **Which terminals support OSC 52:**
  - Supported: kitty, WezTerm, Ghostty, Alacritty, foot, Windows Terminal, and iTerm2 (iTerm2 needs "Applications in terminal may access clipboard" turned on).
  - Not supported: GNOME Terminal and other VTE-based terminals.
  - You can't reliably confirm the copy worked, which is why the flash message says "sent" for the OSC 52 paths.
- **Size:** request IDs are tiny, so the payload limits in some terminals and tmux won't matter.

## 2. Click a path to open it: handle the click in your app, run the editor where the file is

OSC 8 hyperlinks (`file://host/path`) look appealing, but they don't work well here:
- Over SSH, the local terminal can't open a remote file.
- Once you enable mouse capture, the terminal stops handling the clicks.
- ratatui's cell-width model makes OSC 8 awkward.

Instead, capture mouse clicks yourself.

**Record hit areas while rendering:**

```rust
// during render, for each visible path span:
app.click_targets.push(ClickTarget { area: span_rect, path: path.clone(), line: lineno });

// in the event loop (after `execute!(stdout, EnableMouseCapture)` at startup):
Event::Mouse(MouseEvent { kind: MouseEventKind::Down(MouseButton::Left), column, row, .. }) => {
    if let Some(t) = app.click_targets.iter().find(|t| t.area.contains((column, row).into())) {
        open_in_editor(terminal, &t.path, t.line)?;
    }
}
```

Clear `click_targets` at the start of each frame. Bind a key (e.g. `Enter` or `o`) to the same action on the selected line. Some users' mouse events get swallowed by tmux or their terminal, and keyboard users will want it anyway.

**Opening the editor:**

```rust
use crossterm::{execute, terminal::*, event::{EnableMouseCapture, DisableMouseCapture}};

fn open_in_editor<B: Backend + Write>(
    terminal: &mut Terminal<B>, path: &Path, line: Option<u32>,
) -> io::Result<()> {
    let editor = env::var("VISUAL").or_else(|_| env::var("EDITOR")).unwrap_or_else(|_| "vi".into());
    let mut argv = shell_words::split(&editor).map_err(io::Error::other)?; // handles "code --wait"
    argv.extend(editor_args(&argv[0], path, line));

    // Inside tmux: open a new window so the log viewer keeps tailing.
    if env::var_os("TMUX").is_some() {
        Command::new("tmux").arg("new-window").arg("--").args(&argv).status()?;
        return Ok(());
    }

    // Otherwise pause the TUI, run the editor in this terminal, then restore.
    execute!(terminal.backend_mut(), LeaveAlternateScreen, DisableMouseCapture)?;
    disable_raw_mode()?;
    let result = Command::new(&argv[0]).args(&argv[1..]).status();
    enable_raw_mode()?;
    execute!(terminal.backend_mut(), EnterAlternateScreen, EnableMouseCapture)?;
    terminal.clear()?; // force a full redraw
    result.map(|_| ())
}

fn editor_args(editor: &str, path: &Path, line: Option<u32>) -> Vec<String> {
    let p = path.display().to_string();
    let name = Path::new(editor).file_name().and_then(|s| s.to_str()).unwrap_or("");
    match (name, line) {
        ("code" | "codium" | "cursor", Some(n)) => vec!["-g".into(), format!("{p}:{n}")],
        ("hx" | "helix", Some(n))               => vec![format!("{p}:{n}")],
        (_, Some(n))                            => vec![format!("+{n}"), p], // vim, nvim, nano, emacs, micro
        (_, None)                               => vec![p],
    }
}
```

**Before opening, check the path:**
- Resolve relative paths against the log's working directory or a configurable root.
- Check that the file exists, and show "file not found on this host" if it doesn't. Logs collected from other machines will reference paths that aren't there.

Tell users the tmux `new-window` behavior is optional (e.g. `--editor-in=window|split|inline`). Some prefer `split-window -h`.

## Summary

| Situation | Copy | Open |
|---|---|---|
| Local, no tmux | `arboard` | Pause TUI, run `$EDITOR` |
| SSH, no tmux | OSC 52 | Pause TUI, run `$EDITOR` (remote) |
| tmux on the remote host | `tmux load-buffer -w -`, falling back to DCS passthrough | `tmux new-window $EDITOR` |
| SSH inside local tmux | OSC 52 (user needs `set-clipboard on`) | Pause TUI, run `$EDITOR` |

Crates used: `base64`, `arboard`, `shell-words`, `crossterm`, `ratatui`.
