The simplest approach is to write a small test-only `App` that mounts your form and keeps a list of every message the form posts. Your tests then drive it headlessly with Textual's `Pilot` and check that list. Textual has no built-in way to capture posted messages, so this recorder pattern is the usual approach, and Textual's own test suite uses it.

## 1. Setup

```bash
uv add --dev pytest-asyncio     # or: pip install pytest-asyncio
```

```toml
# pyproject.toml

asyncio_mode = "auto"   # without this, an unmarked `async def` test fails in strict mode
```

## 2. Shape the form so it's easy to test

This works best if the form is its own widget that posts a custom message. The validation rule goes in a plain function so you can test it without a terminal. If your code looks different, the key parts are a `Submitted` message and an error label that shows text, not just a color change.

```python
# entry_form.py
from textual import on
from textual.app import ComposeResult
from textual.containers import Vertical
from textual.message import Message
from textual.widgets import Button, Input, Label, Select

KINDS = [("Person", "person"), ("Company", "company")]


def validate_name(value: str) -> str | None:
    return "Name is required" if not value.strip() else None


class EntryForm(Vertical):
    DEFAULT_CSS = """
    EntryForm { height: auto; }
    #name-error { color: $error; display: none; }
    """

    class Submitted(Message):
        def __init__(self, name: str, kind: str) -> None:
            super().__init__()
            self.name = name
            self.kind = kind

    def compose(self) -> ComposeResult:
        yield Input(placeholder="Name", id="name")
        yield Label("", id="name-error")
        yield Select(KINDS, value="person", allow_blank=False, id="kind")
        yield Button("Submit", id="submit", variant="primary")

    @on(Button.Pressed, "#submit")
    def submit(self) -> None:
        name = self.query_one("#name", Input)
        error = self.query_one("#name-error", Label)
        if problem := validate_name(name.value):
            error.update(problem)
            error.display = True
            name.focus()          # send the user back to the field that needs fixing
            return
        error.display = False
        kind = self.query_one("#kind", Select).value
        self.post_message(self.Submitted(name.value.strip(), kind))
```

## 3. The tests

```python
# tests/test_entry_form.py
from textual import on
from textual.app import App, ComposeResult
from textual.widgets import Input, Label, Select

from entry_form import EntryForm, validate_name


class FormHarness(App):
    """Mounts the form alone and records every Submitted message that reaches the app."""

    def __init__(self) -> None:
        super().__init__()
        self.submitted: list[EntryForm.Submitted] = []

    def compose(self) -> ComposeResult:
        yield EntryForm()

    @on(EntryForm.Submitted)
    def record(self, message: EntryForm.Submitted) -> None:
        self.submitted.append(message)


# Cheapest layer: the rule itself, no terminal needed
def test_validate_name() -> None:
    assert validate_name("") == "Name is required"
    assert validate_name("   ") == "Name is required"
    assert validate_name("Ada") is None


async def test_empty_name_shows_error_and_posts_nothing() -> None:
    app = FormHarness()
    async with app.run_test(size=(80, 24)) as pilot:
        await pilot.click("#submit")
        await pilot.pause()                      # let messages finish bubbling

        error = app.query_one("#name-error", Label)
        assert error.display
        assert error.content == "Name is required"
        assert app.focused is app.query_one("#name", Input)
        assert app.submitted == []


async def test_submit_posts_message_with_values() -> None:
    app = FormHarness()
    async with app.run_test(size=(80, 24)) as pilot:
        await pilot.click("#name")
        await pilot.press(*"Ada")                # types one key at a time
        app.query_one("#kind", Select).value = "company"
        await pilot.click("#submit")
        await pilot.pause()

        assert len(app.submitted) == 1
        msg = app.submitted[0]
        assert (msg.name, msg.kind) == ("Ada", "company")
        assert not app.query_one("#name-error", Label).display
```

## Things that commonly trip people up

- **Call `await pilot.pause()` before checking anything.** Messages are delivered asynchronously. Without the pause, `submitted` can still be empty even though the message was sent.
- **Set the `Select` value directly.** Assigning `.value` tests your form's logic. Opening the dropdown with the keyboard mostly tests Textual's own `Select`, and those tests break more easily. Do drive the `Input` by typing, though, so the real key handling runs.
- **`notify()` is off in tests by default.** If you show the error as a toast instead of a label, nothing will appear unless you pass `run_test(notifications=True)`.
- **Alternative to the test App:** if you'd rather not subclass, use `run_test(message_hook=seen.append)` and filter with `isinstance(m, EntryForm.Submitted)`. The hook sees every message in the app. It may record the same message object more than once as it bubbles up, so check by identity, not by count.
- **Test narrow terminals too.** Run the submit test again with `size=(60, 24)`. `pilot.click` raises an error if the button is off-screen, so this catches a layout that pushes Submit out of view in a narrow tmux split.

## Optional: screenshot tests

If you also want to catch visual regressions, such as how the error state looks, `pytest-textual-snapshot` can save SVG snapshots of the screen. Note that its latest release requires `pytest<9`. On pytest 9, pip quietly installs an older version that saves `.raw` files instead of `.svg`. If you're on pytest 9, you can pin `pytest>=8.4,<9`, or skip snapshots: the tests above already cover the behavior you asked about.
