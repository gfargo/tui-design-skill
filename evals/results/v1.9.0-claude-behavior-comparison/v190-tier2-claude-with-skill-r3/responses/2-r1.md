## Short version

1. **Debug:** log the computed `Rect`s to a file with `tracing` and watch them with `tail -f` in a second terminal. This tells you whether the overlap is in Ratatui's buffer (a layout bug) or only on the screen (the terminal and the buffer disagree).
2. **Regression test:** move layout into a pure `fn compute_layout(area: Rect) -> AppLayout`. Then check its rules at every terminal size from your minimum up. Add a `TestBackend` test that renders size A, resizes to B, and checks the result matches a fresh render at B. That last test is what catches bugs that only show up "after certain resizes."

---

## (a) Debugging without corrupting the screen

`println!` can't work here. Raw mode turns off newline handling, and the next draw paints over whatever you printed (or the alternate screen hides it). Send diagnostics somewhere the TUI doesn't own.

**Log to a file:**

```rust
use std::{fs::File, sync::Mutex};
use tracing_subscriber::EnvFilter;

fn init_logging() -> color_eyre::Result<()> {
    let file = File::create("app.log")?;
    tracing_subscriber::fmt()
        .with_writer(Mutex::new(file))
        .with_ansi(false)
        .with_env_filter(EnvFilter::from_default_env())
        .init();
    Ok(())
}
```

Run `RUST_LOG=debug cargo run` in one terminal and `tail -f app.log` in another. Log two things:

```rust
// In the event handler
Event::Resize(w, h) => tracing::debug!(w, h, "resize event"),

// In draw(), using the rects you actually render into
let layout = compute_layout(frame.area());
tracing::debug!(area = ?frame.area(), ?layout, "layout");
```

**The log tells you which of two bugs you have:**

- **The logged rects overlap,** for example `panel.bottom() > footer.y`. The bug is in your layout code, and the test below will reproduce it.
- **The logged rects are fine but the screen still overlaps.** The buffer is correct and the terminal shows something else. Look for:
  - A `Resize` event that doesn't set your dirty/redraw flag.
  - Drawing based on a size you stored from an earlier `Resize(w, h)`, while `frame.area()` has a different size.

**Likely causes of a one-row overlap, most common first:**

1. **A rect built by hand instead of taken from `Layout`:** `area.height - 1`, `Rect::new(...)`, `y + h`. The overlap appears only at sizes where the arithmetic is off by one.
2. **A size kept from `Event::Resize` in app state and used for layout.** With tokio, that event can arrive before or after the draw that matters. Always lay out from `frame.area()`.
3. **The panel and the footer come from two different `Layout` splits** (e.g. one uses `Percentage`, the other subtracts rows). Each rounds on its own, so they disagree at odd heights. Take every sibling from a single split.
4. **Intentional overlap leaking out:** `spacing(Spacing::Overlap(1))` or a manual `+1` to collapse shared borders, applied at the wrong level.
5. **Cached state from an earlier size** (scroll offset, panel height, a cached `Rect`) that gets reused after a resize.

**Optional debug-build safety net** that panics the moment the rules break. Ratatui's panic hook restores the terminal first, so you get a readable message:

```rust
debug_assert!(layout.panel.bottom() <= layout.footer.y,
    "panel {:?} overlaps footer {:?} at {:?}", layout.panel, layout.footer, frame.area());
```

If the bug is a stale value, attach `lldb -p <pid>` from a second terminal and inspect state. Don't break into the debugger inside the app's own terminal, because it's still in raw mode on the alternate screen.

## (b) Regression tests that keep it fixed

### 1. A pure layout function, checked at every size (cheapest, catches most)

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct AppLayout { pub header: Rect, pub panel: Rect, pub sidebar: Rect, pub footer: Rect }

pub fn compute_layout(area: Rect) -> AppLayout {
    let [header, body, footer] = Layout::vertical([
        Constraint::Length(1), Constraint::Fill(1), Constraint::Length(1),
    ]).areas(area);
    let [sidebar, panel] = Layout::horizontal([Constraint::Length(30), Constraint::Fill(1)])
        .areas(body);
    AppLayout { header, panel, sidebar, footer }
}
```

`draw()` should only render into these rects and never compute any of its own.

```rust
#[test]
fn layout_invariants_hold_at_every_size() {
    const MIN: (u16, u16) = (60, 15); // use your declared floor
    for w in MIN.0..=250 {
        for h in MIN.1..=80 {
            let area = Rect::new(0, 0, w, h);
            let l = compute_layout(area);
            let rects = [l.header, l.panel, l.sidebar, l.footer];
            for r in rects {
                assert!(area.contains(r.as_position()) && r.right() <= area.right()
                        && r.bottom() <= area.bottom(), "{r:?} escapes {area:?}");
            }
            for (i, a) in rects.iter().enumerate() {
                for b in &rects[i + 1..] {
                    assert!(!a.intersects(*b), "{a:?} overlaps {b:?} at {w}x{h}");
                }
            }
            assert_eq!(l.footer.y, h - 1, "footer not pinned at {w}x{h}");
            assert_eq!(l.panel.bottom(), l.footer.y, "gap/overlap at {w}x{h}");
        }
    }
}
```

That's about 36k sizes and still runs in milliseconds. Since it tries every size, it finds the exact width×height that fails, which you weren't catching by hand. When it does, also add that size as its own named test.

### 2. Rendering after resizes must match a fresh render

This targets bugs that depend on history: stale cached sizes, scroll offsets, or saved rects.

```rust
use ratatui::{backend::TestBackend, Terminal};

fn render_at(app: &mut App, w: u16, h: u16) -> ratatui::buffer::Buffer {
    let mut t = Terminal::new(TestBackend::new(w, h)).unwrap();
    t.draw(|f| app.draw(f)).unwrap();
    t.backend().buffer().clone()
}

#[test]
fn resize_sequence_matches_fresh_render() {
    let sizes = [(120, 40), (61, 24), (200, 17), (80, 24), (60, 15), (133, 51)];
    let mut app = App::fixture();
    let mut term = Terminal::new(TestBackend::new(sizes[0].0, sizes[0].1)).unwrap();
    term.draw(|f| app.draw(f)).unwrap();
    for &(w, h) in &sizes[1..] {
        term.backend_mut().resize(w, h);
        // If your app reacts to Event::Resize, feed it here too:
        app.handle(Event::Resize(w, h));
        term.draw(|f| app.draw(f)).unwrap(); // draw() autoresizes
        let fresh = render_at(&mut App::fixture(), w, h);
        assert_eq!(term.backend().buffer(), &fresh, "diverged after resize to {w}x{h}");
    }
}
```

If the layout test passes but this one fails, the bug is state the app carried over from an earlier size.

### 3. Snapshots at fixed sizes (catches visual regressions)

```rust
#[test]
fn snapshot_sizes() {
    for (w, h) in [(80, 24), (60, 24), (60, 15)] {
        let mut t = Terminal::new(TestBackend::new(w, h)).unwrap();
        t.draw(|f| App::fixture().draw(f)).unwrap();
        insta::assert_snapshot!(format!("app_{w}x{h}"), t.backend());
    }
}
```

Snapshots record text only, which is enough here: a `└──` on the footer row will appear in the diff. Review changes with `cargo insta review`.

**If the overlap only ever appears on screen** (the logged rects are correct and every test above passes), it's in the terminal-facing part of the app: event loop timing or a missed redraw on `Resize`, which `TestBackend` can't see. In that case, add one PTY test with `termlens` (pin its version; it's a new crate). It starts the binary, resizes the PTY, and snapshots `terminal.screen()`. Keep it to that one test and rely on the cheaper tests above for everything else.
