## Short answer

1. **Debugging:** stop printing to the screen. Log every computed `Rect` and the size the frame was drawn at to a file, and watch it with `tail -f` in a second terminal.
2. **Regression test:** move the layout into a pure function `fn compute_layout(Rect) -> AppLayout`. Then write a test that checks it at **every** terminal size, plus a `TestBackend` test that replays a sequence of resizes. The bug only looks random because you can't predict which size triggers it. Checking every size makes it repeatable.

## Likely causes, most likely first

The layout is a pure function of the terminal size, so the intermittency usually comes from where the size or the rects come from:

1. **The size is stale.** The app stores `(w, h)` from `Event::Resize` or calls `terminal.size()`, then computes rects from that number. While you drag-resize, crossterm sends a burst of resize events, and the stored size can lag the real one by a row. `terminal.draw` resizes its own buffer, so `frame.area()` is correct while your rects are one row too tall. That's exactly a panel border landing on the footer.
2. **The layout is cached.** Rects computed in the resize handler, for example for mouse hit-testing, get reused in `draw`.
3. **The panels and footer come from separate splits.** If the panels are split from `frame.area()` instead of from the `body` rect left after taking the footer, or there's hand arithmetic like `area.height - 1`, rounding can make the two splits disagree at some heights.
4. **The constraints can't all fit.** For example, `Length(3) + Min(10) + Length(1)` in fewer than 14 rows. Small heights are where these bugs live.

Draw order also matters. Whichever widget renders last wins the shared row, so the bug can come and go when draw order changes.

## (a) Debugging without corrupting the screen

`println!` can't work here. Raw mode turns off newline handling, and the next draw overwrites whatever you printed. Send output to a file instead:

```rust
// Cargo.toml: tracing, tracing-subscriber = { features = ["env-filter"] }
use std::{fs::File, sync::Mutex};
use tracing_subscriber::EnvFilter;

fn init_logging() -> color_eyre::Result<()> {
    tracing_subscriber::fmt()
        .with_writer(Mutex::new(File::create("app.log")?))
        .with_ansi(false)
        .with_env_filter(EnvFilter::from_default_env())
        .init();
    Ok(())
}
```

Call it in `main` before `ratatui::run`. Run with `RUST_LOG=debug`, and in another terminal run `tail -f app.log`. Then log both sides of the suspected mismatch:

```rust
// event handler
Event::Resize(w, h) => {
    tracing::debug!(w, h, "resize event");
    self.dirty = true; // treat Resize as "redraw", never as the source of truth for size
}

// draw
fn draw(&self, frame: &mut Frame) {
    let layout = compute_layout(frame.area());
    tracing::debug!(area = ?frame.area(), ?layout, "draw");
    debug_assert!(layout.panels.iter().all(|p| p.bottom() <= layout.footer.y),
        "panel overlaps footer at {:?}: {layout:?}", frame.area());
    // ...
}
```

Reproduce the glitch, then read the log:
- If the last `resize event` size differs from the `draw` area, it's cause 1 or 2. Fix it by computing layout only from `frame.area()` inside `draw`.
- If the sizes match but the `debug_assert` fires, it's the layout math (cause 3 or 4), and the logged area is your failing size.

Other options:
- **In-app debug pane:** a `show_debug: bool` toggle that splits off a column and renders `format!("{layout:#?}")`.
- **`tui-logger`:** a ready-made log widget.
- **A debugger:** attach it from a *second* terminal with `lldb -p <pid>`. Pausing the app in its own terminal leaves you at a prompt that's still in raw mode.

## (b) Regression tests

**Step 1: make the layout pure and testable.** Split the panels from `body`, never from the full area:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct AppLayout { pub header: Rect, pub panels: [Rect; 2], pub footer: Rect }

pub fn compute_layout(area: Rect) -> AppLayout {
    let [header, body, footer] = Layout::vertical([
        Constraint::Length(3),
        Constraint::Min(0),
        Constraint::Length(1),
    ]).areas(area);
    let panels = Layout::horizontal([Constraint::Fill(1), Constraint::Fill(2)]).areas(body);
    AppLayout { header, panels, footer }
}
```

**Step 2: check the rules at every size.** Each layout takes microseconds, so roughly 16k sizes is fine:

```rust
#[test]
fn layout_invariants_hold_at_every_size() {
    for w in 0..=200u16 {
        for h in 0..=80u16 {
            let area = Rect::new(0, 0, w, h);
            let l = compute_layout(area);
            let rects = [l.header, l.panels[0], l.panels[1], l.footer];
            for r in rects.iter().filter(|r| !r.is_empty()) {
                assert_eq!(r.intersection(area), *r, "{r:?} escapes {area:?}");
            }
            for (i, a) in rects.iter().enumerate() {
                for b in &rects[i + 1..] {
                    assert!(!a.intersects(*b), "{w}x{h}: {a:?} overlaps {b:?}");
                }
            }
            if !l.footer.is_empty() {
                assert_eq!(l.footer.bottom(), area.bottom(), "{w}x{h}: footer not pinned");
            }
        }
    }
}
```

When this fails, the message names the exact size, and that size becomes a permanent pinned case. `proptest` works too, but checking every size is cheaper and finds everything.

**Step 3: replay resizes through the real draw path.** Step 2 can't catch a stale size, because that bug is in the event-to-draw path, not the math. Drive the same handler the real loop uses, including an event that lags the actual size:

```rust
use ratatui::{backend::TestBackend, buffer::Buffer, crossterm::event::Event, Terminal};

fn row(buf: &Buffer, y: u16) -> String {
    (0..buf.area.width).map(|x| buf[(x, y)].symbol()).collect()
}

#[test]
fn footer_survives_resize_sequence() -> color_eyre::Result<()> {
    let mut app = App::default();
    let mut terminal = Terminal::new(TestBackend::new(80, 24))?;
    // (actual size, size reported by the event): the last entries model a lagging burst
    let steps = [((80, 24), (80, 24)), ((80, 23), (80, 23)), ((60, 24), (60, 24)),
                 ((80, 17), (80, 17)), ((80, 20), (80, 21)), ((100, 30), (100, 31))];
    for ((w, h), (ew, eh)) in steps {
        terminal.backend_mut().resize(w, h);
        app.handle(Event::Resize(ew, eh));
        let frame = terminal.draw(|f| app.draw(f))?;
        let footer = row(frame.buffer, h - 1);
        assert!(footer.starts_with(" q quit"), "{w}x{h}: footer row is {footer:?}"); // your footer text
        assert!(!footer.contains('└'), "{w}x{h}: panel border on footer row");
    }
    Ok(())
}
```

**Step 4: snapshot fixed sizes.** Use `insta` at 80×24, at 60 columns, at your minimum size, and at the size that failed:

```rust
for (w, h) in [(80, 24), (60, 24), (40, 10), (80, 17)] {
    let mut terminal = Terminal::new(TestBackend::new(w, h))?;
    terminal.draw(|f| app.draw(f))?;
    insta::assert_snapshot!(format!("app_{w}x{h}"), terminal.backend());
}
```

Snapshots only record text, not colors. Since this bug is about border characters, text is enough.

## Two related fixes

- **Add a minimum size.** Below the height where your constraints fit, draw a "Terminal too small — need W×H" screen instead of the normal layout. That removes cause 4 entirely, and the every-size test then also covers the too-small screen.
- **Skip a PTY test unless you need it.** An end-to-end test that runs your real binary in a pseudo-terminal (the `termlens` crate does this; pin its version) is only worth it if step 3 can't reach the bug, for example because your real loop doesn't call `handle` the way the test does. Even then, keep it to one flow.

Don't fix this by drawing the footer last. That hides the overlap without fixing it. The `debug_assert` in `draw` plus the every-size test make sure it can't silently come back.
