**Short answer: don't take over the screen.** Render the picker inline, below the prompt, with a height cap. When it exits, erase the picker and leave a single receipt line. lazygit uses the full screen because people stay in it for a while. A branch picker is something you call up, use once and dismiss, so it should leave the shell around it alone.

## 1. Inline, with a height cap

The alternate screen (the separate full-screen buffer lazygit uses) has no scrollback. On exit the terminal restores the old view, so nothing from the session is kept. That's the opposite of what you want. Use the alternate screen when people work inside the app for a while (editors, dashboards, lazygit). Use inline rendering for pick-one-and-go tools.

Your picker shows one column of branch names and doesn't need a large preview, so it has no reason to use the full screen. Cap it at about 10 rows (or 40% of the terminal height, whichever is smaller) so the previous command and its output stay visible above it, like `fzf --height 40%`.

Wide (80+ columns):
```
~/src/api $ gsw
  feat/rate-limiter                         2 hours ago
> fix/null-session-token                    yesterday
  main                                      3 days ago
  chore/bump-go-1.26                        last week
  4/12  > fix█                 ↑↓ move · enter switch · esc cancel
```

Floor (60-column tmux split):
```
~/src/api $ gsw
  feat/rate-limiter               2h
> fix/null-session-token…         1d
  main                            3d
  4/12 > fix█          enter · esc
```

At narrow widths, keep the branch name and drop things in this order: the age column becomes short form (`2h`), then the key hints shrink to `enter · esc`, then long names are cut with `…`. Measure text with `lipgloss.Width`, not `len`. Below about 30 columns or 3 rows, show "terminal too small" instead of a broken layout.

**Clutter check:** no borders, since the terminal edge is enough. The selected row is marked by the `>` in the left column, so color is optional extra emphasis. The current branch is shown once (dimmed, or left out of the list) instead of being marked on every row. The counter, query and hints share one footer line.

## 2. Exit contract: answer on stdout, everything else on stderr

This is the decision that makes the tool composable:

- **Draw the UI on stderr** (`tea.WithOutput(os.Stderr)`), or on `/dev/tty`, the way gum does. When stdout is captured, as in `git switch $(gsw)`, anything drawn to stdout would end up in the result.
- **Print the branch name on stdout**, followed by a newline and nothing else.
- **Erase the picker on exit**, then leave a single receipt line. Don't leave the last frame of the list on screen.

After a pick, scrollback looks like this:
```
~/src/api $ gsw
✓ fix/null-session-token
~/src/api $
```

The command line is still there because you never left the main screen buffer, and the pick is recorded once. If stdout is a terminal, the branch printed to stdout already serves as the receipt. If stdout is captured, write `✓ <branch>` to stderr so the user still sees it.

If the tool runs `git switch` itself instead of only printing the name, let git's own `Switched to branch 'x'` be the receipt and don't print a second line.

**On cancel,** erase the picker and print nothing. Return a non-zero exit code so scripts can tell nothing was picked: 130 for Ctrl+C (fzf's convention) and 1 for Esc. Then `git switch $(gsw)` stops instead of running `git switch` with an empty argument.

## 3. Bubble Tea v2 outline

```go
type model struct {
    branches []branch
    filtered []branch
    cursor   int
    query    textinput.Model
    chosen   string
    done     bool
}

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyPressMsg:
        switch msg.String() {
        case "enter":
            if len(m.filtered) > 0 {
                m.chosen = m.filtered[m.cursor].name
            }
            m.done = true
            return m, tea.Quit
        case "esc":
            m.done = true
            return m, tea.Quit
        case "ctrl+c":
            m.done = true
            return m, tea.Interrupt
        // up/down, ctrl+p/ctrl+n move; everything else goes to m.query
        }
    }
    // ...
}

func (m model) View() tea.View {
    if m.done {
        return tea.NewView("") // erase the transient UI; receipt is printed after Run
    }
    return tea.NewView(m.render()) // inline is the default: no v.AltScreen
}

func main() {
    p := tea.NewProgram(newModel(), tea.WithOutput(os.Stderr))
    final, err := p.Run()
    if errors.Is(err, tea.ErrInterrupted) {
        os.Exit(130)
    }
    if err != nil {
        fmt.Fprintln(os.Stderr, "gsw:", err)
        os.Exit(1)
    }
    m := final.(model)
    if m.chosen == "" {
        os.Exit(1)
    }
    fmt.Println(m.chosen) // stdout: the answer
    if !term.IsTerminal(int(os.Stdout.Fd())) {
        fmt.Fprintln(os.Stderr, "✓", m.chosen) // receipt when stdout is captured
    }
}
```

Printing the receipt after `Run()` returns, rather than leaving it as the final frame, means it can't be overwritten by the renderer's own cleanup.

Other details that matter for this kind of tool:

- **Typing goes into the filter,** so use `↑`/`↓` and `Ctrl+P`/`Ctrl+N` to move, not `j`/`k`. `Enter` picks, `Esc` cancels, and `Ctrl+C` interrupts.
- **Load branches in a `tea.Cmd`, never inside `Update`.** Use `git for-each-ref --sort=-committerdate refs/heads --format=...`. If the user is outside a git repo, report that on stderr and exit before starting the UI. If there's only one branch, say "no other branches" instead of showing an empty list.
- **Startup speed is part of the design** for a tool you run dozens of times a day. Show the list on the first frame if possible, and avoid a loading spinner that flashes for 50 ms.
- **Test without a terminal first:** unit-test filtering and sorting, then golden-test frames at 80×24 and at 60 columns. Add one test in a pseudo-terminal that checks `$(gsw)` captures only the branch name and that the receipt appears on stderr.

**When the full screen would be worth it:** only if you later add a large preview pane, such as a commit log or diff for the highlighted branch. Even then, fzf keeps an inline mode for that case. Start inline and switch only if the preview needs the space.
