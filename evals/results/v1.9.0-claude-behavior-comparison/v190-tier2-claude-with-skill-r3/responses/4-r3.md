I've read the skill's guidance on inline vs. full-screen and the Go/Bubble Tea notes. Here's the answer.

## Recommendation: don't take over the screen. Draw it inline, below the prompt, with a capped height.

lazygit is something you stay in for a while, so the alternate screen suits it. Your picker is something you call up, pick from and leave. That's a bounded list (recent branches, maybe 10–30 rows) with no big preview pane. Two problems with full screen for that:

- **It defeats your own goal.** The alternate screen has no scrollback. When it closes, the terminal snaps back as if nothing happened. You'd lose exactly the context you want to keep.
- **It's a jarring jump** for a two-second interaction. The whole screen flips, then flips back.

Use the bounded inline mode from fzf (`fzf --height 40%`): the list draws just under the cursor, the earlier shell history stays visible above it, and nothing is taken over. Note that fzf's *default* is full screen; the inline mode is something you opt into with `--height`. In Bubble Tea v2, inline is the default. Just don't set `v.AltScreen = true`.

```
$ git switch $(brp)                      ← stays visible the whole time
> feat/                                  3/41
▌ feat/login-redirect        2h ago
  feat/billing-v2            yesterday
  feat/search-ranking        3d ago
  ↑↓ move · enter pick · esc cancel
```

## The exit contract: erase the picker, keep a one-line receipt

Three rules make this work, both in scrollback and inside `$(...)`.

**1. The UI goes to the terminal; only the answer goes to stdout.** If the picker draws on stdout, `git switch $(brp)` captures the escape codes along with the branch name. Draw on `/dev/tty`, falling back to stderr (`tea.WithOutput(tty)`). Print only the branch name to stdout, after `p.Run()` returns. gum and fzf both work this way.

**2. On exit, erase the list completely.** Don't leave a half-drawn picker behind. Set a `done` flag in `Update` before returning `tea.Quit`, and have `View()` return an empty view when it's set. The last frame drawn is then blank.

**3. Leave one receipt line, in the right place:**

| How it was run | Scrollback afterward |
|---|---|
| `brp` (stdout is a terminal) | `$ brp` / `feat/login-redirect` (the stdout line *is* the receipt) |
| `git switch $(brp)` (stdout is captured) | `$ git switch $(brp)` / `✓ feat/login-redirect` (receipt on the tty) / `Switched to branch 'feat/login-redirect'` |
| Cancelled with Esc or Ctrl+C | `$ brp`, then nothing. Exit 130 so `git switch $(brp)` doesn't run with an empty argument |

Only print the tty receipt when stdout is *not* a terminal. Otherwise the branch shows up twice. Cancelling is an abort, not a success: exit 0 with empty output would let `&&` chains keep going.

```go
// after p.Run() returns
if m.cancelled {
    os.Exit(130)
}
if !term.IsTerminal(int(os.Stdout.Fd())) {
    fmt.Fprintf(tty, "✓ %s\n", m.choice) // receipt for scrollback
}
fmt.Println(m.choice) // the answer, plain text, no ANSI
```

(Bubble Tea delivers raw-mode Ctrl+C as a key press, so handle it in `Update`: set `cancelled` and quit. Then `Run()` still restores the terminal before you exit.)

## Narrow terminals (60-column tmux split, 80×24)

There's one column of content, so nothing needs to collapse. Truncate the branch name with `…`, measuring width with `lipgloss.Width`, not `len`. Drop the relative time first:

```
> feat/                         3/41
▌ feat/search-ranking-experim…
  feat/billing-v2
  ↑↓ · enter · esc
```

Cap the height at about 40% of the rows, with at least about 5 rows for the list. If the terminal is shorter than that, show a single line like `brp: terminal too short (need 6 rows)` instead of a broken list.

## Keep the chrome light

- No border. The prompt line and the cursor already mark where the picker starts.
- Mark the selected row with one or two signals: `▌` plus reverse video. Don't also add color, bold and `>`.
- Show the current branch with a single `*` (it works in monochrome and under `NO_COLOR`). Don't add a "current" label on top of it.
- Keep the `3/41` match count. Skip a title bar.

If you add a large preview later (say, `git log` for the highlighted branch), that's the point where full screen starts to make sense. Even then, the stdout and receipt rules above stay the same.
