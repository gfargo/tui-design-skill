The short version: copy with **OSC 52**, and open files by **suspending the TUI and running `$EDITOR` on the machine where the TUI is running**. Neither one needs `pbcopy` or `xclip`. Both work over SSH because the escape sequence travels to the user's local terminal while the editor runs remotely, next to the files. Inside tmux, copying needs one config line. The click needs no tmux config.

## 1. `y` → copy the request ID

OSC 52 is an escape sequence that tells the user's terminal emulator to set its clipboard. It goes through the TTY stream like any other output, so it crosses SSH, containers and tmux. It is **write-only**, and the terminal never confirms that it worked. Always send it, and also use a local clipboard when you're not remote:

```rust
use base64::{engine::general_purpose::STANDARD, Engine};
use std::io::{self, Write};

/// OSC 52: the user's terminal sets its clipboard. Works over SSH; no ack.
fn copy_osc52(text: &str) -> io::Result<()> {
    let mut out = io::stdout().lock();
    write!(out, "\x1b]52;c;{}\x1b\\", STANDARD.encode(text))?;
    out.flush()
}

fn is_remote() -> bool {
    std::env::var_os("SSH_TTY").is_some() || std::env::var_os("SSH_CONNECTION").is_some()
}

pub fn copy(app: &mut App, text: &str) {
    let _ = copy_osc52(text); // harmless where unsupported
    let local = !is_remote()
        && app.clipboard.as_mut().is_some_and(|cb| cb.set_text(text).is_ok()); // arboard::Clipboard, kept alive in App
    app.status = if local {
        format!("Copied {text}")
    } else {
        format!("Sent {text} to terminal clipboard (OSC 52)")
    };
}
```

Notes:
- **Call it from your key handler, not inside `terminal.draw`.** Writing to stdout between frames is fine because the sequence takes up no screen cells. Don't put escape sequences inside a `Span`; that breaks Ratatui's width calculations.
- **Don't wrap it in tmux DCS passthrough.** tmux handles OSC 52 natively.
- crossterm 0.29 also has a built-in OSC 52 command. The hand-written version above is just as small and doesn't care which crossterm version you use.
- **Have a fallback for when it doesn't land.** Show the full ID in the detail pane on its own line, so users can select it with the mouse (Shift-drag; Option-drag in iTerm2). Don't let the 60-column list's truncation be the only place the ID appears.

### Making it work in tmux

Put this in your README or `--help`:

```tmux
# Let inner apps set the clipboard. The default, "external", blocks them.
set -g set-clipboard on

# tmux < 3.6 only, if the outer terminal's terminfo lacks Ms.
# Replace xterm-256color with the TERM *outside* tmux.
set -as terminal-features ',xterm-256color:clipboard'
```

- **Nested tmux** (tmux locally, SSH, tmux again on the server): **each** layer needs `set-clipboard on`.
- **The terminal itself** must allow OSC 52 writes. Most do by default. iTerm2 needs *"Applications in terminal may access clipboard"* turned on.
- **GNU screen** drops OSC 52 completely. There, only the visible fallback above works.

## 2. Click a path → open it in the editor

**Don't use OSC 8 `file://` links.** Over SSH, the link opens on the user's laptop, where `/srv/app/src/db/pool.rs` doesn't exist. Ratatui also has no native hyperlink support. Instead, turn the click into the same action as a key, then do Ratatui's editor handoff.

**Enable only the mouse modes you need.** crossterm's `EnableMouseCapture` also turns on 1003, which reports every mouse movement. For clicks plus the scroll wheel, 1000 and 1006 are enough:

```rust
execute!(stdout(), Print("\x1b[?1000h\x1b[?1006h"))?;   // in enable_extra_modes()
execute!(stdout(), Print("\x1b[?1006l\x1b[?1000l"))?;   // in disable_extra_modes(), before ratatui::restore()
```

Add these to the same enable/disable pair your panic hook already calls. Ratatui's `restore()` does **not** turn mouse modes off. tmux passes the clicks through once your app turns mouse reporting on. Ctrl-drag and Alt-drag still belong to tmux.

**Hit-test against what you actually drew.** While rendering, record where each path appeared. Rebuild this list every frame:

```rust
struct PathHit { area: Rect, path: PathBuf, line: Option<u32> }

// in render: x = row_x + UnicodeWidthStr::width(prefix) as u16  (measure cell width, not bytes)
app.hits.push(PathHit { area: Rect::new(x, y, shown_width, 1), path, line });

// in update:
Event::Mouse(MouseEvent { kind: MouseEventKind::Down(MouseButton::Left), column, row, .. }) => {
    if let Some(h) = app.hits.iter().find(|h| h.area.contains(Position::new(column, row))) {
        app.pending = Some(Action::Open(h.path.clone(), h.line));
    }
}
Event::Key(k) if k.code == KeyCode::Char('o') => app.pending = app.selected_path().map(Action::Open), // keyboard equivalent
```

When a path is truncated at narrow widths (`…/pool.rs:88`), the clickable area is the truncated text, but the full path is what gets opened.

**Build the editor command** from `$VISUAL`, then `$EDITOR`, then `vi`. Split it with `shell-words`, because `EDITOR="code --wait"` is common:

```rust
fn editor_command(path: &Path, line: Option<u32>) -> Command {
    let ed = env::var("VISUAL").or_else(|_| env::var("EDITOR")).unwrap_or_else(|_| "vi".into());
    let mut words = shell_words::split(&ed).unwrap_or_else(|_| vec![ed.clone()]);
    let mut cmd = Command::new(words.remove(0));
    cmd.args(words);
    let prog = Path::new(cmd.get_program()).file_name().and_then(|s| s.to_str()).unwrap_or("");
    match (line, prog) {
        (Some(n), "hx" | "helix" | "zed") => cmd.arg(format!("{}:{n}", path.display())),
        (Some(n), "code" | "codium")      => cmd.arg("--goto").arg(format!("{}:{n}", path.display())),
        (Some(n), _)                      => cmd.arg(format!("+{n}")).arg(path), // vim, nvim, nano, emacs
        (None, _)                         => cmd.arg(path),
    };
    cmd
}
```

Add a config override such as `editor = "nvim +{line} {file}"` for editors this doesn't cover.

**Run the editor from the main loop**, never from inside the event handler:
1. Stop your input reader thread or task first. Otherwise it steals the editor's keystrokes.
2. Call `disable_extra_modes()`, then `ratatui::restore()`.
3. Run `.status()` and wait for it to finish.
4. Re-enable raw mode, the alternate screen and the extra modes.
5. Call `terminal.clear()`, reload the data, and redraw.

This is Ratatui's spawn-vim recipe. Keep both the editor's result and the re-entry result so one error can't hide the other.

Before handing off, check that the path exists. If it doesn't, show `File not found on this host: src/db/pool.rs` instead of opening an empty buffer. Resolve relative paths against the service's working directory.

- **At 60 columns:** the message text truncates first, then IDs shorten to 8 characters (`y` still copies the full ID), and paths are cut from the left so the filename and line stay visible.
- **Status line:** the status message wins over the key hints, but the hints never shrink below `y`/`o`.
- **Clutter:** paths show up on every row, so underlining them all marks nothing. Draw paths in the normal style and underline only the path on the selected row. Skip clipboard and link icons; the footer hint already explains it.

## Mouse caveats to document
- Mouse capture takes over text selection. To select text anyway, hold Shift in most terminals, Option in iTerm2, or Fn in Terminal.app. Offer `--no-mouse`.
- Every click target has a key (`o`, `Enter`), so mouse support is a shortcut, not a requirement. That matters on restricted SSH setups and serial consoles.

## Tests worth writing
- **Unit tests:** the exact OSC 52 bytes for a known string; `editor_command` for vim, helix, `code --wait`, and an `EDITOR` containing quotes; hit-testing when the row has CJK text before the path, and against a truncated path.
- **One PTY smoke test:** open the editor (use `EDITOR=true`), come back, and check that raw mode, the alternate screen and mouse modes are restored. Run it once normally and once after an injected panic.
