The two features fail over SSH for different reasons, so they need different fixes.

- **Copy (`y`):** write an **OSC 52** escape sequence to the terminal. Your local terminal emulator reads it and sets your local clipboard. It passes through SSH unchanged. Inside tmux it works once the user sets one option in their tmux config.
- **Click a path:** don't use terminal hyperlinks (OSC 8). A `file://` link opens on the user's local machine, where that remote path doesn't exist. Ratatui also can't render OSC 8 cleanly (issue #1227). Instead, make the click an action inside the app. Turn on mouse reporting, work out which path was clicked, and run `$EDITOR` on the remote host where the file lives. Bind the same action to a key, because the mouse should never be the only way to do something.

## 1. Copy the request ID with `y`

OSC 52 is `ESC ] 52 ; c ; <base64> ST`. Write it through Ratatui's backend between draws (your key handler already runs between draws):

```rust
use std::io::Write;
use std::process::{Command, Stdio};
use base64::{engine::general_purpose::STANDARD, Engine};

fn osc52(text: &str) -> String {
    format!("\x1b]52;c;{}\x1b\\", STANDARD.encode(text))
}

impl App {
    fn copy(&mut self, terminal: &mut DefaultTerminal, text: &str) {
        let w = terminal.backend_mut();
        let _ = w.write_all(osc52(text).as_bytes()).and_then(|()| w.flush());

        if self.env.in_tmux {
            // Also fill tmux's paste buffer, so prefix+] works even if the
            // system clipboard didn't receive it.
            let _ = Command::new("tmux").args(["load-buffer", "-"])
                .stdin(Stdio::piped()).spawn()
                .and_then(|mut c| { c.stdin.take().unwrap().write_all(text.as_bytes())?; c.wait() });
        }
        if !self.env.over_ssh {
            // Local fallback for terminals that turn OSC 52 off.
            // Keep one arboard::Clipboard in App: on X11 the copied text
            // disappears when the Clipboard is dropped.
            if let Some(cb) = self.clipboard.as_mut() { let _ = cb.set_text(text); }
        }
        self.status = self.env.copy_message(text);
    }
}
```

Crossterm 0.29 also has its own OSC 52 copy command if you'd rather not hand-roll the sequence. Either way:

**The tmux case.** tmux handles OSC 52 itself, so don't wrap it in DCS passthrough and don't require `allow-passthrough`. What matters is the `set-clipboard` option:
- The default is `external`. tmux's own copy mode can set the outer clipboard, but it **ignores OSC 52 from apps running inside it**. That's the setting your tmux users have now.
- Users need this in `~/.tmux.conf`:
  ```tmux
  set -g set-clipboard on
  ```
- To pass the copy on to the outer terminal, tmux needs either the `Ms` terminfo capability or (tmux 3.6+) the terminal's device-attributes reply. Most modern terminals work without extra setup. On older setups the fix is `set -as terminal-features ',xterm-256color:clipboard'`.

**Detect the setting so you can say what actually happened.** OSC 52 is write-only, so you can never confirm the copy arrived. At startup, if `$TMUX` is set, run `tmux show-options -gv set-clipboard` once and keep the result. Detect SSH with `$SSH_TTY` or `$SSH_CONNECTION`. Then make the status message match reality:

| Situation | Status line |
|---|---|
| Local, or SSH without tmux | `Copied req_7f3a…` |
| tmux, `set-clipboard on` | `Copied req_7f3a…` |
| tmux, `external` or `off` | `Copied to tmux buffer (prefix+]) — add "set -g set-clipboard on" for system clipboard` |

Other things to know:
- Alacritty 0.11+ ignores OSC 52 writes from windows that don't have focus. A keypress always comes from the focused window, so `y` is fine. Don't copy from a background task.
- Some terminals turn OSC 52 off or limit it to roughly 75 KB. Request IDs are tiny, but if you add "copy whole log entry" later, cap the size.
- Never request clipboard reads. Most terminals block them because a remote host could use them to steal data.

## 2. Click a path to open it in the editor

**Mouse mode.** Crossterm's `EnableMouseCapture` turns on every mouse mode, including 1003, which reports every pointer movement. For clicks you only need press/release (1000) plus SGR coordinates (1006). Enable just those, and turn them off yourself on exit and in the panic hook, because `ratatui::restore()` won't:

```rust
const MOUSE_ON:  &str = "\x1b[?1000h\x1b[?1006h";
const MOUSE_OFF: &str = "\x1b[?1006l\x1b[?1000l";
```

Put these in your `enable_extra_modes()` / `disable_extra_modes()` pair: the one called from the panic hook and before `restore()`, as in the Ratatui lifecycle pattern. Crossterm parses the SGR events without further setup. Add a `--no-mouse` flag. Mouse capture takes over drag-to-select, which is probably how users copy IDs today. Shift-drag still selects in most terminals (Option in iTerm2, Fn in Terminal.app). Mention that in your help screen.

**Finding the clicked path.** While drawing, record each visible path as `(row, col_start..col_end, LogLineIdx)`, measured in terminal cells, not bytes. On `MouseEventKind::Down(MouseButton::Left)`, look up the entry for that cell and run the same `open_path` action the keyboard uses. Take the full path from your log model, not the rendered text, which may be shortened.

**Keyboard equivalent.** Bind `o` (or Enter) to open the path on the selected line. Mouse is a shortcut, not the only route.

**Launch the editor on the remote host** using the same handoff as Ratatui's editor recipe: stop the input reader, turn off mouse mode, `restore()`, run the child and wait, re-enter, clear, redraw.

```rust
fn editor_command(path: &Path, line: Option<u32>) -> Command {
    let raw = std::env::var("VISUAL").or_else(|_| std::env::var("EDITOR"))
        .unwrap_or_else(|_| "vi".into());
    // Split so EDITOR="code --wait" and similar values work.
    let mut parts = shell_words::split(&raw).unwrap_or_else(|_| vec![raw.clone()]);
    let mut cmd = Command::new(parts.remove(0));
    cmd.args(parts);
    if let Some(n) = line { cmd.arg(format!("+{n}")); } // vi, nvim, nano, emacs; helix wants path:line
    cmd.arg(path);
    cmd
}

fn open_path(&mut self, terminal: &mut DefaultTerminal, p: &LogPath) -> Result<()> {
    let resolved = self.resolve(&p.path); // log paths are often relative to the service's cwd
    if !resolved.exists() {
        self.status = format!("Not found on this host: {}", p.path.display());
        return Ok(());
    }
    self.input.stop();          // otherwise the reader steals the editor's keystrokes
    disable_extra_modes();      // mouse off while the editor runs
    ratatui::restore();
    let child = editor_command(&resolved, p.line).status();
    let reentry = enable_raw_mode()
        .and_then(|()| execute!(stdout(), EnterAlternateScreen))
        .and_then(|()| enable_extra_modes())
        .and_then(|()| terminal.clear());
    self.input.start();
    // report child and reentry errors together, as in the recipe
    ...
}
```

Specific to a log viewer:
- **Parse `path:line[:col]`** when you extract paths, so the editor opens at the right line.
- **Check the file exists before handing off.** Paths in logs are often relative to the service's working directory or come from a container's filesystem. Let users set a `--path-root` (or a prefix rewrite such as `/app` → `~/src/svc`), and show a clear error instead of opening the editor on an empty file.
- **Keep tailing during the handoff.** Stop only the input reader. The file-follow task can keep adding to your buffer, and the redraw on return shows what arrived.

## Discoverability and narrow terminals

- Underline the path and ID **only on the selected line**. Underlining every path on every row would be a marker on every row, which marks nothing. Put the keys in the footer: `y copy id  o open  ? help`.
- At 80×24 and in a 60-column tmux split, long paths truncate. Truncate from the left (`…/handlers/auth.rs:142`) so the filename survives. Clicks still work because the hit map points at the full path in your model.

## Tests

- **Unit:** `osc52()` output, `path:line` parsing, `editor_command` argument building (`EDITOR="code --wait"`, missing `EDITOR`), and the status-message table for each environment.
- **Rendered frames:** check that the selected path is underlined and shortened from the left at 60 columns.
- **One PTY smoke test:** press `o` with `EDITOR=true`, then confirm the app comes back to a full redraw with mouse mode back on.

## What to tell users (README snippet)

```tmux
# ~/.tmux.conf — let apps inside tmux set your system clipboard
set -g set-clipboard on
```

This works over SSH because OSC 52 travels inside the SSH session. No X forwarding, `pbcopy`, or `xclip` is needed on the server.
