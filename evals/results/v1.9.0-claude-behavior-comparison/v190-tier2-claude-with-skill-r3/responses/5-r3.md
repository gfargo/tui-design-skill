Both features run into the same fact: over SSH, the TUI runs on the remote machine but the clipboard and screen belong to the user's local terminal. So the clipboard copy has to travel through the terminal connection itself, and the file has to open on the remote machine where it lives.

## Recommendation

| Feature | Inside tmux | Over SSH, no tmux | Local |
|---|---|---|---|
| `y` copy request ID | `tmux load-buffer -w -` | OSC 52 escape sequence | `arboard`, falling back to OSC 52 |
| Click a path or press `o` | Pause the TUI and run `$VISUAL`/`$EDITOR` on the remote machine, then resume | same | same |

**Don't use OSC 8 hyperlinks for the paths.** A `file://` link opens on the user's local machine, where the remote path doesn't exist. Ratatui also has no OSC 8 support: escape sequences inside a `Span` break its cell-width accounting (ratatui#1227). Use OSC 8 only for `https://` URLs.

## 1. Copy with `y`

**OSC 52** is an escape sequence that asks the terminal to put text on its clipboard. It travels inside the terminal stream, so it works over SSH: the user's local emulator handles it. The terminal never reports whether the copy worked, so treat it as best effort.

**Inside tmux:** by default (`set-clipboard external`), tmux ignores OSC 52 from programs running inside it. Don't wrap the sequence in DCS passthrough to get around that; tmux handles OSC 52 natively. Instead, give the text to tmux. `load-buffer -w` (tmux 3.2+) does two things:
- it saves the ID in tmux's own paste buffer, so `prefix ]` works even if the outer terminal blocks OSC 52;
- it forwards the ID to the local clipboard using tmux's own OSC 52 support.

```rust
use std::{env, io::{self, Write}, process::{Command, Stdio}};
use base64::{engine::general_purpose::STANDARD, Engine};

pub enum CopyVia { Tmux, Native, Terminal }

fn osc52(text: &str) -> String {
    format!("\x1b]52;c;{}\x1b\\", STANDARD.encode(text))
}

fn is_remote() -> bool {
    env::var_os("SSH_TTY").is_some() || env::var_os("SSH_CONNECTION").is_some()
}

/// Runs off the UI thread (spawn_blocking / std::thread); posts the result back as a message.
fn copy_via_tmux(text: &str) -> io::Result<bool> {
    let mut child = Command::new("tmux")
        .args(["load-buffer", "-w", "-"])
        .stdin(Stdio::piped()).stdout(Stdio::null()).stderr(Stdio::null())
        .spawn()?;
    child.stdin.take().unwrap().write_all(text.as_bytes())?;
    Ok(child.wait()?.success())
}

/// UI thread, between frames — never inside `terminal.draw`.
fn copy_direct(app: &mut App, terminal: &mut DefaultTerminal, text: &str) -> io::Result<CopyVia> {
    if !is_remote() {
        if let Some(cb) = app.clipboard.as_mut() {          // arboard::Clipboard kept alive in App
            if cb.set_text(text).is_ok() { return Ok(CopyVia::Native); }
        }
    }
    let out = terminal.backend_mut();                        // CrosstermBackend implements Write
    out.write_all(osc52(text).as_bytes())?;
    out.flush()?;
    Ok(CopyVia::Terminal)
}
```

How the pieces fit together:
- **Order:** if `$TMUX` is set, send a `CopyRequested` message to a worker that runs `copy_via_tmux`. If that fails, the worker sends back a fallback message, and the loop calls `copy_direct`. Otherwise, call `copy_direct` directly.
- **Writing the sequence:** an OSC 52 write takes up no screen cells, so writing it through the backend between frames doesn't disturb Ratatui's buffer.
- **Linux local:** keep the `arboard::Clipboard` in `App` for the whole session. On X11, the copied text can disappear when that object is dropped.
- **crossterm option:** crossterm 0.29 has a built-in OSC 52 command you can use instead of `osc52()`.

**Report only what you actually know** in the status line. The tmux and native paths can confirm success. OSC 52 can't, so word that message more softly:

```
 Copied req_7f3a9c… to tmux buffer + clipboard        y copy  o open  ? help
 Sent req_7f3a9c… to terminal clipboard               y copy  o open  ? help
```

At 60 columns, cut the middle of the ID (`req_7f…9c21`) and drop the key hints before you drop the message. Also show the full ID in the row's detail view, so if OSC 52 is blocked, users can still select it by hand with Shift-drag.

## 2. Click a path to open it

A click runs the same action as `o`. Mouse support has to stay optional, because some users turn it off or work over restricted SSH.

**Turn on the mouse.** Enable only the modes you need. Crossterm's `EnableMouseCapture` turns on every mode, including 1003, which reports every pointer move. A click needs only 1000 (press/release) and 1006 (SGR coordinates):

```rust
const MOUSE_ON: &str  = "\x1b[?1000h\x1b[?1006h";
const MOUSE_OFF: &str = "\x1b[?1000l\x1b[?1006l";
```

Put these in your `enable_extra_modes()` / `disable_extra_modes()`, and call `disable_extra_modes()` from the panic hook too. Ratatui's `restore()` doesn't turn mouse reporting off, so without this a crash leaves the user's shell receiving mouse escape codes. Also add a `--no-mouse` flag, and document the selection bypass. Turning on mouse capture takes over normal text selection, so users hold a modifier key to select text: Shift in most terminals, Option in iTerm2.

**Hit-testing.** While drawing, record where each clickable item landed on screen. Measure positions in cells, not bytes:

```rust
enum Target { Path { path: PathBuf, line: Option<u32> }, RequestId(String) }
struct Hit { area: Rect, target: Target }

// in draw(&mut self, ...): self.hits.clear(), then for each visible span you render:
let x = row_area.x + line_prefix.cell_width();               // ratatui::buffer::CellWidth
self.hits.push(Hit { area: Rect::new(x, y, span_text.cell_width(), 1), target });
```

```rust
Event::Mouse(MouseEvent { kind: MouseEventKind::Down(MouseButton::Left), column, row, .. }) => {
    if let Some(hit) = self.hits.iter().find(|h| h.area.contains(Position::new(column, row))) {
        match &hit.target {
            Target::Path { .. } => self.pending = Some(Action::Open(hit.target.clone())),
            Target::RequestId(id) => self.pending = Some(Action::Copy(id.clone())),
        }
    }
}
```

Only record the part of a span that is actually visible after truncation. Otherwise a click on clipped-off text lands on the wrong target.

**Opening the file.** Use the hand-off sequence from Ratatui's spawn-vim recipe:
1. Stop the input reader.
2. Call `disable_extra_modes()`, then `ratatui::restore()`.
3. Run the editor and wait for it to exit.
4. Turn raw mode and the alternate screen back on, then call `enable_extra_modes()`.
5. Clear the terminal, reload state, and redraw.

Keep the editor's exit result instead of returning early with `?`, so that if both the editor and the reentry fail, you can report both errors.

**Building the editor command.** Try `$VISUAL`, then `$EDITOR`, then `vi`. Split the value with `shell-words`, because it may contain arguments (`code --wait`). Editors take a line number in different ways:

- `vim`, `nvim`, `nano`, `emacs`, `kak`: `+42 path`
- `hx`, `micro`: `path:42`
- anything else: an `editor = "cmd {file}:{line}"` template in your config file

Parse a trailing `:line:col` from log paths before resolving them.

**When the file isn't there.** Logs often name paths from a different host or container. Check that the file exists before handing off the terminal. If it doesn't, stay in the TUI and show `Not on this host: /srv/app/handler.rs`; don't launch an editor on an empty buffer.

**Keyboard path.** `o` (or Enter) opens the first path on the selected row. If the row has several, show a small picker.

**Styling.** Use one visual signal for clickable items, such as an underline. Adding color and an icon on top of it, on every row, makes the log harder to read.

## tmux.conf lines to document for users

```tmux
set -g set-clipboard on                                  # let apps' OSC 52 reach the outer clipboard
set -as terminal-features ',xterm*:clipboard'            # forward it; not needed on tmux 3.6+ with a modern terminal
```

With `load-buffer -w`, the default `external` setting already works. These lines matter for users who turned `set-clipboard` off, or whose outer terminal tmux doesn't recognize. Inside tmux 3.8+, mouse handling is on by default, so the Shift/Option selection bypass applies there too.

## Tests

- **Unit tests:** `osc52()` encoding; editor-command construction for each editor family; `:line:col` parsing; choosing the copy path from `$TMUX`, `$SSH_TTY` and `$SSH_CONNECTION`. Inject the environment rather than reading it in the logic.
- **Hit-testing:** render with `TestBackend` at 80×24 and at 60 columns, then check that clicking on CJK-prefixed and truncated paths finds the right target.
- **PTY smoke test:** one run that presses `o` and checks that the terminal state is restored after the editor exits.
