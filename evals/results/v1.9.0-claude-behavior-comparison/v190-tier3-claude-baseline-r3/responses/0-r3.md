# Your process can't change the shell's directory directly

On Unix, every process has its own working directory. Your TUI is a child of the shell, so `std::env::set_current_dir` only changes your process's directory, and that change is gone when you exit. There's no supported way for a child to change its parent's cwd. (Using ptrace or TIOCSTI to inject a `cd` into the parent is hacky, and TIOCSTI is disabled on modern Linux and not usable on macOS.)

## The usual pattern: a shell wrapper function

The shell has to run the `cd` itself. A small shell function runs your binary, reads the chosen path, and then calls `cd`. Because a shell function runs inside the user's shell process, its `cd` sticks. yazi, ranger, lf, nnn, broot and zoxide all do some version of this.

There are two ways to pass the path back.

### Option A: a temp file (recommended)

This is what yazi does with `--cwd-file`. Your TUI keeps full control of stdout and the terminal, so nothing interferes with rendering.

**Rust side:**
```rust
// args: --cwd-file <path>
if let (Some(cwd_file), Some(dir)) = (args.cwd_file, selected_dir) {
    std::fs::write(cwd_file, dir.as_os_str().as_encoded_bytes())?;
}
```
Restore the terminal (leave the alternate screen, disable raw mode) before you exit, as you normally would.

**zsh/bash:**
```sh
fp() {
  local tmp="$(mktemp -t fp-cwd.XXXXXX)" cwd
  command fp "$@" --cwd-file="$tmp"
  if cwd="$(cat -- "$tmp")" && [ -n "$cwd" ] && [ "$cwd" != "$PWD" ]; then
    builtin cd -- "$cwd"
  fi
  rm -f -- "$tmp"
}
```

**fish:**
```fish
function fp
    set tmp (mktemp -t fp-cwd.XXXXXX)
    command fp $argv --cwd-file=$tmp
    if set cwd (cat -- $tmp); and test -n "$cwd"; and test "$cwd" != "$PWD"
        builtin cd -- $cwd
    end
    rm -f -- $tmp
end
```

The `command fp` call matters: it runs the binary instead of calling the function again.

### Option B: print the path to stdout

You'd use it as `cd "$(fp)"`. The catch is that `$(...)` captures stdout, so your TUI can't draw there. You'd have to render to `/dev/tty` or stderr instead:

```rust
let tty = std::fs::OpenOptions::new().read(true).write(true).open("/dev/tty")?;
let backend = ratatui::backend::CrosstermBackend::new(tty);
// ...on quit:
println!("{}", dir.display());
```

This works, and fzf does it. But crossterm's input handling and some terminal queries can be awkward when stdin/stdout aren't the tty. Option A avoids all of that.

## Making setup easy

Copy zoxide and starship: add a subcommand that prints the wrapper function, so users add a single line to their rc file:

```sh
# ~/.zshrc
eval "$(fp init zsh)"
```
```fish
# config.fish
fp init fish | source
```

In Rust, that's a `match shell { "zsh" | "bash" => print!(include_str!("init.sh")), "fish" => ..., }`.

## Details worth getting right

- **Only write the file when the user chose a directory.** If they cancel (Esc or Ctrl-C), leave it empty so the wrapper doesn't `cd`.
- **Use two quit keys**, like yazi: `q` quits and changes directory, `Q` quits without changing it.
- **Write raw bytes**, not `display()`, so non-UTF-8 paths survive the round trip.
- **Canonicalize the path** before writing it, so symlinks and relative paths resolve the way you expect.
- **Keep the binary's exit code meaningful**, so a wrapper can skip the `cd` on non-zero.
