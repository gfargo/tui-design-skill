## First run with no key

**1. Look for the key in a fixed order, and only prompt if nothing is found:**

1. `--api-key` flag (one-off use)
2. `MYCLI_API_KEY` environment variable (CI, scripts)
3. The stored key (keychain, then file)
4. Nothing found: go to step 2

**2. Prompt only if a person is at the terminal.** Check that stdin is a TTY. If it isn't (CI, a pipe, cron), don't prompt, because the program will hang or crash. Exit with a non-zero code and a message that tells them how to fix it:

```
Error: no API key configured.
  Run `mycli auth login`, or set MYCLI_API_KEY.
```

**3. When prompting, finish the job.** Explain why you're asking and where to get a key, mask the input, check the key, save it, and then **continue with the command they originally ran**. Don't make them run it again.

```go
func ensureAPIKey(ctx context.Context) (string, error) {
	if k := resolveKey(); k != "" {
		return k, nil
	}
	if !term.IsTerminal(int(os.Stdin.Fd())) {
		return "", errors.New("no API key configured; run `mycli auth login` or set MYCLI_API_KEY")
	}

	var key string
	err := huh.NewInput().
		Title("Enter your API key").
		Description("Get one at https://example.com/settings/keys").
		EchoMode(huh.EchoModePassword).
		Validate(func(s string) error {
			if strings.TrimSpace(s) == "" {
				return errors.New("key can't be empty")
			}
			return nil
		}).
		Value(&key).
		Run()
	if err != nil {
		return "", err // includes huh.ErrUserAborted on Ctrl-C
	}

	key = strings.TrimSpace(key)
	if err := verifyKey(ctx, key); err != nil { // cheap authenticated call, e.g. GET /me
		return "", fmt.Errorf("that key was rejected: %w", err)
	}
	if err := saveKey(key); err != nil {
		return "", err
	}
	fmt.Fprintln(os.Stderr, "✓ API key saved")
	return key, nil
}
```

**4. Also add explicit commands:** `mycli auth login`, `mycli auth logout`, and `mycli auth status` (show the key masked, like `sk-…a1b2`, and where it came from). The first-run prompt is a convenience, but users still need a way to change or remove the key later.

## Where to store the key

**Use the OS keychain first, and fall back to a restricted file.**

- **Keychain:** use [`github.com/zalando/go-keyring`](https://github.com/zalando/go-keyring). It covers macOS Keychain, Windows Credential Manager and Linux Secret Service, and the key is encrypted at rest.
- **File fallback:** keyring calls fail on headless Linux and in most containers (no D-Bus or Secret Service). In that case, write to a separate credentials file. Warn the user once that this is happening.

```go
const service = "mycli"

func saveKey(key string) error {
	if err := keyring.Set(service, "api-key", key); err == nil {
		return nil
	}
	dir, err := os.UserConfigDir()
	if err != nil {
		return err
	}
	dir = filepath.Join(dir, "mycli")
	if err := os.MkdirAll(dir, 0o700); err != nil {
		return err
	}
	path := filepath.Join(dir, "credentials")
	fmt.Fprintf(os.Stderr, "warning: system keychain unavailable; storing key in %s\n", path)
	return os.WriteFile(path, []byte(key+"\n"), 0o600)
}
```

Rules for the fallback file:

- **Keep it separate from your main config file.** People commit config files and share dotfiles. A separate `credentials` file is much less likely to leak.
- **Use `0600` for the file and `0700` for the directory.** If you find an existing file with looser permissions, warn about it.
- **Never write the env var or flag value to disk.** Those are meant to override the stored key, not replace it.
- **Pick a path and be consistent.** `os.UserConfigDir()` follows `XDG_CONFIG_HOME` on Linux, but on macOS it returns `~/Library/Application Support`. Many CLI users expect `~/.config/mycli` on macOS too. Either choice works; just document it and show it in `auth status`.

When reading the key back, `resolveKey()` checks the same places in the same order as the list at the top: flag, env var, keychain, file.
