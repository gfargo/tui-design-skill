The first run should go: detect the missing key, prompt for it if a person is at the terminal, save it, then finish the command they actually ran. If nobody is at the terminal (CI, a pipe, a script), it should fail with a clear message and never prompt.

## First run with no key

**1. Resolve the key in a fixed order:**

```
--api-key flag  >  MYAPP_API_KEY env var  >  OS keychain  >  config file
```

If any of these has a key, use it and don't prompt. That way CI and scripting work without setup.

**2. If none has a key, check whether a person is at the terminal:**

- **Interactive (stdin and stdout are both a TTY):** Say briefly why you're asking and where to get a key. Prompt with the input hidden. Ideally make one cheap API call to check the key. Save it, tell them where you saved it, then **run the command they originally asked for**. Don't make them type it again.
- **Not interactive:** Never prompt, because it will hang or garble output. Print a short error to stderr that lists the ways to provide a key, and exit with a non-zero code:
  ```
  Error: no API key configured.
    Set MYAPP_API_KEY, pass --api-key, or run `myapp auth login`.
    Get a key at https://example.com/settings/keys
  ```

**3. Add explicit commands too:** `myapp auth login` (the same prompt, which also lets people rotate the key), `myapp auth logout`, and `myapp auth status` (shows where the key came from, masked as `sk-…a1b2`). The first-run prompt is a shortcut to these, not the only way in.

**4. Handle cancel properly.** If they press Ctrl-C or Esc in the prompt, exit quietly with code 130. Don't print a stack trace or "error: user aborted".

```go
func ensureAPIKey(ctx context.Context) (string, error) {
	if k := resolveKey(); k != "" { // flag, env, keyring, file
		return k, nil
	}
	if !term.IsTerminal(int(os.Stdin.Fd())) || !term.IsTerminal(int(os.Stdout.Fd())) {
		return "", errNoKey // caller prints the help text above, exits 1
	}

	var key string
	err := huh.NewInput().
		Title("Enter your MyApp API key").
		Description("Create one at https://example.com/settings/keys").
		EchoMode(huh.EchoModePassword).
		Validate(func(s string) error {
			if strings.TrimSpace(s) == "" {
				return errors.New("key can't be empty")
			}
			return nil
		}).
		Value(&key).
		Run()
	if errors.Is(err, huh.ErrUserAborted) {
		os.Exit(130)
	} else if err != nil {
		return "", err
	}
	key = strings.TrimSpace(key)

	if err := verifyKey(ctx, key); err != nil { // one cheap authenticated call
		return "", fmt.Errorf("that key was rejected: %w", err)
	}
	where, err := saveKey(key)
	if err != nil {
		return "", err
	}
	fmt.Fprintf(os.Stderr, "✓ Key saved to %s\n", where)
	return key, nil
}
```

(`term` is `golang.org/x/term`. If you want to support screen readers, huh's `WithAccessible(true)` switches to plain line-based prompts. You could turn it on with an env var.)

## Where to store the key

**Use the OS keychain first, and fall back to a file with locked-down permissions.**

1. **Keychain via [`github.com/zalando/go-keyring`](https://github.com/zalando/go-keyring).** This uses macOS Keychain, Windows Credential Manager, or Linux Secret Service. The key is encrypted at rest and doesn't sit in a dotfile that might get committed or synced.
2. **Fallback: `os.UserConfigDir()/myapp/credentials`.** That's `~/Library/Application Support` on macOS, or `$XDG_CONFIG_HOME` / `~/.config` on Linux. Create the directory with `0700` and the file with `0600`. You need this fallback for headless Linux boxes, containers and SSH sessions, which often have no Secret Service running.

```go
const service = "myapp"

func saveKey(key string) (string, error) {
	if err := keyring.Set(service, "api-key", key); err == nil {
		return "system keychain", nil
	}
	dir, err := os.UserConfigDir()
	if err != nil {
		return "", err
	}
	dir = filepath.Join(dir, "myapp")
	if err := os.MkdirAll(dir, 0o700); err != nil {
		return "", err
	}
	path := filepath.Join(dir, "credentials")
	return path, os.WriteFile(path, []byte(key+"\n"), 0o600)
}
```

`resolveKey` reads in the same order: `keyring.Get` first, then the file. `auth logout` deletes from both.

Some things to avoid:
- **Don't write the key into the user's shell rc** (`.zshrc` and similar). It's surprising, and those files are often in public dotfile repos.
- **Don't store it in the current directory or the project folder.** That's how keys end up committed to git.
- **Don't put it in the same file as your normal settings** if you have one. Keep secrets separate so people can share or sync their config safely.
- **Don't print the full key back to the user.** Mask it everywhere, including `auth status` and debug logs.
