## 1. Nerd Font icons with a fallback

**A terminal app can't tell which font the terminal is using.** The font only matters when the terminal draws the text, and no escape sequence reports it. So don't try to detect it. Give users a setting with a safe default.

**Offer three icon sets** and pick one in this order: CLI flag, then env var, then config file, then default.

```rust
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, clap::ValueEnum, serde::Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum IconSet {
    Nerd,     // needs a patched font
    #[default]
    Unicode,  // standard symbols that nearly every font has
    Ascii,    // works everywhere, including bare TTYs and odd SSH setups
}

pub struct Icons {
    pub folder: &'static str,
    pub file: &'static str,
    pub ok: &'static str,
    pub warn: &'static str,
    pub error: &'static str,
    pub spinner: &'static [&'static str],
}

impl IconSet {
    pub fn icons(self) -> &'static Icons {
        match self {
            IconSet::Nerd => &Icons {
                folder: "\u{f07b}", file: "\u{f15b}", ok: "\u{f00c}",
                warn: "\u{f071}", error: "\u{f00d}",
                spinner: &["\u{f110}", "\u{f1ce}"],
            },
            IconSet::Unicode => &Icons {
                folder: "▸", file: "·", ok: "✓", warn: "⚠", error: "✗",
                spinner: &["⠋", "⠙", "⠹", "⠸", "⠼", "⠴", "⠦", "⠧", "⠇", "⠏"],
            },
            IconSet::Ascii => &Icons {
                folder: "+", file: "-", ok: "ok", warn: "!", error: "x",
                spinner: &["|", "/", "-", "\\"],
            },
        }
    }
}
```

```rust
// precedence: --icons flag > MYAPP_ICONS env > config file > default
let icon_set = cli.icons
    .or_else(|| std::env::var("MYAPP_ICONS").ok().and_then(|v| IconSet::from_str(&v, true).ok()))
    .or(config.icons)
    .unwrap_or_default();
```

Things to watch:

- **Default to `Unicode`, not `Nerd`.** Without the font, Nerd glyphs show up as `□` or `?`, and a first-time user will think the app is broken. Unicode looks fine almost everywhere. People who have a Nerd Font installed are used to turning icons on.
- **Use `ascii` automatically when the terminal is very limited.** For example, when `TERM=linux` (the Linux console) or the locale isn't UTF-8 (check `LANG`/`LC_ALL`).
- **Width problems.** Nerd glyphs live in the Unicode Private Use Area. `unicode-width` counts them as 1 column, but many fonts draw them 1.5–2 columns wide, so they overlap the next character. Two fixes:
  - Always put a space after an icon (`format!("{} {}", icons.folder, name)`).
  - Recommend the **"Nerd Font Mono"** variant in your README, since it keeps glyphs to a single cell.
- **Don't let an icon carry meaning alone.** Pair status icons with color and/or text (`✓ synced`, `⚠ stale`). That way the ASCII set and colorblind users lose nothing.
- **Optional: a quick self-test.** A `myapp --check-icons` that prints `\u{f07b} ← do you see a folder? If not, set icons = "unicode"` saves you a lot of support questions.

## 2. Handling API timeouts during polling

The main rule is that **a failed poll should never blank the screen or freeze the UI.** Keep showing the last good data and make it clear that it's stale.

### Structure: fetch in the background, render from state

Never make network calls in the draw/event loop. Run a background task that sends results back over a channel:

```rust
enum Msg {
    Fetched(Result<Data, FetchError>),
    Tick,
    Key(KeyEvent),
}

// background poller
tokio::spawn(async move {
    let client = reqwest::Client::builder()
        .timeout(Duration::from_secs(5))   // always set this explicitly
        .build()?;
    let mut backoff = Backoff::new(Duration::from_secs(3), Duration::from_secs(60));
    loop {
        let res = client.get(&url).send().await
            .and_then(|r| r.error_for_status())
            .map_err(FetchError::from);
        let delay = if res.is_ok() { backoff.reset() } else { backoff.next() };
        if tx.send(Msg::Fetched(res.map(...))).is_err() { break; }
        tokio::select! {
            _ = tokio::time::sleep(delay) => {}
            _ = refresh_rx.recv() => { backoff.reset(); } // manual 'r' refresh
        }
    }
});
```

Running the loop one request at a time means requests can't pile up when the API is slow. Don't fire a new request every N seconds no matter what.

### Model the connection as explicit state

```rust
struct Remote<T> {
    data: Option<T>,                 // last good data, kept after failures
    last_ok: Option<Instant>,
    status: ConnStatus,
}

enum ConnStatus {
    Loading,                                   // first fetch, no data yet
    Live,
    Retrying { attempt: u32, next_at: Instant, err: String },
}
```

### What the user should see in each state

| State | Main view | Status bar |
|---|---|---|
| First load | Centered spinner ("Connecting…") | — |
| First load failed | Error message, plus "retrying in 8s · r to retry now" | — |
| Live | Data | `● updated 2s ago` (dim) |
| 1–2 timeouts | **Data unchanged** | `⚠ timeout · retrying in 6s` (yellow) |
| Long outage (e.g. >3 failures or >60s) | Data **dimmed** (`Modifier::DIM`) | `✗ offline since 14:02 · last data 3m old · r retry` (red) |
| Recovered | Data | Brief `✓ reconnected`, then back to normal |

Guidelines behind that table:

- **Don't use popups or modals for transient errors.** A timeout every few minutes is normal on real networks. A dialog that steals focus is worse than the timeout itself.
- **Ignore single blips.** Many apps only turn the indicator yellow after 2 consecutive failures. That avoids constant flicker on a flaky connection.
- **Show how old the data is ("updated 12s ago").** That's more useful than a red/green dot, and it's honest even when nothing has visibly failed.
- **Use exponential backoff with jitter, capped** (for example 3s, 6s, 12s, up to 60s). Reset it on success or when the user presses `r`. This protects the API, and it protects your users from rate limits.
- **Show a countdown to the next retry and offer `r` to retry now.** Users feel in control instead of stuck.
- **Never print errors to stderr.** It writes over the alternate screen and garbles the TUI. Log to a file (`tracing-appender`) and show a one-line summary in the status bar.
- **Keep the UI responsive.** Scrolling, filtering, and quitting should all keep working while the network is down. With the channel design above, that happens automatically.
