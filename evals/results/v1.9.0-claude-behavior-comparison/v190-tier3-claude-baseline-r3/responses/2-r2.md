There's no reliable way to detect a Nerd Font, so make icons a user choice with a safe default. For the API, keep showing the last data you got and label how old it is.

## 1. Nerd Font icons with fallbacks

**Why you can't auto-detect:** No terminal escape sequence reports which glyphs the font has. If a glyph is missing, the terminal usually still moves the cursor one cell and draws tofu (□), so checking the cursor position won't tell you anything either. Tools like `eza` (`--icons`) and lazygit (`gui.nerdFontsVersion`) make users opt in for this reason.

**The pattern:** Put every glyph behind an icon set with tiers, and pick the tier from settings:

```rust
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, clap::ValueEnum, serde::Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum IconMode {
    Nerd,
    #[default]
    Unicode,
    Ascii,
}

pub struct Icons {
    pub ok: &'static str,
    pub err: &'static str,
    pub warn: &'static str,
    pub folder: &'static str,
    pub spinner: &'static [&'static str],
}

const NERD: Icons = Icons {
    ok: "\u{f00c}",      // nf-fa-check
    err: "\u{f00d}",     // nf-fa-times
    warn: "\u{f071}",    // nf-fa-warning
    folder: "\u{f07b}",  // nf-fa-folder
    spinner: &["\u{f110}", "\u{f1ce}"],
};
const UNICODE: Icons = Icons {
    ok: "✓", err: "✗", warn: "!", folder: "▸",
    spinner: &["⠋", "⠙", "⠹", "⠸", "⠼", "⠴", "⠦", "⠧", "⠇", "⠏"],
};
const ASCII: Icons = Icons {
    ok: "+", err: "x", warn: "!", folder: ">",
    spinner: &["|", "/", "-", "\\"],
};

impl IconMode {
    pub fn icons(self) -> &'static Icons {
        match self {
            IconMode::Nerd => &NERD,
            IconMode::Unicode => &UNICODE,
            IconMode::Ascii => &ASCII,
        }
    }

    /// Precedence: CLI flag > env var > config file > environment-based default
    pub fn resolve(cli: Option<Self>, config: Option<Self>) -> Self {
        cli.or_else(|| std::env::var("MYAPP_ICONS").ok().and_then(|v| Self::from_str(&v, true).ok()))
            .or(config)
            .unwrap_or_else(|| match std::env::var("TERM").as_deref() {
                Ok("linux") | Ok("dumb") => IconMode::Ascii, // Linux VT console has a tiny font
                _ => IconMode::Unicode,
            })
    }
}
```

Store `&'static Icons` in your app state and never hardcode a glyph anywhere else.

**Things that will catch you out:**
- **Default to Unicode, not Nerd.** Basic symbols like `✓ ✗ ▸` and braille spinners are in nearly every modern font. Users who have a Nerd Font will find the setting. Users without one would otherwise see tofu on first launch and leave.
- **Use Nerd Fonts v3 codepoints.** v3 moved the Material Design icons from `U+F500–FD46` to `U+F0001+`, so old cheat sheets give glyphs that are broken on current fonts. Stick with Font Awesome (`nf-fa-*`) and Codicons where you can, because they're the most stable.
- **Width:** Nerd Font glyphs live in the Private Use Area. `unicode-width` counts them as 1 cell, but many non-"Mono" Nerd Font variants draw them wider, so they overlap the next character. Always put a space after an icon (`format!("{} {}", icons.ok, label)`). Avoid emoji entirely because their width varies between terminals.
- **Never let an icon carry meaning by itself.** Pair it with color and/or text (`✗ timeout`). This also keeps ASCII mode usable.
- **Optional extra:** add a `myapp --icon-test` command that prints every glyph in each tier, so users can see which one renders correctly.

## 2. Handling API timeouts

The basic rule: **a timeout should never blank the screen, block the UI, or pop up a modal.** Keep the last good data on screen and show how old it is.

**Architecture:** Fetch in a background task and send results to the render loop over a channel. The render loop only reads state, so it never waits on the network.

```rust
pub enum ApiEvent {
    FetchStarted,
    Data(Payload),
    Failed { kind: FailKind, msg: String, next_retry: Instant },
}

pub enum FailKind { Transient, Fatal } // timeout/5xx/network  vs  401/403/404/bad config

pub async fn poller(
    client: reqwest::Client,
    tx: mpsc::Sender<ApiEvent>,
    mut retry_now: mpsc::Receiver<()>, // bound to the `r` key
) {
    let base = Duration::from_secs(5);
    let max = Duration::from_secs(60);
    let mut delay = base;

    loop {
        let _ = tx.send(ApiEvent::FetchStarted).await;
        // Timeout must be shorter than the poll interval, so requests never pile up
        match tokio::time::timeout(Duration::from_secs(4), fetch(&client)).await {
            Ok(Ok(data)) => {
                delay = base;
                let _ = tx.send(ApiEvent::Data(data)).await;
            }
            res => {
                let (kind, msg) = classify(res); // Err(_) elapsed => Transient, 4xx => Fatal, ...
                if matches!(kind, FailKind::Transient) {
                    delay = (delay * 2).min(max);
                }
                let jittered = delay.mul_f64(0.8 + fastrand::f64() * 0.4);
                let _ = tx.send(ApiEvent::Failed { kind, msg, next_retry: Instant::now() + jittered }).await;
                delay = jittered;
            }
        }
        tokio::select! {
            _ = tokio::time::sleep(delay) => {}
            _ = retry_now.recv() => { delay = base; }
        }
    }
}
```

**State the UI renders from:**

```rust
pub struct Feed {
    pub data: Option<Payload>,        // keep this on error!
    pub updated_at: Option<Instant>,
    pub in_flight_since: Option<Instant>,
    pub consecutive_failures: u32,
    pub last_error: Option<(FailKind, String)>,
    pub next_retry: Option<Instant>,
}
```

**What the UI should show:**

| Situation | UI |
|---|---|
| Healthy | Status bar: `✓ Updated 3s ago` (dim) |
| Request in flight | Nothing at first. Show a spinner only after ~300 ms, so quick polls don't flicker |
| 1 timeout | **Nothing visible yet.** One blip isn't worth bothering the user about |
| ≥ 2–3 failures, or data older than ~3× the poll interval | Yellow `! Reconnecting… retry in 8s (r to retry now)`, and **dim the stale data** without hiding it |
| Long outage (e.g. > 1 min) | Red `✗ Offline. Last data 2m ago`, data still visible and dimmed |
| Fatal (401, bad URL) | Show this right away and prominently, since retrying won't help: `✗ Auth failed: check API token`. Stop backing off and wait for the user |
| Recovery | Go back to the normal display. Optionally flash `✓ Reconnected` for about 2 s |

**Practical details:**
- **Use hysteresis.** Base the warning on the failure count or the data's age, not on the last request alone. Otherwise the status bar flickers between states on a flaky network.
- **Show relative times** ("12s ago") and re-render on your tick, so the age keeps counting up even when no events arrive.
- **Keep error details out of the main view.** Log them with `tracing` to a file, or to an in-app log pane via `tui-logger`. Never use `println!`/`eprintln!`, because they corrupt the alternate screen.
- **Reset the backoff on success and on a manual retry.** Add jitter so many clients don't all retry at the same moment.
- If you use `tokio::time::interval` instead of sleep, set `MissedTickBehavior::Delay` so you don't get a burst of catch-up requests after a stall.

The two parts connect in the status bar: it uses `icons.ok`, `icons.warn`, `icons.err` and `icons.spinner`, so connection status looks right in all three icon modes.
