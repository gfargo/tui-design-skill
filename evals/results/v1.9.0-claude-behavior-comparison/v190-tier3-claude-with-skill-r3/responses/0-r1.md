**You can't do it directly.** A child process can't change its parent shell's working directory. Your Rust binary runs as a child of the shell, so `std::env::set_current_dir` only changes *your* process's cwd, and that change is lost when you exit. No syscall or IPC trick gets around this. Only the shell can `cd` itself.

**What people actually do:** your program writes the chosen directory to a file, and a small shell function reads that file and runs `cd` after your program exits. yazi (`--cwd-file`) and ranger (`--choosedir`) both work this way.

### 1. Rust side: add a `--cwd-file` flag

```rust
use std::{fs, os::unix::ffi::OsStrExt, path::PathBuf};

#[derive(clap::Parser)]
struct Args {
    /// Write the final directory to this file on exit (for shell cd-on-exit)
    #[arg(long)]
    cwd_file: Option<PathBuf>,
}

// ...after the event loop ends and you've restored the terminal
// (left the alternate screen, disabled raw mode):
if let (Some(path), Some(dir)) = (&args.cwd_file, app.chosen_dir.as_ref()) {
    fs::write(path, dir.as_os_str().as_bytes())?;
}
```

A few details:
- Write the raw bytes with no trailing newline. That way paths with odd characters survive and the shell can read the file back exactly.
- If the user cancels (Esc or `q` without choosing), **write nothing**. The file stays empty and the wrapper doesn't `cd`. This gives you "quit and cd" vs. "quit and stay" for free, and you can bind them to different keys.
- Return a non-zero exit code on cancel too, so scripts can tell the two cases apart.

### 2. Shell side: a wrapper function in the user's rc file

bash/zsh (this is yazi's documented function, with your binary name swapped in):

```bash
function p() {
    local tmp="$(mktemp -t "picker-cwd.XXXXXX")" cwd
    command picker "$@" --cwd-file="$tmp"
    IFS= read -r -d '' cwd < "$tmp"
    [ "$cwd" != "$PWD" ] && [ -d "$cwd" ] && builtin cd -- "$cwd"
    command rm -f -- "$tmp"
}
```

fish:

```fish
function p
    set tmp (mktemp -t "picker-cwd.XXXXXX")
    command picker $argv --cwd-file="$tmp"
    if read -z cwd < "$tmp"; and [ -n "$cwd" ]; and [ "$cwd" != "$PWD" ]
        builtin cd -- "$cwd"
    end
    command rm -f -- "$tmp"
end
```

The `cd` runs inside a function, which executes in the user's current shell, so the directory change sticks.

### 3. Ship the function from the binary itself

Instead of making users copy and paste the function, add a `picker init <bash|zsh|fish>` subcommand that prints it. Users then add one line to their rc file:

```bash
eval "$(picker init zsh)"
```

zoxide, starship, and mise all distribute their shell integration this way. Print that line in your README or on first run and tell people to add it themselves. Don't edit their rc files silently.

### Why not just print the path to stdout and run `cd "$(picker)"`?

That only works if the TUI doesn't draw to stdout. The `$(...)` captures stdout, so a normal ratatui app would hand all its escape codes to `cd`. fzf gets around this by drawing on `/dev/tty`. In Rust you could build the ratatui `CrosstermBackend` on `stderr` or an opened `/dev/tty` instead. This works, but it's more fragile: users have to wrap it in an alias anyway, and any stray stdout output corrupts the result. The cwd-file approach avoids all of that. I'd only add stdout path printing as an extra mode, like `--print`, for piping into other tools.
