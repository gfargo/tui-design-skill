**No, your program can't do it directly.** A child process can't change its parent shell's working directory. `chdir()` in your Rust binary only changes the binary's own cwd, and that disappears when it exits. Every tool that seems to do this, including yazi, ranger, broot, nnn and zoxide, has a small **shell function** run the `cd`. The pattern is:

1. Your binary accepts `--cwd-file <FILE>` and writes the chosen directory there on exit.
2. You document (or print) a shell wrapper that creates a temp file, runs your binary, reads the file, and runs `cd` in the user's own shell.

yazi's `--cwd-file` and ranger's `--choosedir` work exactly this way.

## The Rust side

Write the file **after** the terminal is restored, and only when the user actually picked a directory:

```rust
use std::path::PathBuf;
use clap::Parser;

#[derive(Parser)]
struct Args {
    /// Write the chosen directory to FILE on exit (used by the shell wrapper)
    #[arg(long, value_name = "FILE")]
    cwd_file: Option<PathBuf>,
}

enum Outcome {
    Chose(PathBuf),
    Cancelled,
}

fn main() -> anyhow::Result<()> {
    let args = Args::parse();

    // ratatui::run restores raw mode + alt screen before returning,
    // including on error, so nothing below can draw over the UI.
    let outcome = ratatui::run(|terminal| App::new()?.run(terminal))?;

    match outcome {
        Outcome::Chose(dir) => {
            if let Some(file) = &args.cwd_file {
                write_path(file, &dir.canonicalize()?)?;
            }
            Ok(())
        }
        Outcome::Cancelled => std::process::exit(1),
    }
}

#[cfg(unix)]
fn write_path(file: &std::path::Path, dir: &std::path::Path) -> std::io::Result<()> {
    use std::os::unix::ffi::OsStrExt;
    // Raw bytes, no trailing newline: non-UTF-8 paths survive intact.
    std::fs::write(file, dir.as_os_str().as_bytes())
}
```

Details that matter:
- **Write raw bytes, not `to_string_lossy()`.** Otherwise directory names that aren't valid UTF-8 get mangled.
- **Don't add a trailing newline.** The wrapper reads up to NUL or end of file, so a newline would become part of the path.
- **Treat "accept" and "cancel" as different exits.** For example, `Enter` or `q` writes the file and `Esc` or `Ctrl+C` doesn't. yazi does this with `q` (quit and cd) and `Q` (quit without writing). If no file is written, the wrapper does nothing and the user stays where they were.

## The shell side

bash/zsh (the same shape yazi documents):

```bash
p() {
    local tmp="$(mktemp -t "picker-cwd.XXXXXX")" cwd
    command picker "$@" --cwd-file="$tmp"
    IFS= read -r -d '' cwd < "$tmp"
    [ -n "$cwd" ] && [ "$cwd" != "$PWD" ] && [ -d "$cwd" ] && builtin cd -- "$cwd"
    command rm -f -- "$tmp"
}
```

fish:

```fish
function p
    set tmp (mktemp -t "picker-cwd.XXXXXX")
    command picker $argv --cwd-file="$tmp"
    if read -z cwd < "$tmp"; and test -n "$cwd"; and test "$cwd" != "$PWD"
        builtin cd -- "$cwd"
    end
    rm -f -- "$tmp"
end
```

`command` and `builtin` keep the function from calling itself or a user's `cd` alias.

## Make installing it easy

Add a `picker init <bash|zsh|fish>` subcommand that prints the right wrapper. Users then add one line to their rc file:

```sh
eval "$(picker init zsh)"      # bash/zsh
picker init fish | source      # fish
```

zoxide, starship and mise all work this way. Show users the line to add; **don't edit their rc file silently.**

## Why not just `cd "$(picker)"`?

That's the other common pattern: print the path to stdout and let command substitution capture it. It works well for small inline pickers like fzf. For a full-screen ratatui app it's fragile:
- `$(...)` captures stdout, so if ratatui draws to stdout (the default), nothing appears on screen. You'd have to render to stderr or `/dev/tty` instead.
- Any stray `println!` or log line ends up inside the path the shell tries to `cd` into.
- You still need a wrapper to handle cancel cleanly, so you've saved nothing.

The cwd-file keeps the result completely separate from the terminal, which is why yazi-style tools use it. Offering a `--print` / stdout mode on top is fine for scripting (`picker --print | xargs ...`), but use `--cwd-file` for cd-on-exit.
