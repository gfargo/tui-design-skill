**Recommendation:** have the first run prompt for the key inline, but only when a person is clearly at the keyboard. Check the key against the API, save it to the OS keychain, and then finish the command they originally ran. When no one is there to answer (piped input, CI), don't prompt. Fail straight away with an error that names the environment variable that fixes it.

## First run with no key

Look for the key in this order before doing anything else:

1. **`MYTOOL_API_KEY` env var.** If it's set, use it and never prompt. This is how scripts and CI skip the prompt, the same way `GH_TOKEN` works for gh.
2. **The stored key**: keychain first, then the fallback file (see the storage section).
3. **Interactive?** That means stdin *and* stdout are both TTYs and `CI` isn't set. If so, show the huh prompt.
4. **Otherwise, fail fast.** Print to stderr, exit non-zero and never hang waiting for input:

```
error: no API key configured
Set MYTOOL_API_KEY, or run `mytool auth login` in a terminal.
```

The interactive path at a 60-column floor needs no layout work, because it's a single inline field (no alternate screen):

```
No API key found for mytool.
┃ API key
┃ Create one at https://example.com/settings/keys
┃ > ••••••••••••••••••••
  enter submit • ctrl+c cancel
⠋ Checking key…
✓ Saved to macOS Keychain. Continuing…
```

Behavior details that matter:

- **Mask the input** with `EchoModePassword`. Prompt chrome goes to stderr, so stdout stays clean for the command's real output.
- **Check the key before saving it**, with a spinner while you call some cheap endpoint. If you don't, a pasted typo gets stored and every later command fails in a confusing way. On a 401, re-prompt with an explanation instead of exiting.
- **Ctrl+C means abort.** Store nothing and exit with code **130**, not 0. Otherwise `mytool init && mytool deploy` would carry on with no key.
- **Run the original command afterward.** Don't make people retype it.
- **Make the first-run prompt the same thing as `mytool auth login`**, so people can switch keys later on purpose. Add `mytool auth login --with-token` (reads the key from stdin) for headless machines, and `mytool auth status` to show where the key came from, with the key itself redacted.
- **Never add an `--api-key` flag.** Flag values leak through `ps`, shell history and logs.

```go
func resolveKey() (string, error) {
	if k := os.Getenv("MYTOOL_API_KEY"); k != "" {
		return k, nil
	}
	if k, err := loadStoredKey(); err == nil {
		return k, nil
	}
	if !interactive() {
		return "", errNoKey // caller prints the error above and exits 1
	}
	return promptAndStore()
}

func interactive() bool {
	return term.IsTerminal(int(os.Stdin.Fd())) &&
		term.IsTerminal(int(os.Stdout.Fd())) &&
		os.Getenv("CI") == ""
}

func promptAndStore() (string, error) {
	var key string
	err := huh.NewInput().
		Title("API key").
		Description("Create one at https://example.com/settings/keys").
		EchoMode(huh.EchoModePassword).
		Validate(func(s string) error {
			if strings.TrimSpace(s) == "" {
				return errors.New("required")
			}
			return nil
		}).
		Value(&key).
		Run()
	if errors.Is(err, huh.ErrUserAborted) {
		os.Exit(130)
	}
	// ...verify against the API, then storeKey(key)
}
```

Two huh v2 details:

- **Theme:** a standalone `Run()` always draws the light theme. Detect the background first with `lipgloss.HasDarkBackground(os.Stdin, os.Stdout)` and pin it with `huh.ThemeFunc(func(bool) *huh.Styles { return huh.ThemeCharm(isDark) })`.
- **Accessibility:** add a switch such as `MYTOOL_ACCESSIBLE` that sets `WithAccessible(true)`, which turns the prompt into plain line-by-line text for screen-reader users. Huh only does this by itself when `TERM=dumb`.

## Where to store the key

**Default: the OS keychain**, using `github.com/zalando/go-keyring` (the library gh uses). It covers macOS Keychain, Windows Credential Manager and libsecret on Linux:

```go
keyring.Set("mytool", "default", key)
```

**Fallback: a plaintext file, but only when the user opts in.** On Linux, headless boxes and containers often have no Secret Service running, so `keyring.Set` fails there. Don't silently fall back to plaintext. Tell the user, and offer `--insecure-storage` the way gh does. When you do write the file:

- **Path:** `$XDG_CONFIG_HOME/mytool/credentials`, or `~/.config/mytool/credentials` if that's unset. Work this out yourself: Go's `os.UserConfigDir()` ignores `XDG_CONFIG_HOME` and returns `~/Library/Application Support` on macOS.
- **Separate file:** keep it apart from `config.toml`, so people can share or commit their settings without leaking the key.
- **Permissions:** make the directory `0700`, and explicitly `chmod 0600` the file when you create it. Don't rely on umask; the AWS CLI shipped credential files as `0644` because of exactly this.
- **Atomic writes:** write to a temp file in the same directory, chmod it, then rename it into place.

**Precedence:** env var, then keychain, then file. `mytool auth status` should say which one is in use, for example `key: sk-…a91f (from macOS Keychain)`.

**Tests to write:**
- No TTY plus no key exits 1 with that stderr message.
- `MYTOOL_API_KEY` set means no prompt.
- Aborting the prompt exits 130 and stores nothing.
- The fallback file comes out `0600` even under `umask 022`.
