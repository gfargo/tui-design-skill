## What happens on first run

**Never just crash with "missing API key".** Treat it as a setup flow, but only run it interactively when someone is actually at the keyboard. Which path you take depends on the situation:

| Situation | Behavior |
|---|---|
| `MYTOOL_API_KEY` is set | Use it. No prompt, nothing saved. This is the CI/script path (like `GH_TOKEN`). |
| stdin **and** stdout are TTYs | Explain in one line why you need a key, prompt with huh, check the key against the API, save it, then **continue the command they ran**. |
| Not a TTY (piped, CI, cron) | Don't prompt and don't hang. Write the fix to stderr and exit non-zero. |
| User cancels the prompt (Ctrl+C/Esc) | Restore the terminal and **exit 130**, not 0, so `mytool init && mytool deploy` doesn't carry on. |

A few more rules:

- **Ship an explicit `mytool auth login` that runs the same flow.** The first-run prompt is just that command called automatically. Users also need `auth logout` and `auth status`. `status` should show where the key came from (env/keyring/file) and redact it.
- **Don't trigger the prompt from `--help`, `--version`, `completion`, or `auth status`.** Only commands that really call the API should need the key.
- **Never accept the key as a flag** (`--api-key=sk-...`). It leaks through `ps`, shell history and logs. Offer `--with-token` reading from stdin instead: `pass show mytool | mytool auth login --with-token`.
- **Check the key before saving it.** One cheap API call, with a spinner on stderr if it takes more than about 150ms. Saving a mistyped key means every later run fails confusingly.

The interactive version stays inline, with no alt screen:

```
$ mytool sync

Create one at https://example.com/settings/keys

┃ API key
┃ ••••••••••••••••••••••••
  enter submit • ctrl+c cancel

```

The non-interactive failure goes to stderr and is actionable:

```
$ mytool sync | tee out.txt
error: no API key configured
  set MYTOOL_API_KEY, or run `mytool auth login` in a terminal
$ echo $?
1
```

Exit 1 is fine here. If you've adopted `sysexits.h` across the whole tool, use `78` (EX_CONFIG), but don't mix the two schemes.

## Where to store the key

**Use the OS keychain via `zalando/go-keyring`**, which is what `gh` uses (macOS Keychain, libsecret on Linux, Windows Credential Manager). If that isn't available, **fall back to a 0600 file under XDG config**. Look the key up in this order:

1. `MYTOOL_API_KEY` env var
2. Keychain (`service="mytool"`, `user="default"` or the account name)
3. `$XDG_CONFIG_HOME/mytool/credentials` (default `~/.config/mytool/`, also on macOS). Don't use `~/.mytool`. Go's `os.UserConfigDir` ignores `XDG_CONFIG_HOME` and returns `~/Library/Application Support` on macOS, so resolve the path yourself.

Headless Linux boxes and containers often have no Secret Service daemon, so the keychain call will fail there. **Don't silently write plaintext.** Tell the user, and require opt-in, like gh's `--insecure-storage`. When you do write the file, **set 0600 yourself and don't rely on umask.** The AWS CLI shipped exactly this bug (CVE-2026-13769) and wrote credential files as 0644.

```go
import (
	"errors"
	"fmt"
	"os"
	"path/filepath"

	"charm.land/huh/v2"
	"github.com/zalando/go-keyring"
	"golang.org/x/term"
)

const service = "mytool"

var errNoKey = errors.New("no API key configured")

func resolveKey() (key, source string, err error) {
	if k := os.Getenv("MYTOOL_API_KEY"); k != "" {
		return k, "env", nil
	}
	if k, err := keyring.Get(service, "default"); err == nil {
		return k, "keyring", nil
	}
	if b, err := os.ReadFile(credPath()); err == nil {
		return string(b), "file", nil
	}
	return "", "", errNoKey
}

func interactive() bool {
	return term.IsTerminal(int(os.Stdin.Fd())) && term.IsTerminal(int(os.Stdout.Fd())) &&
		os.Getenv("CI") == ""
}

func promptKey() (string, error) {
	var key string
	err := huh.NewForm(huh.NewGroup(
		huh.NewInput().
			Title("API key").
			Description("Create one at https://example.com/settings/keys").
			EchoMode(huh.EchoModePassword).
			Value(&key).
			Validate(func(s string) error {
				if s == "" {
					return errors.New("required")
				}
				return nil
			}),
	)).
		WithAccessible(os.Getenv("MYTOOL_ACCESSIBLE") != "").
		WithOutput(os.Stderr). // prompt chrome on stderr; stdout stays for results
		Run()
	return key, err // huh.ErrUserAborted on Ctrl+C → caller exits 130
}

func saveKey(key string, allowInsecure bool) (string, error) {
	if err := keyring.Set(service, "default", key); err == nil {
		return "system keychain", nil
	} else if !allowInsecure {
		return "", fmt.Errorf("no system keychain available (%w); rerun with --insecure-storage to save to %s", err, credPath())
	}
	p := credPath()
	if err := os.MkdirAll(filepath.Dir(p), 0o700); err != nil {
		return "", err
	}
	if err := os.WriteFile(p, []byte(key), 0o600); err != nil {
		return "", err
	}
	return p, os.Chmod(p, 0o600) // WriteFile keeps old perms on an existing file
}

func credPath() string {
	dir := os.Getenv("XDG_CONFIG_HOME")
	if !filepath.IsAbs(dir) {
		home, _ := os.UserHomeDir()
		dir = filepath.Join(home, ".config")
	}
	return filepath.Join(dir, "mytool", "credentials")
}
```

In your command's `PersistentPreRunE`, for commands that need the key: call `resolveKey()`. If it returns `errNoKey` and `interactive()` is true, run `promptKey` → verify → `saveKey` and continue. If it's not interactive, print the two-line hint and exit 1. If the user aborts, exit 130.

Two huh details to know:
- A standalone `form.Run()` always uses the light theme. To theme it, detect the background first with `lipgloss.HasDarkBackground(os.Stdin, os.Stdout)` and pin it with `huh.ThemeFunc(...)`.
- Huh only switches to its line-by-line accessible mode on its own for `TERM=dumb`, which is why the code reads a `MYTOOL_ACCESSIBLE` env var (gh uses `GH_ACCESSIBLE_PROMPTER`).

**What to test:** unit-test `resolveKey` precedence by setting env vars and using `keyring.MockInit()`. Add black-box golden tests with no TTY that check stderr, empty stdout and exit 1. Check that the file fallback is 0600 even under `umask 022`.
