**Short answer:** the first time someone runs a command that needs the key, show the prompt inline (no full-screen UI), but only when a person is at a terminal. Save the key in the OS keychain using `zalando/go-keyring`, which is the library `gh` uses. If the keychain isn't available, the user can opt in to a file at `~/.config/mytool/credentials` with mode `0600`. An environment variable always wins over both, so CI never sees a prompt.

## What happens on first run

Look up the key in this order and stop at the first one found:

1. **`MYTOOL_API_KEY` env var.** This is how scripts and CI skip the prompt. Use an env var, not a flag. `GH_TOKEN` and `VERCEL_TOKEN` work this way, and a key passed as a flag leaks through `ps` and shell history.
2. **OS keychain.**
3. **Credentials file**, if the user opted into it.
4. **Nothing found.** Then:
   - **Both stdin and stdout are TTYs** (and `CI` isn't set): prompt for the key, check it with one cheap API call, save it, then **carry on with the command they ran**. Don't make them run it again.
   - **Not a TTY:** don't prompt and don't hang. Exit non-zero with a message that tells them exactly how to fix it:
     ```
     error: no API key configured
       set MYTOOL_API_KEY, or run: mytool auth login --with-token < key.txt
     ```
   - **They press Ctrl+C at the prompt:** exit 130, not 0. Otherwise `mytool init && mytool deploy` would keep going without a key.

Also add an `auth` command group: `mytool auth login` (prompt again, or read the key from stdin with `--with-token`), `auth status` (shows where the key came from, masked), and `auth logout`.

The prompt goes on stderr, inline, and fits in a 60-column tmux split:

```
$ mytool sync
No API key found. Get one at https://example.com/settings/keys

┃ API key
┃ > ••••••••••••••••••••
  enter submit • ctrl+c cancel

✓ Key saved to macOS Keychain
Syncing…
```

## The huh prompt

```go
import (
    "errors"
    "fmt"
    "os"

    "charm.land/huh/v2"
    "github.com/zalando/go-keyring"
)

const service = "mytool"

func promptForKey() (string, error) {
    var key string
    err := huh.NewForm(huh.NewGroup(
        huh.NewInput().
            Title("API key").
            Description("Get one at https://example.com/settings/keys").
            EchoMode(huh.EchoModePassword).
            Value(&key).
            Validate(func(s string) error {
                if len(s) == 0 {
                    return errors.New("required")
                }
                return nil
            }),
    )).
        WithOutput(os.Stderr). // keep stdout clean for results
        WithAccessible(os.Getenv("MYTOOL_ACCESSIBLE") != "").
        Run()
    if errors.Is(err, huh.ErrUserAborted) {
        os.Exit(130)
    }
    return key, err
}
```

- Run the API check after the form finishes, with a spinner, not inside `Validate`. A network call in the validator freezes the input while it waits. If the key is rejected, say so and ask again.
- `WithAccessible` turns the prompt into plain line-by-line input for screen readers. Huh only switches to it automatically when `TERM=dumb`, so you need your own switch for it.

## Where to store the key

```go
func saveKey(key string, insecure bool) error {
    if !insecure {
        if err := keyring.Set(service, "default", key); err == nil {
            return nil
        } else if !errors.Is(err, keyring.ErrUnsupportedPlatform) {
            return fmt.Errorf("keychain unavailable (%w); rerun with --insecure-storage", err)
        }
    }
    return writeCredentialsFile(key) // ~/.config/mytool/credentials
}
```

- **Keychain by default.** `go-keyring` covers macOS Keychain, Windows Credential Manager, and libsecret on Linux. Read it back with `keyring.Get` and treat `keyring.ErrNotFound` as "no key yet".
- **Linux headless hosts and containers** often have no Secret Service daemon running, so the keychain call fails. Don't silently fall back to a file. Fail with a clear message and let the user opt in, the way `gh auth login --insecure-storage` does.
- **The file fallback:**
  - Use the XDG path: `$XDG_CONFIG_HOME/mytool/credentials`, or `~/.config/mytool/` if that's unset. Don't use `~/.mytool`. Note that Go's `os.UserConfigDir` returns `~/Library/Application Support` on macOS and ignores `XDG_CONFIG_HOME`, so work out the path yourself.
  - Call `os.Chmod(path, 0600)` explicitly after writing. `os.WriteFile` doesn't change the permissions of a file that already exists, and the AWS CLI shipped a world-readable-credentials bug from making this assumption.
  - Keep the key out of your main `config.toml` so people can share their config without sharing their key.
