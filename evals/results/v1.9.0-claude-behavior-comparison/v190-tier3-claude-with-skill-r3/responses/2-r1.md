Both answers come from the skill's guidance on icons and on loading, error and stale states. Here are the recommendations first, then a Rust sketch.

## 1. Nerd Font icons: make them opt-in, because you can't detect the font

**Recommendation:** default to plain Unicode or ASCII, and let users turn Nerd Font glyphs on with a config key, a flag, or an env var. Don't try to detect the font.

No terminal can tell your app which font it's using. The protocol has no font query, and font fallback can swap fonts glyph by glyph anyway. Even `has-nerd-font`, which guesses from the configured font name, still needs a `NERD_FONT=1` override. Established tools take a few approaches:

- **lazygit:** `gui.nerdFontsVersion: '2' | '3' | ""`. Empty is the default and means no icons.
- **eza:** `--icons=always|automatic|never`. `automatic` only checks whether stdout is a TTY. It doesn't check the font.
- **yazi:** icons are on by default, and users without the font override the icon tables in `theme.toml`.
- **starship:** ships three presets: Nerd Font, Unicode, and plain text.

Two details matter:

- **Store the Nerd Fonts version, not just on/off.** Nerd Fonts v3 moved the Material Design icons from `F500–FD46` to `F0001+`. A glyph from one generation shows up as tofu (an empty box) on the other. That's why lazygit asks for `'2'` or `'3'`.
- **Put every icon behind one lookup table** with a Nerd → Unicode → ASCII ladder. Never write glyph literals in render code. The ASCII level is also your plain/accessible mode and works where Unicode support is uncertain.

```rust
#[derive(Clone, Copy, Default, clap::ValueEnum, serde::Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum IconSet { Nerd3, Nerd2, #[default] Unicode, Ascii }

pub struct Icons { pub folder: &'static str, pub ok: &'static str, pub err: &'static str, pub stale: &'static str }

impl IconSet {
    pub fn icons(self) -> Icons {
        match self {
            IconSet::Nerd3 | IconSet::Nerd2 => Icons { folder: "\u{f07b}", ok: "\u{f00c}", err: "\u{f00d}", stale: "\u{f017}" }, // FA range: same in v2 and v3
            IconSet::Unicode => Icons { folder: "▸", ok: "✓", err: "✗", stale: "◷" },
            IconSet::Ascii   => Icons { folder: ">", ok: "+", err: "x", stale: "~" },
        }
    }
}
// Resolution order: --icons flag > MYAPP_ICONS env > config file > default (Unicode).
```

(If you use Material Design glyphs, the `Nerd2` and `Nerd3` arms really do differ.)

Other rules to follow:

- An icon never carries meaning by itself. Pair it with a label or position, so it still makes sense if a glyph renders as tofu or color is stripped.
- Measure width with `Span::width()` or `cell_width()`, not `len()`. Some Nerd glyphs render 2 cells wide in some terminals. Leave a space after each icon so a wide one doesn't run into the text.
- Mention the setting in your README and `--help`, for example: "seeing boxes? set `icons = "unicode"`".

## 2. Poll timeouts: keep the last good data on screen, mark it stale, and retry with backoff

**Recommendation:** a failed poll should never clear or replace the screen. Keep the last good data visible, dimmed, with a `STALE` marker showing how old it is and a retry key. Retry automatically with exponential backoff.

Sketch at 80 columns:

```
 Jobs (prod)                                    ◷ STALE 42s · retry in 8s · r now
 ───────────────────────────────────────────────────────────────────────────────
 ▸ build-1234   running   3m        <- dimmed, last known good
   build-1233   passed    12m
 ───────────────────────────────────────────────────────────────────────────────
 r refresh ⋅ / filter ⋅ enter open ⋅ ? help
```

At 60 columns, cut the marker down from the left side and keep the age and the key:

```
 Jobs (prod)                         ◷ STALE 42s · r retry
```

How the status line should react:

| Situation | UI |
|---|---|
| Normal poll in progress | Nothing, or a small spinner that only appears after about 200ms. Never a modal. |
| One timeout | Stay quiet if the data is still fresh. A single missed poll every few seconds isn't worth alarming anyone. |
| Data older than about 2–3 poll intervals | Dim the rows and show `STALE <age>` with the retry countdown. The marker text is what carries the meaning, so it survives `NO_COLOR`. The dimming only reinforces it. |
| Many consecutive failures | `✗ Cannot reach api.example.com (timeout after 5s) · r retry · l log`. It stays until dismissed or the connection recovers. |
| Recovered | Remove the stale marker, show `✓ Reconnected` for 3–5 seconds, then go back to idle. |

Every failure also goes into a message log the user can reopen (with a key or `:messages`), with timestamps, so a flaky connection can be diagnosed later. If only one of several sources fails, show a partial state (`2 of 3 sources · ! eu unreachable · r retry`) instead of an error screen.

Implementation rules (Ratatui + Tokio):

- **Run the poll off the UI thread.** Use a spawned task with `tokio::time::timeout` and send the result back over the same channel your event loop already `select!`s on. Never `.await` the network call in the draw/update path.
- **Never let polls overlap.** Don't start a new poll while one is still in flight, or slow responses pile up and arrive out of order.
- **Back off, then reset.** Use 2s → 4s → 8s… up to about 60s, with some jitter. Pressing `r` retries now and resets the backoff. On success, go back to the normal interval.
- **Keep the selection stable when data refreshes.** Track the selected row by ID, not by index. If that row disappears, select its nearest neighbor. Never re-sort unless the user asked to.
- **Redraw only when something visible changed.** The age counter needs a 1s tick only while data is stale.
- **Never let a transient failure change saved config or layout.** btop has an open bug where a missing GPU permanently rewrites the user's layout.
- **Optional:** pause polling while the terminal is unfocused (focus reports, mode 1004) and refresh as soon as it regains focus.

```rust
enum Msg { Key(Event), Polled(Result<Vec<Job>, PollError>), Tick }

struct Feed { data: Vec<Job>, last_ok: Option<Instant>, failures: u32, in_flight: bool, next_at: Instant }

impl Feed {
    fn on_result(&mut self, r: Result<Vec<Job>, PollError>, log: &mut MessageLog) {
        self.in_flight = false;
        match r {
            Ok(jobs) => { self.data = jobs; self.last_ok = Some(Instant::now()); self.failures = 0; }
            Err(e)   => { self.failures += 1; log.push(Kind::Error, e.to_string()); } // keep self.data
        }
        let delay = if self.failures == 0 { BASE } else { (BASE * 2u32.pow(self.failures.min(5))).min(MAX) };
        self.next_at = Instant::now() + jitter(delay);
    }
    fn is_stale(&self) -> bool { self.last_ok.map_or(true, |t| t.elapsed() > BASE * 3) }
}

// Spawning: only if !in_flight && now >= next_at (or on 'r')
let tx = tx.clone();
tokio::spawn(async move {
    let r = tokio::time::timeout(Duration::from_secs(5), client.fetch_jobs()).await
        .map_err(|_| PollError::Timeout).and_then(|r| r);
    let _ = tx.send(Msg::Polled(r));
});
```

**Tests:** these are mostly state transitions, so unit-test `Feed` with fake results: one timeout, then N timeouts, then recovery, and check that a manual retry resets the backoff. Then take snapshots with `TestBackend` and `insta` of the stale and error frames at 80×24 and 60 columns. Run the stale frame once with each icon set, including ASCII, to catch width problems.
