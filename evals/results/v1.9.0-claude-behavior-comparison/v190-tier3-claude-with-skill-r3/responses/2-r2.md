## 1. Nerd Font icons: make them opt-in, because you can't detect them

**Recommendation:** use plain Unicode symbols by default. Turn Nerd Font glyphs on only when the user says so with a flag, config key or env var. Don't try to detect the font.

No terminal can tell your app whether a Nerd Font is installed and in use. There is no protocol for asking, and font fallback can swap fonts glyph by glyph anyway. Tools that guess from the configured font name still need a manual override. Established tools all use opt-in:

- **lazygit:** `gui.nerdFontsVersion: "2" | "3" | ""`. Empty (no icons) is the default.
- **eza:** `--icons=always|automatic|never`. `automatic` only checks that stdout is a TTY, not which font is in use.
- **starship:** ships three presets, `nerd-font-symbols`, `no-nerd-font` and `plain-text-symbols`.

**Ask for the Nerd Fonts version, not just on/off.** Nerd Fonts v3 moved the Material Design icons from `F500–FD46` to `F0001+`, so v2 and v3 glyphs differ. That's why lazygit asks for `'2'` or `'3'`.

Put all glyphs behind one table so no glyph literals end up in render code:

```rust
#[derive(Clone, Copy, Default, clap::ValueEnum, serde::Deserialize)]
pub enum IconSet { NerdV3, #[default] Unicode, Ascii }

pub struct Icons { pub ok: &'static str, pub err: &'static str, pub warn: &'static str,
                   pub stale: &'static str, pub folder: &'static str }

impl IconSet {
    pub const fn icons(self) -> Icons {
        match self {
            IconSet::NerdV3  => Icons { ok: "\u{f00c}", err: "\u{f00d}", warn: "\u{f071}",
                                        stale: "\u{f017}", folder: "\u{f07b}" },
            IconSet::Unicode => Icons { ok: "✓", err: "✗", warn: "!", stale: "◦", folder: "▸" },
            IconSet::Ascii   => Icons { ok: "+", err: "x", warn: "!", stale: "~", folder: ">" },
        }
    }
}
// Resolve once at startup: --icons flag > MYAPP_ICONS env > config file > default.
```

Rules that keep this working:
- **Never let an icon carry meaning alone.** Write `✗ timeout`, not just a red `✗`. Then a missing glyph (shown as tofu), `NO_COLOR` or the ASCII set loses nothing.
- **Check icon widths.** Nerd Font glyphs are Private Use Area codepoints, which Unicode marks as ambiguous width. Width libraries count them as 1 cell, but many fonts draw them wider, so they overlap the next character. Follow each icon with a space, keep them out of right-aligned table columns, and snapshot a frame with the Nerd set enabled.
- **Prefer narrow-width Unicode symbols** (`✓ ✗ ▸ ◦ ⋯`) in the default set. Characters like `● ★ ▶` are ambiguous width and misalign in CJK locales.
- Show the active icon set in `--help` or the settings screen so users can find the switch.

## 2. Polling timeouts: keep the last good data and mark how old it is

**Recommendation:** a timeout should almost never clear the screen or open a modal. Keep the last good data visible, dim it, and show how old it is with a `STALE` marker. Retry with backoff in the background and give the user a key to retry immediately.

```
Wide (100+ cols), healthy:
 Jobs (prod)                                                   updated 3s ago
 ▸ build-412   running   2m
   build-411   ok        9m

Wide, after repeated timeouts (rows dimmed, still selectable):
 Jobs (prod)               STALE 47s · retrying in 8s (attempt 3) · r retry now
   build-412   running   2m
   build-411   ok        9m

60 cols, same state, shortened label:
 Jobs (prod)            STALE 47s · retry 8s · r
```

At 60 columns the stale marker and its age stay, and the "retrying in" wording is the part that gets shortened. Even at the smallest size, users need to know the data is old.

How the UI should behave:

| Situation | UI |
|---|---|
| First load, nothing fetched yet | Draw the layout immediately with a delayed spinner and elapsed time (`loading… 4s · Esc cancel`). If it fails: `✗ Cannot reach api.example.com (timed out after 5s) · r retry · l log` |
| One timeout after a success | Show nothing beyond a small `retrying…` in the status line. A single blip shouldn't alarm anyone. |
| Data older than about 2× the poll interval | Header shows `STALE <age>`, rows are dimmed, the next retry countdown appears, and `r` retries now. |
| Recovered | Remove the marker. Optionally show `✓ reconnected` for 3–5 s. |
| Each failure | Write one entry to a message log the user can reopen. Don't show a toast per failed poll. |

The rules behind this:
- **Never block the render loop on the request.** Poll from a tokio task and send results back over a channel.
- **Never overlap requests.** Give each request a timeout shorter than the poll interval, and skip a tick if the previous request is still running.
- **Back off exponentially with jitter**, capped at around 30–60 s. Reset to the normal interval after a success.
- **Keep the selection on a stable ID, not a row index**, so a refresh doesn't move the cursor. If the selected row disappears, select its nearest neighbor.
- **Never write a failure into saved config.** btop has a bug of exactly this kind: a temporarily missing GPU rewrites the user's saved layout.
- Consider a **pause key** (htop uses `Z`) so users can hold the view still while reading.

A minimal state model:

```rust
enum Feed<T> {
    Loading { since: Instant },
    Ready   { data: T, at: Instant },
    Stale   { data: T, at: Instant, attempt: u32, next_retry: Instant, last_err: String },
    Failed  { attempt: u32, next_retry: Instant, last_err: String }, // no data yet
}

enum Msg { Fetched(Result<Vec<Job>, FetchError>), RetryNow, Tick /* ... */ }

// Poller task: one request in flight, timeout < interval, backoff on error.
tokio::spawn(async move {
    let mut delay = base;
    loop {
        let res = tokio::time::timeout(Duration::from_secs(5), client.jobs()).await;
        let ok = matches!(res, Ok(Ok(_)));
        let _ = tx.send(Msg::Fetched(res.map_err(FetchError::from).and_then(|r| r)));
        delay = if ok { base } else { (delay * 2).min(Duration::from_secs(60)) + jitter() };
        tokio::select! {
            _ = tokio::time::sleep(delay) => {}
            _ = retry_now.notified() => { delay = base; }   // `r` key
            _ = stop.cancelled() => break,
        }
    }
});
```

In `update`, handle `Fetched(Err)` like this: from `Ready` go to `Stale` (keep `data`), from `Loading` go to `Failed`, and in both cases append one entry to the message log. Only redraw on a tick when it changes something visible, such as the stale age or the retry countdown.

**Testing:** cover the state transitions with unit tests by feeding in synthetic `Fetched(Err)` messages. Snapshot the `Stale` and `Failed` frames with `TestBackend` at 80×24 and 60 columns, once with each icon set and once under `NO_COLOR`, to confirm the stale state still reads correctly without color.
