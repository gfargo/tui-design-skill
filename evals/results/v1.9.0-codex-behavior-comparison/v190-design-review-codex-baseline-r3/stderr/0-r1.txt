codex
The busyness comes mostly from **too many elements demanding equal attention**. Borders, status badges, arrows, labels, and log prefixes all have similar visual weight, so the actual pipeline state gets buried.

Here’s what’s contributing:

- **Nested borders consume space without adding structure.** The screen has an outer frame, pane frames, and inner frames. Those repeated edges create visual clutter and take columns away from content.
- **Every row looks selected or expandable.** A `▶` beside every job suggests either expansion or selection, but neither is clear. Reserve one marker for the active row; use disclosure arrows only for expandable groups.
- **Status is repeated and decorated.** `[PASS]` and `✅ PASSED ✅` communicate the same thing with several competing symbols. Use one consistent vocabulary: `Passed`, `Failed`, `Running`, `Queued`.
- **The hierarchy is flat.** App title, pane titles, metadata, and shortcuts all compete with failures and active work. Failures and selection should be prominent; successful jobs and field labels can be quieter.
- **Logs spend too much width on boilerplate.** Repeating `[INFO]`, a full date, and `::` on every line makes three simple messages feel dense.
- **The relationship between panes is ambiguous.** “Details” and “Logs” don’t explicitly say whether they follow the selected job. Making that connection visible reduces the effort of interpreting the screen.

I’d start with a layout like this, shown narrower for readability:

```text
CI Monitor                                      main · Updated 2s ago
2 passed · 1 failed · 1 running · 1 queued

PIPELINES                     TEST-UNIT
  build-api       Passed      Failed · 3m 42s
  build-web       Passed      main · a3f9c2b
› test-unit       Failed
  test-e2e        Running
  deploy-stg      Queued

────────────────────────────────────────────────────────────────────
LOGS · test-unit                                      Follow: on
14:22:01  Starting tests
14:22:03  Running unit tests
14:22:09  FAIL  TestCreateUser: expected 201, got 500

↑↓ Navigate   Tab Focus logs   r Refresh                       q Quit
```

The main changes I’d make:

1. **Remove the outer frame and inner frames.** Use whitespace between list and details, with one divider above logs. If a pane needs a border to show focus, give it a single border.
2. **Make selection unmistakable.** Use `›` plus a subtle row background. Don’t rely on color alone.
3. **Spend emphasis on actionable states.** Give failed jobs strong emphasis, running jobs a restrained spinner, and successful jobs plain text. Keep status text aligned in a consistent column.
4. **Reduce metadata to useful groups.** `Failed · 3m 42s` is easier to scan than a stack of equally weighted labels. Keep labels where values would otherwise be ambiguous.
5. **Simplify logs by default.** Show time and message; retain severity for warnings and errors. Offer full timestamps and other fields in an expanded mode.
6. **Make shortcuts match behavior.** If navigating immediately updates details and logs, remove “Enter Select.” If Enter opens something deeper, label that action explicitly.

For Bubble Tea + Lipgloss, implement the hierarchy with a small set of shared styles: **heading, muted text, selected row, and semantic status**. Use explicit column widths, modest horizontal padding, and `lipgloss.Width` when measuring styled content. Emoji can have inconsistent terminal widths; plain status words will make alignment more predictable.

**The highest-impact first pass is removing the nested boxes and the repeated arrows.** That alone should make the same information feel substantially calmer.
