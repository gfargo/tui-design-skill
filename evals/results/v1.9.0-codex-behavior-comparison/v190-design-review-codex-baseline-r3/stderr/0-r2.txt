codex
The main source of noise is **too many elements competing at the same visual weight**. Borders, labels, status markers, timestamps, and shortcuts all demand attention, so the actual pipeline state is harder to scan.

Here’s what I’d change, in order:

1. **Remove the nested boxes.** You have an outer frame, pane frames, and inner frames around the same content. Each adds padding and linework without adding information. Use whitespace between the pipeline list and details, with one divider above logs.

2. **Separate selection from status.** Every row has `▶`, which makes every pipeline look selected—or expandable. Use one cursor on the selected row, then a fixed-width status column. Give the selected row a subtle background.

3. **Simplify status language.** `[PASS]`, `[....]`, `[WAIT]`, and `✅ PASSED ✅` mix several visual conventions. Pick consistent text such as `passed`, `failed`, `running`, and `queued`. Use restrained color alongside text; reserve the strongest emphasis for failures.

4. **Make details earn their space.** `Job: build-api` repeats the selection, and `Status:` repeats its state. Put the job name and status in a heading, then show the metadata underneath. This also makes room for useful failure information.

5. **Reduce log prefixes.** Repeated `[INFO]`, full dates, and `::` delimiters overpower short messages. Show time only by default, dim it, and reserve prominent level labels for warnings and errors. Keep full timestamps available when needed.

6. **Quiet the application chrome.** The version can live in help. Use a dim footer with compact shortcuts, and make the focused pane apparent so “Navigate” and “Select” have a clear target.

A flatter layout could look like this—the shorter lines here illustrate hierarchy rather than exact column sizing:

```text
CI Monitor                                              main · a3f9c2b

Pipelines                  build-api · passed
› build-api     passed     Duration   3m 42s
  build-web     passed     Branch     main
  test-unit     failed     Commit     a3f9c2b
  test-e2e      running
  deploy-stg    queued

Logs · build-api
──────────────────────────────────────────────────────────────────────
14:22:01  Starting build-api
14:22:03  Compiling sources ...
14:22:09  Running vet + lint ...

↑↓ move   Tab pane   r refresh   ? help   q quit
```

In Lipgloss, I’d define a small shared palette: **normal text, muted metadata, selection, and semantic status colors**. Avoid making every pane title bold and colored. Also, emoji can render at inconsistent widths across terminals; plain text or tested single-width symbols will make alignment more predictable.

At 120 columns, you have enough room. The biggest improvement will come from removing repeated framing and emphasis, rather than squeezing the content tighter.
