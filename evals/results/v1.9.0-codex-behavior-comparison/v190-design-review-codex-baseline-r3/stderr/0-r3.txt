codex
The busyness comes mostly from **too much framing and too little hierarchy**. The content itself is modest, but almost everything gets the same visual weight.

- **Nested borders crowd the content.** The pipeline list and details each have two boxes, inside another application box. Those repeated edges consume space and draw attention away from the jobs. Remove the inner boxes and probably the outer application border.
- **The selection is unclear.** Every pipeline has `▶`, so the marker reads as decoration. Show it only on the selected row, paired with a subtle background or bold name. Keep keyboard focus distinct: accent the active pane’s heading.
- **Status is repeated.** `[PASS]`, `Status:`, and `✅ PASSED ✅` express the same thing with increasing emphasis. Use one consistent vocabulary: `Passed`, `Failed`, `Running`, `Queued`. Emoji also introduce terminal width and rendering variability.
- **Successful jobs compete with failures.** Keep passed and queued states subdued; reserve strong color for failures and a restrained accent for running jobs. Retain text labels so color isn’t required.
- **Log prefixes dominate the messages.** Repeated dates, `[INFO]`, and `::` make three short messages look dense. Show the date once when needed, dim timestamps, and emphasize warning/error levels.
- **The help bar competes with the workspace.** Use a dimmer, shorter line with contextual actions. If moving the selection updates details immediately, drop the separate Enter action.

At 120 columns, I’d use a roughly 30-column pipeline list, give the rest to details, and let logs take most of the vertical space. Something like this—the spacing is schematic:

```text
CI MONITOR                                      main · refreshed 2s ago

PIPELINES                     BUILD-API
› build-api       Passed      Passed · 3m 42s
  build-web       Passed      Branch  main     Commit  a3f9c2b
  test-unit       Failed
  test-e2e        Running
  deploy-stg      Queued

LOGS · build-api ───────────────────────────────────────────────────────
14:22:01  Starting build-api
14:22:03  Compiling sources…
14:22:09  Running vet + lint…

↑↓ navigate   tab pane   r refresh   q quit
```

In Lipgloss, start with **padding, aligned columns, and text emphasis**; add borders only where they clarify a boundary. One subtle separator above logs is likely enough. If panes scroll independently, a single border around the focused pane can make keyboard focus clearer.

The first change I’d try is simply removing the nested boxes and making `▶` exclusive to the selected job. That should make the layout feel substantially calmer before you touch colors or sizing.
