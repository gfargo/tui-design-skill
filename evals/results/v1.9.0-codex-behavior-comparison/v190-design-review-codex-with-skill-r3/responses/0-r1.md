**Keep the list-and-detail structure, but remove the nested boxes and give logs more space.** Your main loop is likely “spot a problem → select the job → read its output.” The current layout gives decoration and repeated metadata more emphasis than that workflow.

The biggest sources of noise, in priority order:

| Observation | Why it feels busy | Change |
|---|---|---|
| **Three border layers** before list/detail content: application → pane → inner box | Your eye crosses several boundaries to reach five short rows | Remove the outer frame and both inner boxes. Separate the two panes with whitespace or one divider |
| `▶` appears on **all five rows** | It identifies neither selection nor expansion; the selected job is unclear | Use reverse video for the selected row only. Keep disclosure markers only for actual expandable groups |
| `Status: ✅ PASSED ✅` has **three state signals**, plus a label | Repetition makes routine success demand attention | Use `PASS` once, optionally reinforced with color |
| The logs repeat `[INFO]`, a full date, and `::` delimiters | Boilerplate competes with the actual messages | Show time and message; retain severity as a compact column when useful. Put the date in the header and expose raw logs on demand |
| Every shortcut has brackets and a long description | The footer becomes another dense band | Use contextual hints: `↑/↓ move  Enter logs  Tab focus  r refresh  q quit  ? help` |
| The largest detail area contains five fields, while logs show three lines | Space favors static metadata over diagnosis | Compress metadata into two lines and let logs fill the remaining height |

The chrome cost is substantial: **eight of the upper section’s ten rows contain horizontal borders**, sometimes alongside useful content in the neighboring pane. Each log line also spends roughly **35 cells on its prefix before the message begins**. You have little data, but a high proportion of framing and boilerplate.

A wide layout could look like this. The `>` below stands in for a reverse-video selected row; the log content is your existing sample.

```text
CI MONITOR   main · a3f9c2b

JOBS                           SELECTED JOB
  build-api      PASS          build-api   PASS   3m 42s
> build-web      PASS          main · a3f9c2b
  test-unit      FAIL
  test-e2e       RUNNING        Logs preview the selected job
  deploy-stg     WAITING

────────────────────────────────────────────────────────────────────────────
LOGS · build-web
  No log output shown in this example


↑/↓ move   Enter logs   Tab focus   r refresh   q quit   ? help
```

For the actual screen, selecting `build-api` would show:

```text
LOGS · build-api
14:22:01  INFO  Starting build-api
14:22:03  INFO  Compiling sources ...
14:22:09  INFO  Running vet + lint ...
```

A few behavior choices make this calmer as well:

- **Selection updates the preview immediately.** Make Enter mean something concrete, such as “open full-screen logs,” rather than the ambiguous “Select.”
- **Make focus visible.** Bold the focused pane title; use reverse video on its selected row. Color can reinforce both, but neither should require color.
- **Keep successes quiet.** Use normal text for passing jobs and stronger emphasis for failure. Replace `[....]` with `RUNNING`; reserve animation for active work.
- **Keep live updates steady.** Preserve selection by job ID across refreshes. Scrolling upward in logs should pause following and show `PAUSED · 12 new`; `G` resumes at the end.

The layout should also shrink deliberately:

| Size | Behavior |
|---|---|
| **120+ columns** | List and compact details above; logs take the remaining height |
| **80×24** | Hide the permanent details pane. Keep a full-width job list and selected-job logs beneath it; Enter expands logs |
| **60 columns** | Show one pane at a time. Enter opens the selected job’s logs; Esc restores the list and its scroll position |
| **Below a proposed 60×12 minimum** | Show `Terminal too small — need 60×12; current W×H` |

For Bubble Tea/Lipgloss, derive those layouts from `tea.WindowSizeMsg`, measure terminal cells rather than `len()`, and truncate long job names without wrapping rows. Keep semantic styles for selection, failure, and secondary metadata, with readable monochrome output.

**My first edit would be just three changes: delete the outer and inner borders, remove every repeated `▶`, and shorten log prefixes.** Those directly reduce noise before you change any architecture.
