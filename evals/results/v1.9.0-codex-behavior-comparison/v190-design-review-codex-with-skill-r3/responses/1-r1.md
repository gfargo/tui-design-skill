**Replace the fixed thirds with a breakpoint layout that protects the current directory.** Keep Miller columns on wide screens; progressively turn the supporting panes into views users open on demand.

For your full-screen file manager, the main loop—move selection, enter directory, go up, filter, inspect, act on files—must remain usable in every layout.

A practical starting policy:

| Terminal width | Layout | Behavior |
|---|---|---|
| 120+ | Parent · current · preview | Current gets the most space; parent stays compact |
| 90–119 | Parent · current | Preview opens on demand |
| 60–89 | Current only | Path supplies context; parent navigation and preview remain keyboard accessible |
| 40–59 | Compact current only | Filenames first; remove optional metadata and shorten hints |
| Below 40 columns or 8 rows | Too-small state | Show required/current dimensions; keep resize and quit working |

These are **proposed thresholds**, not Ratatui requirements. Tune them against your filenames and preview content. In particular, don’t preserve a pane once its *usable interior* falls below its minimum.

The wide and floor layouts should look roughly like this; sketches are abbreviated:

```text
Wide: 120+ columns                  Floor target: 60 columns
parent | current       | preview    ~/work/project/src
-------+---------------+--------    > main.rs
 src/  | > main.rs     | fn main    lib.rs
 docs/ |   lib.rs      | ...        components/
       |   components/ |            
                                    h up  Enter open  p preview  ? help
```

At **80×24**, show the current directory full width: one path row, 22 content rows, one hint/status row. At **60 columns**, use that same navigation model. Don’t stack three panes vertically: a short tmux split also needs room for file rows.

**Make collapse a change in presentation, not a loss of functionality.**

- `Enter`/Right enters a directory or opens a file; Left/`h` goes to the parent.
- `p` opens a full-body preview at narrow widths; `Esc` returns to the list.
- Preserve selected file, filter, marked files, list offset, and preview scroll when resizing or returning.
- If a focused pane disappears, transfer focus to the current list. Never leave keyboard focus in a hidden pane.
- Show a compact hint such as `p preview`; keep the complete bindings in `?` help.

Use ordinary keys for these essential actions so they work through SSH and tmux without enhanced keyboard protocols.

In Ratatui, **choose the layout mode before splitting rectangles**. Constraints alone won’t decide which pane should disappear:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum LayoutMode {
    ThreePane,
    ParentCurrent,
    Single,
    Compact,
    TooSmall,
}

fn layout_mode(width: u16, height: u16) -> LayoutMode {
    if width < 40 || height < 8 {
        LayoutMode::TooSmall
    } else {
        match width {
            120.. => LayoutMode::ThreePane,
            90..=119 => LayoutMode::ParentCurrent,
            60..=89 => LayoutMode::Single,
            _ => LayoutMode::Compact,
        }
    }
}
```

Derive geometry from `frame.area()` on every draw. For the three-pane body, one reasonable allocation is a parent clamped to 18–28 cells, with the remaining width split roughly 55:45 between current and preview:

```rust
let parent_width = (body.width / 6).clamp(18, 28);

let [parent, rest] = Layout::horizontal([
    Constraint::Length(parent_width),
    Constraint::Fill(1),
]).areas(body);

let [current, preview] = Layout::horizontal([
    Constraint::Fill(55),
    Constraint::Fill(45),
]).areas(rest);
```

Subtract borders, padding, separators, and selection gutters when calculating usable width. Handle Crossterm’s `Event::Resize` by requesting a redraw; use the next frame’s actual area for layout. Keep filesystem reads and preview generation outside rendering, and avoid launching expensive previews while their view is hidden.

**Spend the remaining cells on filenames.** Drop modification times, owner, permissions, and size columns before shrinking the name field. Keep list rows single-line. Middle-truncate long filenames when preserving the extension helps, and collapse path prefixes before losing the basename. Provide a detail view for the complete value. Measure terminal cells rather than bytes, and truncate at grapheme boundaries so CJK and combining characters survive.

For chrome, target:

- **Border nesting: zero or one**, never an outer frame plus individually boxed panes.
- **Selection: one cue**, such as reverse video; remove repeated arrows/checkmarks that encode the same state.
- **Per-row markers:** reserve them for meaningful distinctions such as marked files.
- **Chrome budget at 80×24:** two full-width rows is about 8% of the screen before separators. Remove repeated pane paths, decorative blank rows, and boxed footers.

Also respond to height: below roughly 12 rows, remove optional headers and metadata, retain one compact hint row, and keep the selection visible. Below the declared minimum, render a clipped message such as `Need 40x8; have 35x6` instead of attempting the normal layout. Resize must recover automatically.

Verify with a pure layout-policy test and Ratatui `TestBackend` frames at **220×40, 120×24, 119×24, 90×24, 89×24, 80×24, 60×24, 60×10, 40×8, and below minimum**. Include long Unicode filenames, empty/loading/error previews, and a resize sequence from wide → narrow → wide. Assert that selection remains stable, hidden panes cannot retain focus, and preview/back still works.

The key acceptance criterion is simple: **at 60 columns, users can still browse, identify files, inspect them, and return without losing their place.**
