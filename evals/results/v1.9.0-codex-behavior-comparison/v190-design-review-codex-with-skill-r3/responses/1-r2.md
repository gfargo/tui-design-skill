**Make the current directory the pane that always survives. Collapse secondary panes before filenames become unreadable.** Keep Miller columns for wide terminals and switch to drill-down navigation on small ones.

For your file manager, I’d start with this policy. These are initial thresholds to validate against real filenames and previews:

| Available size | Default layout | Access to hidden content |
|---|---|---|
| ≥120 columns | Parent · current · preview | All visible |
| 80–119 columns | Parent · current; preview hidden | `p` opens full-width preview |
| 60–79 columns | Current directory only | Parent via navigation; `p` previews |
| 40–59 columns | Same single pane, reduced metadata | Full details on demand |
| <40 columns or <8 rows | “Terminal too small; need 40×8” | Keep resize and quit working |

**At 80×24:** give the parent about 20 columns and the current directory the remaining width. **At 60 columns:** give the current directory the entire body.

Conceptually, with widths compressed in the sketch:

```text
Wide: parent | current | preview       60 columns: current only

 Parent   | Current       | Preview    ~/work/project/src
----------+---------------+---------   ------------------------------
 project/ | > src/        | main.rs    > main.rs
 docs/    |   Cargo.toml  | fn main…     long_descriptive_filename.rs
          |   README.md   |              tests/
----------+---------------+---------   ------------------------------
 p preview  / filter  ? help           h parent  Enter open  p preview
```

Keep the main loop consistent across sizes: move selection, enter a directory, go to parent, filter, preview, mark files, and act on marked files. Resizing changes presentation, not those operations.

**Use pane budgets instead of equal thirds.** For example, require approximately 20 cells for parent, 40 for current, and 40 for preview, plus separators. Clamp the parent to 20–28 cells and share the remainder between current and preview, favoring current. If a pane cannot meet its usable minimum, hide it. Calculate those minima *after* borders and padding.

In Ratatui, make the layout choice explicit before splitting rectangles:

```rust
use ratatui::layout::Rect;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum LayoutMode {
    ThreePane,
    ParentCurrent,
    CurrentOnly,
    TooSmall,
}

fn layout_mode(area: Rect) -> LayoutMode {
    match (area.width, area.height) {
        (0..=39, _) | (_, 0..=7) => LayoutMode::TooSmall,
        (120.., _) => LayoutMode::ThreePane,
        (80..=119, _) => LayoutMode::ParentCurrent,
        _ => LayoutMode::CurrentOnly,
    }
}
```

Use `frame.area()` each draw, reserve header/footer rows, then apply `Layout` constraints within the body. `Length` is useful for the bounded parent pane; `Fill` for the remaining space. Minimum constraints alone cannot decide which pane should disappear—you need the mode selection above.

**Make hidden panes reachable and preserve context.**

- `p` opens a full-body preview in compact layouts; `Esc` returns to the same selected file and scroll position.
- `Enter` opens a directory or activates a file; `h`/Left goes to the parent. Keep these meanings stable across widths.
- If resizing hides the focused pane, move focus to current. Tab must skip hidden panes.
- Preserve directory, selection, filter, marks, and preview position through resize. Track selection by file identity/path rather than only row index.
- Handle Crossterm resize events by requesting a draw; derive geometry from the new frame. Don’t require restarting after a tmux split.

**Budget height and filename space as carefully as width.** At 80×24, a one-row path and one-row footer leave 22 body rows without borders. In short splits, remove decorative rows and extra metadata rather than stacking three panes vertically.

Keep filenames on one row. Drop owner, permissions, timestamps, and size before sacrificing the name. Shorten breadcrumb paths from the start or middle; offer full names in details. Measure terminal cells and truncate at grapheme boundaries, including the truncation marker’s width. For Ratatui 0.30.1+, `CellWidth` provides renderer-aligned cell measurement; byte length is unsuitable.

Run a concrete clutter audit while making this change:

- Target border nesting depth **0–1**; remove any outer frame around already bordered panes.
- Three separately bordered panes consume six horizontal cells before padding; shared separators consume two.
- Use one non-color selection cue, such as reverse video. Remove arrows or icons repeated on every row.
- At 60×24, one header plus one footer consumes **8.3%** of the screen; keep other chrome small. Keep `? help` visible and shorten secondary hints.

Loading, empty-directory, permission-error, and preview-unavailable messages should render inside whichever pane survives. Run directory reads and preview generation outside the UI thread; discard stale preview results when selection changes.

Finally, verify the policy with `TestBackend` frames at **220×40, 120×24, 119×24, 80×24, 79×24, 60×24, 40×8, and 39×8**, plus a short split such as 80×10. Assert that rectangles stay in bounds, selection remains visible, hidden panes cannot retain focus, and expanding restores the full layout. Include long names, CJK, combining characters, monochrome, and ASCII mode. One real SSH/tmux resize smoke test should cover shrinking, opening preview, returning, expanding, and quitting cleanly.
