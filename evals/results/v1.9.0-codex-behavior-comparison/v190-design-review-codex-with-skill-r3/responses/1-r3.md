Make the **current directory the pane that always survives**. As space shrinks, remove the preview, then the parent column; expose those views through navigation. Equal thirds give secondary information the same space as the filenames users need to act on.

Your app can stay a full-screen Miller-column file manager on wide terminals and become a drill-down file manager on narrow ones.

Use this starting policy; tune thresholds against real filenames and preview content:

| Terminal width | Default layout | Detail access |
|---|---|---|
| 120+ | Parent · **current** · preview | Live preview |
| 80–119 | Parent · **current** | `p` opens full-body preview |

The important details:

- **Give panes minimum useful widths.** Start with parent ≥20, current ≥40, preview ≥40 content cells, plus separators and padding. Collapse a pane when those budgets cannot fit. Relative constraints alone won’t make that decision.
- **Weight the current column highest.** On wide screens, clamp the parent to roughly 20–30 cells and share the remaining space between current and preview, favoring current. A `1:4:3` ratio is also a reasonable starting point.
- **Preserve the same navigation at every width.** Up/down selects; Enter opens or enters; Left goes to the parent; `/` filters; Space marks; `p` previews; `?` explains controls. Preview becomes a full-body view at narrow sizes, with Esc returning to the unchanged list.
- **Treat height independently.** At 80×24, one path row and one combined status/help row leave 22 list rows. Remove optional metadata and extra header rows in short tmux splits. Don’t replace horizontal crowding with a vertically stacked preview at 24 rows.

For Ratatui, choose the layout mode **before** splitting the body:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum LayoutMode {
    ThreePane,
    TwoPane,
    SinglePane,
    TooSmall,
}

fn layout_mode(width: u16, height: u16) -> LayoutMode {
    // Proposed product minimum: validate against actual controls/content.
    if width < 40 || height < 8 {
        LayoutMode::TooSmall
    } else if width >= 120 {
        LayoutMode::ThreePane
    } else if width >= 80 {
        LayoutMode::TwoPane
    } else {
        LayoutMode::SinglePane
    }
}
```

Use `frame.area()` on every draw. Reserve header/footer rows with `Layout::vertical`, then use `Layout::horizontal` only for the panes that survive. `Constraint::Length` works for a bounded parent column; `Fill` works for sharing the remaining space. Account for borders through `Block::inner()` if you keep them.

Handle Crossterm resize events by requesting a redraw; derive geometry from the new frame rather than storing startup dimensions. Keep directory, selection, marked files, filter, and preview scroll state separate from pane rectangles. If resize hides a focused secondary pane, move focus to current; Tab must never land on invisible panes. Keep the selected file visible as height changes.

**Truncation still needs deliberate handling.** Measure terminal cells, not Rust byte lengths, and truncate at grapheme boundaries. Keep filenames on one row; shorten path prefixes before the basename. Offer the complete filename/path in the detail view. Hide permissions, timestamps, and size columns before sacrificing the filename. Run preview reads asynchronously, and ignore stale results after selection changes.
