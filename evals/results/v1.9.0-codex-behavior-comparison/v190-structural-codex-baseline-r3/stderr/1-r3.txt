user
Review my Kubernetes resource browser layout. At 140 columns it has a double-line outer frame around the whole terminal, then three bordered panes: namespaces, resources, and YAML. Every resource row begins with a bullet and ends with a green `[READY]` plus a checkmark. The bottom two rows list 18 keyboard shortcuts. There is no responsive behavior yet because most of us use wide monitors. What would you change before release?

codex
I’d change four things before release, in this order:

1. **Make readiness meaningful.** A green `[READY] ✓` on every row adds noise and may misrepresent resources that don’t have a readiness condition. Use kind-appropriate status: deployment availability, pod readiness, job completion. Make failures, pending states, and unknown status easy to spot without relying on color. Remove the bullets unless they convey selection or another state.

2. **Add a narrow-terminal fallback.** Wide monitors still get split windows and larger fonts. Keep three panes when they fit; collapse namespaces into a picker as space shrinks, then show resources and YAML as switchable views. Preserve selection and focus when resizing. YAML should scroll horizontally or offer wrapping, without forcing the resource list offscreen.

3. **Reduce the border weight.** Drop the double-line outer frame—it consumes space without separating useful content. Use lightweight pane dividers and a clear focus indicator. Give the resource list and YAML most of the width; namespaces rarely need an equal share.

4. **Replace the shortcut wall with contextual help.** Show roughly five frequent actions for the focused pane, plus `? Help`. Put the full shortcut reference in a searchable overlay. Keep navigation and exit keys discoverable.

I’d also make **cluster/context, namespace scope, active filters, and connection state** persistently visible. Users need to know which environment they’re inspecting, especially before any action.

Before shipping, test at 80, 100, and 140 columns, with short terminal heights, long names, empty results, API errors, and color disabled. The release bar should be: users can identify focus, understand resource health, and navigate at every supported size.
