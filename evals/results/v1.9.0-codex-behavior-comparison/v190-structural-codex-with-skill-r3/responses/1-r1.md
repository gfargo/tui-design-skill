I’d make responsive behavior a release requirement, then remove the repeated decoration. The namespace → resource → YAML flow is a good fit for a full-screen browser; the main resource list should get priority.

1. **Make the three panes collapse predictably.** Wide monitors still get split for SSH, tmux, and incident work.

   | Size | Recommended behavior |
   |---|---|
   | 120+ columns | Three panes; resources widest, namespaces capped, YAML preview uses the remainder. |
   | 80×24 | Resources fill the view. Namespace becomes a picker; Enter opens YAML, Esc returns. |
   | 60 columns | Same single-pane flow; keep name and meaningful status, hide secondary columns. |
   | Below minimum | Show a readable “terminal too small” message with required and current dimensions; keep quit working. |

   Start with a proposed minimum of **60×12**, then validate that the essential controls fit. Resize should preserve selection, filter, and scroll position.

2. **Remove the outer double-line frame.** Your border nesting depth is **2**: outer frame, then pane border. The outer frame adds no boundary the terminal doesn’t already provide. Use shared thin separators between panes, with a bold focused-pane title and reverse video for the selected row.

3. **Cut redundant row signals.** Readiness currently has **three signals**: `[READY]`, green, and a checkmark. Keep a plain `Ready` value with optional green; remove the brackets and checkmark. The bullet appears on **100% of rows**, so remove it too. Reserve markers for selection or an actual exception.

   Make status truthful for the resource kind: pod readiness counts, deployment available/desired counts, and an explicit unknown or unavailable state where readiness doesn’t apply. A generic green READY can hide useful distinctions.

4. **Replace the 18-shortcut footer with contextual help.** Keep one row showing roughly five common actions plus `? Help`, for example:

   `Tab pane  / filter  Enter YAML  n namespace  ? help  q quit`

   In YAML, change the hints to search, scroll, and back. Put all 18 bindings in searchable or grouped help. Outside text input, keep conventional quit behavior; Esc dismisses or backs out before quitting.

There are measurable space savings: removing the outer frame reclaims **280 cells across its top and bottom at 140 columns**, plus its side cells; shortening the footer returns another **140-cell row**. Exact total chrome percentage needs a rendered frame and terminal height.

Before release, also verify loading, empty, permission-denied, disconnected, and stale-data views—stale YAML must not appear current. Keep live selection attached to the resource UID so refreshes don’t move the user onto another object. Check the resulting frames at 140 columns, 80×24, 60 columns, and the minimum, including monochrome, ASCII fallback, long names, and terminal restoration on exit.
