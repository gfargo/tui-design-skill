I’d make responsive behavior a release requirement, then remove redundant chrome. The namespace → resource → YAML flow is a good fit for a full-screen browser with a preview; the resource list should get the most space.

1. **Make the resource list win as width shrinks.** Wide monitors still get split into tmux panes and SSH sessions.

   | Size | Proposed behavior |
   |---|---|
   | 120+ columns | Three panes, provided each meets its minimum width |
   | 80×24 | Full-width resources; namespace picker and YAML open on demand |
   | 60 columns | Single-pane drill-down; Enter opens YAML, Esc returns |
   | Below a tested minimum, provisionally 60×12 | Show “Requires 60×12; current size W×H,” with quit still available |

   Preserve selection, filters, and scroll position through resizing. Drop low-priority columns before truncating names; keep full values accessible in details.

2. **Remove the double-line outer frame.** Your border nesting depth is **2**: terminal frame, then pane border. The outer frame adds no separation. Keep lightweight pane dividers and use a bold, marked title to identify focus.

3. **Remove every-row bullets and simplify readiness.** A bullet on every row distinguishes nothing. Readiness currently has **three signals**: `[READY]`, green, and a checkmark. Replace these with a compact text column, optionally reinforced by color. For pods, `READY 1/1` and `STATUS Running` convey different facts; don’t label every resource kind “ready” unless that condition exists. Use reverse video for the selected row.

   The clutter cost is measurable: at 140×24, the outer frame alone occupies **324 cells, about 9.6%** of the screen. Two shortcut rows consume another **8.3%**. Pane borders and repeated row decorations add more.

4. **Replace 18 persistent shortcuts with contextual help.** Keep roughly five to eight common actions visible: move, filter, change namespace/resource type, open YAML, switch focus, back, help, quit. Put the complete keymap behind a visible `? help` entry. Tab/Shift+Tab should follow pane order; printable shortcuts must yield while typing into filters.

Before shipping, also verify live-data behavior: retain selection by resource UID, distinguish loading from empty/filter-no-match/RBAC-denied states, and mark disconnected data as stale rather than leaving reassuring green statuses. Test resize in both directions, monochrome/`NO_COLOR`, ASCII fallback, long names, keyboard reachability, and terminal restoration on exit. Provide a linear plain-output mode for accessibility and scripting.

These are recommendations from your description; lifecycle and rendering correctness still need verification in the running app.
