No. This is a **summon–choose–exit picker**, best rendered inline beneath the shell command. Bubble Tea is suitable, but a full-screen alternate buffer adds little value here.

The important distinction is that **stdout carries the branch; the terminal carries the interaction and permanent receipt**.

| Channel | Contract |
|---|---|
| stdout | On success, exactly the complete branch name plus `\n`. No ANSI, prompt, label, or debug text. |
| stderr / controlling terminal | Search UI, instructions, errors, and a final `Selected: feature/login` receipt. |
| Exit status | `0` selected; `1` no candidates/no match in noninteractive mode; `2` usage or operational error; `130` cancelled. Failures emit no stdout. |

Command substitution captures stdout, so printing the chosen branch there **does not make it visible in scrollback**. After restoring the terminal, explicitly print the receipt to the UI stream. Leave the invoking shell line intact; clear only the picker’s temporary rows.

Prefer guarded, quoted usage:

```sh
branch=$(branchpick) && git checkout "$branch"
```

The original `git checkout $(branchpick)` still runs `git checkout` if the picker cancels; the picker’s failure status does not prevent that outer command.

Use a bounded inline list, around 6–10 rows, with no mouse capture. For example:

```text
Wide terminal                         60-column split
$ git checkout "$(branchpick)"        $ git checkout "$(branchpick)"
Branch > log                         Branch > log
> feature/login          2h ago       > feature/login
  fix/logout             yesterday     fix/logout
2 matches                            2 matches
↑/↓ move · Enter choose · Esc cancel  Up/Down move; Enter pick; Esc cancel
```

At 80×24, keep the same single-column layout. At 60 columns, hide optional recency metadata first and truncate names by terminal cell width; preserve the complete underlying value. Reduce visible rows as height shrinks. Declare a hard minimum, for example 30×6, below which selection pauses with a truthful resize message and cancellation remains available.

The clutter audit is simple: **zero borders, one selection marker, no marker on every row**, and two fixed chrome rows for query and help/count. Remove banners, repeated “branch” labels, and a preview pane.

The most important implementation choices are:

- **Define “recent.”** For recently checked-out branches, derive order from checkout events in HEAD’s reflog, deduplicate, and intersect with existing local refs. Commit date measures recent development, which is a different promise. Document reflog/worktree limits and use deterministic fallback ordering.
- **Separate display from identity.** Store full ref/name, recency rank, and display text separately. Fuzzy ranking should be deterministic, with recency breaking ties. Never output truncated or highlighted text.
- **Keep typing modeless.** Printable characters—including `q`, `j`, and `k`—edit the query. Arrows navigate; Enter selects; Esc and Ctrl+C cancel. Disable conflicting list defaults.
- **Own the correct terminal.** On Unix, open `/dev/tty` for input and UI output so captured stdout remains usable. With Bubble Tea v2, use `tea.WithInput` and `tea.WithOutput`, leave `View.AltScreen` false, and let `Program.Run()` manage restoration. Emit the receipt and result only after it returns. Bind Ctrl+Z to `tea.Suspend` where supported.
- **Keep I/O outside rendering/update.** Run Git through argument-based `exec.CommandContext`, use machine-oriented output, and return loading/results/errors through commands and messages. Render only the visible list window.
- **Provide a linear path.** A `--no-tui` numbered prompt supports accessibility; a deterministic `--filter QUERY` supports automation. Without a controlling terminal, fail clearly unless an explicit noninteractive mode was requested. Honor `NO_COLOR`.

Test primarily below the terminal layer: reflog parsing, stale refs, deduplication, fuzzy ordering, selection transitions, and exact full-name output. Add pinned frame tests at wide, 80×24, 60-column, and minimum sizes, including Unicode and monochrome.

Then test the built binary’s **stdout, stderr, and exact status independently**, including no TTY, Git failure, empty results, and cancellation. Finally, use one or two PTY flows with stdout captured separately to verify real command substitution, the permanent receipt, absence of alternate-screen entry, and restoration after selection, interrupt, resize, and suspend/resume.
