No. This is a **summon–choose–exit picker**: use a bounded inline UI in the normal screen buffer. Bubble Tea is suitable, but full-screen mode adds little here and hides the shell context while picking.

**Output contract**

- **stdout:** exactly the selected local branch name plus `\n`, without labels, quoting, or ANSI escapes.
- **UI:** read keys from `/dev/tty` and render there; stderr is also suitable when attached to a terminal. Command substitution captures stdout, so never render the picker there.
- **Completion:** erase the transient list, restore the terminal, then leave `branchpick: selected feature/login` on the UI stream. That receipt and the original shell command remain in scrollback.
- **Exit codes:** `0` selected; `1` no candidates/matches; `130` cancelled; `2` operational error. All unsuccessful paths produce empty stdout; errors go to stderr.

Prefer guarded shell usage:

```sh
branch=$(branchpick) && git checkout "$branch"
```

With `git checkout $(branchpick)`, the shell still invokes Git if selection fails. The guard prevents that; quoting also prevents shell expansion of branch names.

**Terminal mode and layout**

Use temporary raw input, no alternate screen, no mouse capture, and a height cap around eight lines. Preserve everything above the picker and replace only its own region.

```text
80 columns                           60-column split
branch> log                          branch> log
> feature/login           2h         > feature/login
  fix/logout              1d           fix/logout
2/18  Up/Down move                   2/18  Up/Down move
Enter choose | Esc cancel            Enter choose | Esc cancel
```

At 80×24, show up to five candidates; at 60 columns, drop optional age metadata before truncating names. Truncate by terminal cells while retaining the complete selected value. Declare a minimum such as 32×5; below it show “terminal too small,” allowing cancellation or recovery after resize.

Clutter budget: zero borders, one selection marker on the active row, none on other rows, and two lines for query/help/count. No title banner, preview pane, or repeated “branch” labels.

**Implementation choices**

- Use Bubble Tea v2’s `Model → Update → View`, keeping `View.AltScreen` false. Explicitly configure terminal input/output with `tea.WithInput` and `tea.WithOutput`.
- Define “recent” precisely: preferably recently checked-out local branches from HEAD’s reflog, deduplicated newest first and intersected with existing `refs/heads`. Commit timestamp is a different meaning; label it if used.
- Run Git through `exec.CommandContext` with argument slices and machine-readable formats, never shell interpolation. Perform Git I/O in `tea.Cmd`, outside `Update` and `View`.
- Start with the query focused. Printable characters—including `q`, `j`, and `k`—always enter the query. Support arrows, Backspace, Enter, Esc, Ctrl+C, and framework-supported Ctrl+Z suspension.
- Use fuzzy relevance with deterministic recency tie-breaking; virtualize visible rows. Show distinct loading, no-branches, no-matches, and error states; disable acceptance without a candidate.
- Let `Program.Run()` manage restoration, including recovered panics. Write the receipt and stdout result after it returns; never call `os.Exit` inside `Update`.
- Honor `NO_COLOR`, retain an ASCII selection marker, and offer `--no-tui` with a linear numbered prompt. Without a controlling terminal, fail promptly rather than hang; provide `--list` for automation.

**Tests that matter most**

1. Unit-test recency extraction, deleted-branch filtering, deduplication, fuzzy ranking, and selection/cancellation transitions using synthetic `tea.KeyPressMsg` events.
2. Golden-test frames at 80×24, 60 columns, and the minimum, with pinned color profiles; include Unicode widths, long names, empty results, and resize.
3. Black-box test exact stdout, stderr, and exit codes, including no terminal and `NO_COLOR`.
4. Add a small PTY integration suite around real command substitution: verify keyboard input still works, stdout contains only the branch, the invoking command and receipt survive, no alternate screen is entered, and terminal settings/cursor are restored after selection, interruption, and failure.
