**Use a bounded inline picker.** Bubble Tea is a good fit, but a full-screen app adds little to “filter → choose → exit.” Staying in the normal screen buffer preserves the invoking command and lets you leave the chosen branch in scrollback.

**Output contract**

| Channel | Content |
|---|---|
| stdout | Exactly the selected branch name plus `\n`; no ANSI, labels, or quotes |
| stderr / controlling terminal | Picker, hints, diagnostics, and a permanent `Selected: feature/auth` line |
| Exit status | `0` selected; `1` cancelled/no selection; `2` operational error; `130` interrupted |

Every unsuccessful outcome produces **empty stdout**. The visible selection line matters because command substitution captures stdout.

Prefer a guarded invocation:

```sh
branch=$(branchpick) && git checkout "$branch"
```

`git checkout $(branchpick)` still runs `git checkout` if selection fails: the substitution’s status does not gate the outer command. Quoting also prevents shell expansion of branch names.

**Terminal behavior**

Use temporary raw input in the **normal screen buffer**, with mouse capture off. Open `/dev/tty` for keyboard input; render to terminal-connected stderr, falling back to the controlling terminal when stderr is redirected. A redirected stdout is expected in this workflow and must not disable interaction.

Keep the UI to roughly 6–10 lines. On acceptance, replace the transient picker with the permanent selection line, restore the terminal, then emit stdout.

```text
Wide terminal                          60-column split
branch> auth                 2/18      branch> auth          2/18
> feature/auth               2h       > feature/auth
  fix/auth-timeout           1d         fix/auth-timeout
Up/Down move | Enter select            Up/Down move | Enter select
Esc cancel | Ctrl+C interrupt         Esc cancel | Ctrl+C interrupt
```

At 80×24, retain the single list and optional age column. At 60 columns, hide ages and truncate names by terminal-cell width; retain the complete underlying value. Below a declared minimum such as 40×5, show “Terminal too small; resize or Esc cancel” and disable acceptance.

Clutter audit: zero borders, one selection marker, no per-row icons, and two compact control lines. In an eight-line picker, six lines remain available for query and results.

**Most important implementation choices**

- Use Bubble Tea v2’s MVU architecture: Git reads in `tea.Cmd`, state changes in `Update`, rendering in `View`. Set `AltScreen` to false; explicitly configure `tea.WithInput` and `tea.WithOutput`.
- Define “recent”: preferably **recently checked-out local branches**, derived from HEAD reflog history, deduplicated and intersected with existing `refs/heads`. Commit timestamps measure recent commits, not recent use. Document how never-visited branches are ordered.
- Invoke Git through `exec.CommandContext` with argument slices. Use machine-readable ref formats; never parse decorated `git branch` output or run through a shell.
- Keep empty-query ordering by recency. With a query, rank fuzzy matches and use recency as a deterministic tie-breaker. Render only visible rows; keep filtering responsive.
- Start with the query focused. Printable `q`, `j`, and `k` enter text; arrows navigate, Backspace edits, Enter accepts, Esc cancels, Ctrl+C interrupts. On supported systems bind Ctrl+Z to `tea.Suspend`.
- Let `Program.Run()` manage cleanup, including recovered panics. Never call `os.Exit` from `Update`; publish the selected result only after successful shutdown.
- Distinguish loading, no branches, no matches, and Git errors. Empty results cannot be accepted. Honor `NO_COLOR`; offer `--no-tui` with numbered, append-only prompts and an explicit unattended selection option. Without a controlling terminal, fail clearly instead of hanging.

**Most important tests**

1. Unit-test recency extraction, deleted-branch filtering, deduplication, deterministic fuzzy ranking, selection bounds, and acceptance/cancellation using synthetic `tea.KeyPressMsg` events.
2. Golden-test stdout, stderr, and status separately. Assert exact selected bytes and empty stdout on every failure, including when stdout is piped.
3. Snapshot frames at wide, 80×24, 60-column, and minimum sizes, including Unicode names, monochrome, loading, empty, and error states.
4. Use a small PTY suite for acceptance and cancellation/interruption, plus lifecycle checks for resize, supported suspend/resume, error and panic restoration. Verify that the invoking command and final selection remain visible, no alternate-screen sequence occurs, and terminal settings and cursor state are restored.
