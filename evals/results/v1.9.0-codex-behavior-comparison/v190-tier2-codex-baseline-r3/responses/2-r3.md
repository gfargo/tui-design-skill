Treat this as a layout bug first: **inspect the rectangles used for the bad frame, then test the rendered buffer at those dimensions.**

### (a) Debug without touching the terminal

Send diagnostics to a file using `tracing` and `tracing-subscriber`. Avoid stdout **and stderr** while the TUI owns the terminal.

```rust
let log = std::fs::File::create("tui-debug.log")?;

tracing_subscriber::fmt()
    .with_writer(log)
    .with_ansi(false)
    .with_max_level(tracing::Level::DEBUG)
    .init();
```

Inside the draw callback, log the frame size and computed rectangles:

```rust
terminal.draw(|frame| {
    let area = frame.area();
    let [body, footer] = Layout::vertical([
        Constraint::Min(0),
        Constraint::Length(1),
    ])
    .areas(area);

    tracing::debug!(?area, ?body, ?footer, "layout");

    frame.render_widget(
        Block::bordered().title("Panel"),
        body,
    );
    frame.render_widget(Paragraph::new("Footer"), footer);
})?;
```

Watch the log from a **separate terminal** with `tail -f tui-debug.log`.

The likely places to inspect:

- **Mixed size sources:** calculate each frame’s layout from `frame.area()`. Don’t combine it with a cached size or dimensions from a resize event.
- **Inclusive arithmetic:** `Rect::bottom()` is exclusive. The last occupied row is `bottom() - 1`, when height is nonzero. Adjacent rectangles should satisfy `body.bottom() <= footer.y`.
- **Border accounting:** a bordered block’s rectangle already includes its borders. Render its contents in `block.inner(rect)`.
- **Resize ordering:** with Tokio, keep terminal drawing and layout updates under one owner. Log resize events alongside frame rectangles to expose stale state.
- **Tiny dimensions:** shrink through heights `0`, `1`, `2`, and `3`; manual subtraction is especially fragile there.

Prefer one parent layout that reserves the footer and then subdivides the body. Avoid independently computing a panel’s height and the footer’s position.

### (b) Test the actual rendered buffer

Extract your real rendering code into a function shared by the application and tests:

```rust
fn render_ui(frame: &mut Frame<'_>, app: &App) {
    // Real layout and widgets.
}
```

Use Ratatui’s `TestBackend`: it renders in memory without opening a terminal.

```rust
use ratatui::{backend::TestBackend, Terminal};

#[test]
fn panel_border_stays_above_footer_after_resizes() {
    let mut terminal =
        Terminal::new(TestBackend::new(80, 24)).unwrap();
    let app = App::default();

    // Replace/add sizes from the failing log, including the exact sequence.
    for (width, height) in [
        (80, 24),
        (80, 3),
        (41, 12),
        (120, 40),
        (80, 24),
    ] {
        terminal.backend_mut().resize(width, height);
        terminal.autoresize().unwrap();
        terminal.draw(|frame| render_ui(frame, &app)).unwrap();

        let buffer = terminal.backend().buffer();

        // Adapt these to your actual footer text and border style.
        assert_eq!(
            buffer[(0, height - 1)].symbol(),
            "F",
            "footer overwritten at {width}x{height}"
        );
        assert_eq!(
            buffer[(0, height - 2)].symbol(),
            "└",
            "panel bottom misplaced at {width}x{height}"
        );
    }
}
```

Here the example assumes the footer starts with `"F"` and the panel fills the body with a plain border. Assert the **whole footer row and panel bottom row**, or compare against an expected `Buffer`, for stronger coverage.

Add two complementary checks:

- A layout test across many small widths/heights asserting that panel and footer rectangles stay within the frame and do not overlap.
- A buffer regression test reproducing the captured resize sequence, using the same `Terminal` throughout. This exercises state retained between draws.

`TestBackend` catches application layout and rendering mistakes. If the buffer is correct but the physical terminal is wrong, investigate terminal resize handling, concurrent terminal writes, and Crossterm integration separately; that requires a real-terminal or PTY reproduction.
