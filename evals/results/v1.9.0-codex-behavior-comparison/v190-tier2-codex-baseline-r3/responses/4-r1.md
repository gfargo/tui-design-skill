For a small “pick a branch” helper, I’d default to a **compact, inline picker** beneath the command prompt. Show perhaps 8–12 rows, filter as the user types, and scroll the list within that space. A full-screen interface makes more sense when users need multiple panels or extended browsing.

After selection, remove the transient picker and leave a simple receipt in the normal terminal buffer:

```text
$ pick-branch
Selected: feature/login-refresh
$
```

On cancellation, remove the picker without printing a selected branch. Avoid clearing the terminal or erasing anything above the picker.

The key distinction is the **alternate screen buffer**. Full-screen TUIs commonly use it; its contents disappear when the app exits. That’s useful for cleanup, but anything you want preserved must be printed **after returning to the normal buffer**. You can therefore offer a full-screen mode and still preserve the command and selection.

For the Go implementation, keep these concerns separate:

- Render interactive UI to the terminal, usually via stderr or `/dev/tty`.
- Restore terminal settings and clean up the UI before printing the final result.
- Write only the branch name to stdout so scripts can consume it.
- If used as `git switch "$(pick-branch)"`, print the human-readable receipt to stderr too: captured stdout won’t appear in scrollback.

That gives you a lightweight default, clean scripting behavior, and a visible record of what the user picked.
