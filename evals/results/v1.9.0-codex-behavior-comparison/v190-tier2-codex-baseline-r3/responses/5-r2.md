Use **OSC 8 hyperlinks for paths** and **OSC 52 for copying**. These are terminal escape sequences: your Rust process writes them over SSH, and the user’s local terminal handles the action. No remote `pbcopy` or `xclip` needed.

The important distinction: clipboard forwarding works naturally over SSH; opening a **remote file in a local editor** needs an editor-aware link.

### 1. Make paths clickable with OSC 8

The wire format is:

```text
ESC ] 8 ; ; URI ESC \ visible text ESC ] 8 ; ; ESC \
```

For example:

```rust
fn hyperlink(uri: &str, label: &str) -> String {
    format!("\x1b]8;;{uri}\x1b\\{label}\x1b]8;;\x1b\\")
}
```

Choose the URI based on where the file lives:

| File location | Link target |
|---|---|
| Local filesystem | `file:///absolute/path/to/file.rs` |
| SSH host | An editor-specific remote URI, or a configured URL template |
| Repository source | A source-browser URL, optionally with a line anchor |

**A `file:///…` URI emitted over SSH does not automatically open that remote file locally.** Even `file://hostname/path` depends on the terminal’s handler and is not a portable remote-editor solution.

Make the target configurable—for example, support a VS Code Remote SSH link template using the user’s SSH alias. Use a URL library to encode paths correctly, and reject terminal control characters in both URIs and labels.

Most terminals require a modifier-click to follow links. Also, TUI renderers often measure and truncate strings themselves: don’t blindly put raw OSC sequences into a widget’s text unless the renderer understands them. Emit them through a supported hyperlink API or at the rendering layer.

### 2. Copy the selected request ID with OSC 52

On `y`, base64-encode the ID and write an OSC 52 clipboard-setting sequence:

```toml
[dependencies]
base64 = "0.22"
```

```rust
use base64::{engine::general_purpose::STANDARD, Engine};
use std::io::{self, Write};

fn copy_request_id(id: &str) -> io::Result<()> {
    let encoded = STANDARD.encode(id.as_bytes());
    let mut out = io::stdout().lock();

    // c = clipboard; BEL terminates the sequence.
    write!(out, "\x1b]52;c;{encoded}\x07")?;
    out.flush()
}
```

Send this through your existing terminal-output owner so it cannot interleave with a redraw. This writes to the **local terminal’s clipboard**, even when the program runs remotely.

The terminal must support and permit OSC 52 clipboard writes. There is no universally reliable success acknowledgment, so “Copy requested” is more accurate than claiming verified clipboard success.

### 3. Handle tmux explicitly

Prefer tmux’s native OSC 52 handling. On the machine running tmux:

```tmux
# Allow applications inside tmux to set the clipboard.
set -s set-clipboard on
```

`external` is insufficient for this use case: it permits tmux’s own clipboard integration but does not accept clipboard-setting requests from applications inside panes.

tmux also needs to know that its outer terminal supports clipboard operations. Inspect:

```sh
tmux info | rg 'Ms:'
```

If the capability is missing **and the outer terminal supports OSC 52**, configure its actual terminal pattern, for example:

```tmux
set -as terminal-features ',xterm-256color:clipboard'
```

Recent tmux versions can also handle OSC 8 hyperlinks natively. Older versions may strip them; document a supported tmux version and test against it.

For sequences that require bypassing tmux, an optional **passthrough mode** is useful:

```tmux
set -g allow-passthrough on
```

Wrap the complete sequence in tmux’s DCS wrapper, doubling every embedded ESC:

```rust
fn tmux_passthrough(sequence: &str) -> String {
    format!(
        "\x1bPtmux;{}\x1b\\",
        sequence.replace('\x1b', "\x1b\x1b")
    )
}
```

For OSC 52, wrap the entire clipboard sequence. For OSC 8, wrap the opening and closing control sequences separately, leaving the visible label as normal screen text. Passthrough requires support and permission at every tmux layer; nested sessions need additional handling.

Expose settings such as `clipboard = auto | osc52 | tmux-passthrough | off` and a configurable path-link template. `$TMUX` is a useful hint, but it does not prove that passthrough is enabled.

Test local, SSH, and SSH-plus-tmux with the terminals you support. Keep request IDs selectable and provide a keyboard “show path/ID” action as a fallback when terminal policy blocks these features.
