codex
Treat these as two separate problems: **who owns terminal output**, and **whether React commits the new state**.

### 1. Keep debugging output out of Ink’s drawing path

Ink redraws the terminal using cursor movement and clearing. Writes that bypass its output handling can interrupt a frame and garble the UI.

Ink patches `console` by default:

```tsx
render(<App />, {
  patchConsole: true, // Default; keep enabled for console.log debugging.
});
```

Check that you haven’t disabled this. Direct `process.stdout.write()` calls, child processes inheriting stdout, and some loggers can still bypass Ink’s handling. stderr shares the same terminal, so switching to `console.error()` alone doesn’t isolate output.

For dependable tracing, log to a file and watch it from another terminal:

```ts
import {appendFileSync} from 'node:fs';

function trace(event: string, data: unknown) {
  appendFileSync(
    'ink-debug.log',
    `${JSON.stringify({time: Date.now(), event, data})}\n`,
  );
}
```

For intentional messages above the UI, use Ink’s `useStdout().write()` instead of raw stdout writes.

### 2. Make the frame history visible

Temporarily enable Ink’s debug mode:

```tsx
render(<App />, {debug: true});
```

This preserves successive output frames instead of clearing them. It helps distinguish “Ink rendered the new value, but terminal output obscured it” from “the rendered value never changed.”

### 3. Trace state through React, not just through the reducer

**A reducer running does not prove that React committed a changed state.** A common cause is mutating and returning the same object:

```ts
// Wrong: same reference, so React can skip the update.
state.count += 1;
return state;

// Correct:
return {...state, count: state.count + 1};
```

Copy every changed level of nested state too.

Add a temporary trace in the component that actually displays the value:

```tsx
useEffect(() => {
  trace('committed count', {count: state.count});
}, [state.count]);

return <Text>Count: {state.count}</Text>;
```

Then follow the evidence:

- **Reducer runs; committed value stays unchanged:** check returned object identity, reducer branches, and mutation.
- **Parent commits; child stays stale:** inspect `React.memo` comparisons, memo dependencies, and whether you passed the updated value.
- **Component has the correct value; screen stays unchanged:** check output interference, layout/clipping, and whether the content is inside Ink’s `<Static>`—already printed static items do not update.

### 4. Inspect the component tree

Ink supports standalone React DevTools. For Ink versions supporting this integration:

```sh
npm install --save-dev react-devtools
npx react-devtools
```

Then run your CLI in another terminal with:

```sh
DEV=true <your-cli-command>
```

Inspect the displaying component’s props and hooks as you trigger the action.

The useful sequence is: **file trace → preserved frames → committed state → DevTools**. Each step narrows the failure to a specific layer instead of adding more terminal noise.
