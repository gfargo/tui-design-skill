codex
Treat these as two separate problems: **terminal output ownership** and **React deciding whether to render**.

**1. Make terminal output predictable**

Ink redraws the terminal, so raw writes can collide with its cursor movements. Ink normally patches `console` to coordinate logs with the UI; check that you haven’t set `patchConsole: false`. Writes through `process.stdout.write()` or another logger can bypass that protection.

For a debugging session, enable Ink’s debug mode:

```tsx
render(<App />, {debug: true});
```

This preserves successive frames instead of continuously clearing and replacing them. It makes noisy output easier to inspect, although it changes the live UI experience.

For traces that won’t disturb the terminal at all, write to a file:

```ts
import {appendFileSync} from 'node:fs';

function trace(label: string, value: unknown) {
  appendFileSync(
    'ink-debug.log',
    `${label} ${JSON.stringify(value)}\n`,
  );
}
```

Watch that file in another terminal. Avoid logging from render functions when possible: renders can repeat, so those logs aren’t proof that a change committed.

**2. Trace the update through React**

A reducer running proves that an action was processed. It doesn’t prove that React received a different state value.

The first thing to check is mutation:

```ts
// Wrong: same state reference
state.count += 1;
return state;

// Correct: new state reference
return {...state, count: state.count + 1};
```

React can skip an update when the returned state is identical under `Object.is`. Copy every changed level of nested state as well, especially when passing objects to memoized children.

Then trace three points:

- **Reducer:** record the action, previous/next values, and `Object.is(previous, next)`.
- **Component:** confirm that the component displaying the value renders with the expected props/state.
- **Commit:** use an effect to observe the value React committed:

```tsx
useEffect(() => {
  trace('committed count', count);
}, [count]);
```

If state changes but the child doesn’t render, inspect `React.memo`, custom equality functions, and reused object references. If the child renders with stale data, inspect missing hook dependencies, stale closures, and state initialized from props only once.

**3. Inspect the component tree**

Ink supports React DevTools. The usual setup is:

```sh
npm install --save-dev react-devtools-core
npx react-devtools
```

Then launch your CLI separately with `DEV=true`, for example:

```sh
DEV=true npm run dev
```

Use compatible DevTools packages for your installed Ink/React versions. Inspect the actual component’s hooks and props to locate where the expected value stops propagating.

Finally, reproduce the action with `ink-testing-library` and assert `lastFrame()` after React processes the update. If that frame is correct while the live terminal is wrong, focus on terminal writes and redraw behavior. If the frame is wrong too, focus on state and rendering.
