Use **file-based tracing to capture the resize sequence**, then test both **layout geometry and rendered frames**. A one-row overlap can come from stale dimensions, inclusive/exclusive coordinate math, or splitting panels from the full screen instead of the body.

**(a) Debug without writing into the terminal**

Configure logging before terminal initialization. For Tokio, a nonblocking writer keeps file I/O off the render path:

```rust
// tracing-subscriber: features = ["env-filter"]
let file = std::fs::File::create("app.log")?;
let (writer, _log_guard) = tracing_appender::non_blocking(file);
tracing_subscriber::fmt()
    .with_env_filter(tracing_subscriber::EnvFilter::from_default_env())
    .with_ansi(false)
    .with_writer(writer)
    .init();

// Keep _log_guard alive until shutdown.
```

Run with `RUST_LOG=debug` and `tail -f app.log` in another terminal. `eprintln!` and `dbg!` also corrupt the TUI when stderr points at the same terminal.

Log these together for each draw:

```rust
tracing::debug!(
    frame_id,
    area = ?frame.area(),
    panel = ?panel,
    footer = ?footer,
    "layout"
);
```

Also record resize-event dimensions and their order. Treat `Event::Resize` as a reason to redraw; derive rendering geometry from **that draw’s `frame.area()`**, since queued resize events can describe an older size. Keep terminal drawing in one owning task.

Centralize the layout:

```rust
use ratatui::layout::{Constraint, Layout, Rect};

fn regions(area: Rect) -> [Rect; 2] {
    Layout::vertical([
        Constraint::Min(0),
        Constraint::Length(1),
    ])
    .areas(area) // [body, footer]
}
```

Split all panels **inside `body`**. A bordered block’s rectangle already includes its borders; use `block.inner(panel)` for content.

`Rect::bottom()` is exclusive: the last border row is `panel.bottom() - 1`, when height is nonzero. For a panel above the footer, assert:

```rust
debug_assert!(panel.bottom() <= footer.y);
```

Don’t “fix” overlap by drawing the footer last—it can hide invalid geometry.

**(b) Make the regression deterministic**

Extract the production layout into a pure function. Test that every panel stays inside the body and above the footer, including nonzero origins, odd/even heights, 80×24, 60 columns, and heights around your minimum. Below the minimum, render an explicit “terminal too small” state.

Then replay the failing resize sequence through **the same app and terminal instance**:

```rust
use ratatui::{backend::TestBackend, Terminal};

#[test]
fn resize_keeps_panel_above_footer() -> std::io::Result<()> {
    let mut terminal = Terminal::new(TestBackend::new(80, 24))?;
    let mut app = App::test_fixture(); // deterministic production state

    // Replace/extend with the dimensions captured in app.log.
    let sizes = [(80, 24), (80, 23), (60, 12), (81, 25), (80, 24)];

    for (step, (width, height)) in sizes.into_iter().enumerate() {
        terminal.backend_mut().resize(width, height);
        terminal.autoresize()?;

        // If your app handles Resize events, feed the corresponding
        // event through its real update handler here, before drawing.
        terminal.draw(|frame| app.draw(frame))?;

        insta::assert_snapshot!(
            format!("resize_{step}_{width}x{height}"),
            terminal.backend()
        );
    }

    Ok(())
}
```

`App::test_fixture()` is your fixture constructor; the test must call your **production renderer**, not a separate example renderer. Pin data, time, selection, and loading state so snapshots stay stable.

Review the snapshots with `cargo insta review`, checking the complete bottom border and footer row. Keep geometry assertions too: snapshots alone can miss overlap that later drawing covers. Text snapshots don’t verify styles; compare `Buffer`s if footer styling matters.

If geometry and `TestBackend` output are correct while the real terminal still fails, add one fixed-size PTY resize smoke test. That targets Crossterm/event-loop/output integration, which `TestBackend` does not exercise.
