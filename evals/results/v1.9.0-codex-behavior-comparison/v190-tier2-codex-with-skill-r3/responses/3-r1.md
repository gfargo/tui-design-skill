Use a workflow that separates **state changes, rendered frames, and terminal output**. A reducer running proves only the first.

1. **Make logging safe first.** Ink defaults to `patchConsole: true`: it intercepts `console.*`, prints above the live UI, then repaints. If logs garble the screen, check for:
   - `patchConsole: false`
   - direct `process.stdout.write()` calls
   - child processes using inherited stdio
   - another renderer or spinner writing to the same terminal

   Keep high-volume tracing in a file you `tail -f` in another terminal. Inside components, Ink’s `useStderr().write()` provides coordinated diagnostic output; raw stderr writes can still collide when stderr shares the terminal.

2. **Expose the actual frame history.**

   ```tsx
   render(<App />, {debug: true});
   ```

   This appends each rendered update instead of repainting in place. Reproduce one action and inspect the resulting frames:
   - **New value appears:** investigate terminal output interference.
   - **New value is absent:** investigate React state, subscriptions, or rendering.

3. **Trace the missing update through React.** Check these in order:
   - **Identity:** return a new state object and new changed nested objects. Mutating state and returning the same reference can cause React to skip the update.
   - **Subscriptions:** confirm the visible component reads the state instance your reducer updates. Check Context providers and external-store selectors.
   - **Derived values:** inspect stale closures, missing hook dependencies, and `React.memo` comparisons.
   - **`<Static>`:** already printed items do not update. Put changing values in the live tree.
   - **Visibility:** check conditional rendering, clipping, and zero-sized containers.

   Inspect committed state with an effect or DevTools; logging immediately after `dispatch()` reads the current render’s state.

4. **Inspect the component tree when needed.** Install the optional `react-devtools-core` dependency, run your CLI with `DEV=true`, and launch `npx react-devtools` separately. Inspect props, hooks, and component ownership. Ink supports tree inspection here, **not React Profiler profiling**.

5. **Turn the reproduction into a regression test.** Test the reducer’s returned value and identity, then use `ink-testing-library` to drive the action and assert `lastFrame()`. Await asynchronous input and rendering before asserting; an immediate assertion can read the previous frame. Reserve a small PTY test for corruption that occurs only in a real terminal.

If the UI eventually updates but freezes first, check synchronous I/O and CPU-heavy loops. Use `node --cpu-prof` to investigate performance.
