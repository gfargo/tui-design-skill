Use three layers: **safe tracing → appended frames → component inspection**. A reducer running proves the action reached it; it doesn’t prove React committed a changed value or Ink painted it.

1. **Make logging safe first.** Ink defaults to `patchConsole: true`: it intercepts `console.*`, prints messages above the live UI, and repaints. Garbling suggests checking for:
   - `patchConsole: false`
   - direct `process.stdout.write()`
   - child processes with inherited terminal stdio
   - another renderer or spinner writing to the same terminal

   For heavy tracing, use a file and `tail -f` in another terminal. Inside components, `useStderr().write()` is Ink’s coordinated diagnostic API. Merely switching to raw stderr isn’t isolation when both streams share a terminal.

2. **Record frames instead of overwriting them.**

   ```tsx
   render(<App />, {debug: true, patchConsole: true});
   ```

   Debug mode appends each rendered update. Trigger one action and inspect whether the expected text appears:
   - **Absent:** investigate state, props, subscriptions, and render conditions.
   - **Present, but broken in normal mode:** investigate competing terminal writers, clipping, and layout.

3. **Trace the missing update through React.** Check these in order:
   - **Immutable reducer return:** mutating state and returning the same object can cause React to skip the update.
     ```ts
     // Wrong
     state.count += 1;
     return state;

     // Correct
     return {...state, count: state.count + 1};
     ```
   - **Committed value:** temporarily trace the selected value in `useEffect(..., [value])`. Logging immediately after dispatch sees the current render’s snapshot.
   - **Consumer path:** verify the visible component reads the same provider/store; inspect memo comparisons, selectors, and stale `useMemo` dependencies.
   - **`<Static>`:** already rendered items don’t update. Changing status belongs in the live region.
   - **Visibility and timing:** check hidden/clipped content and synchronous work blocking the event loop before painting.

4. **Inspect the live component tree.** Install the optional `react-devtools-core` peer, run the CLI with `DEV=true`, and launch `npx react-devtools` separately. Inspect the affected component’s props and hooks. Ink supports tree inspection here, **not React profiling**. For CPU problems, use `node --cpu-prof`.

5. **Turn the reproduction into two checks.** Unit-test the reducer’s next value and object identity, then use `ink-testing-library` to trigger the action and assert `lastFrame()`. Await the asynchronous update before asserting; an immediate frame read can be stale.

This workflow separates “state didn’t propagate” from “the correct frame couldn’t be displayed,” so each debugging step tests a specific boundary.
