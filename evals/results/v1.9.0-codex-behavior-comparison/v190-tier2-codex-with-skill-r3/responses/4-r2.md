Use a **bounded inline picker**, then replace it with a **one-line receipt**. This is a summon–choose–exit tool; keeping the shell context visible suits it better than lazygit’s full-screen workspace.

Cap the picker at roughly 8–10 rows or 40% of terminal height. Use one searchable list, without borders or a preview initially:

```text
Wide terminal                         60-column split
$ branch-pick                         $ branch-pick
Branch > fix                          Branch > fix
> fix/login                  2h ago    > fix/login
  fix/build                  1d ago      fix/build
Up/Down move | Enter pick             Up/Down move | Enter pick
Type to filter | Esc/Ctrl+C cancel     Type to filter | Esc/Ctrl+C cancel
```

At 80×24, keep that same compact layout. At 60 columns, hide timestamps first and truncate long branch names by terminal-cell width. Reduce visible rows on short terminals; below a declared minimum such as 30×6, show a readable “terminal too small” message with cancellation still available. The clutter budget is zero borders, one selection marker, and two control lines.

After selection, erase only the picker’s transient rows and leave:

```text
$ branch-pick
fix/login
$
```

The original invocation belongs to the shell: don’t clear the screen or redraw over it. Don’t leave the entire candidate list behind.

Define the streams explicitly:

- **Interactive UI:** stderr or `/dev/tty`.
- **Result:** exactly the selected branch plus a newline on stdout.
- **Cancellation:** no result on stdout; return a documented nonzero status.
- **Errors:** restore the terminal, then print a concise diagnostic on stderr.

For direct invocation, stdout already supplies the persistent receipt. For `branch=$(branch-pick)`, stdout is captured; if the selection must still appear in scrollback, print `Selected branch: fix/login` to the interactive terminal after cleanup. Avoid duplicating that receipt during ordinary invocation.

In Go, Bubble Tea fits well: keep its default inline mode, use `tea.WithOutput(os.Stderr)` when stderr is the interactive terminal, and print the result **after `Program.Run()` returns**. Let the framework restore terminal modes and cursor state on exit.

Full-screen can be an optional mode later if a large commit preview earns the space. Even then, print the receipt after leaving the alternate screen—its contents won’t persist in normal scrollback.
