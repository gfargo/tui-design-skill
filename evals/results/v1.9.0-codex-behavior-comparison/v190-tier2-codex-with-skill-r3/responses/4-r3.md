**Use a bounded inline picker, and leave a one-line receipt when it exits.** This is a summon–choose–exit tool; keeping the shell context visible suits it better than lazygit’s full-screen session.

Cap it at roughly 8–10 rows or 40% of terminal height. Use one searchable list:

```text
Wide terminal                         60-column split
$ git-recent                          $ git-recent
branch> fix                           branch> fix
> fix/login       2 hours ago         > fix/login
  fix/tests       yesterday             fix/tests
Up/Down move | Enter pick | Esc cancel Up/Down move | Enter pick | Esc cancel
```

At 80×24, keep the same layout. At 60 columns, drop timestamps first and truncate long names by terminal cell width; retain the full branch value internally. Reduce visible rows as height shrinks. Below a declared minimum, such as 40×6, show a “terminal too small” message with cancellation available.

**After selection, erase the transient list and search prompt, restore the terminal, then print the result:**

```text
$ git-recent
fix/login
$
```

The shell’s original command stays intact, and the selected branch becomes permanent output. Avoid leaving the final menu frame behind or clearing the whole screen.

Keep the output contract explicit:

- **stdout:** exactly the selected branch plus a newline.
- **stderr or `/dev/tty`:** interactive UI and diagnostics.
- **Cancellation:** no branch on stdout; a nonzero status.
- **Captured output:** for `branch=$(git-recent)`, optionally leave `Selected branch: fix/login` on the interactive terminal after cleanup so the choice remains visible in scrollback.

In Go, Bubble Tea fits this well: inline is the default; keep `AltScreen` false, direct rendering away from stdout, and emit the result after `Program.Run()` returns and cleanup finishes. Verify success, cancellation, and error paths restore the cursor and terminal modes.

Keep the chrome minimal: zero borders, one `>` selection marker, no icon on every branch, and only the search line and key hints. Full-screen becomes useful later if a substantial commit or diff preview needs the space; even then, print the receipt **after leaving the alternate screen**.
