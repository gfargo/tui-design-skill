Use **OSC 52 for clipboard writes**, and **app-handled path clicks to launch the editor on the machine running the TUI**. OSC 8 hyperlinks are useful too, but they don’t solve remote file opening.

### Copy request IDs with OSC 52

OSC 52 sends a base64 payload through the terminal connection to the user’s **local clipboard**, including over SSH:

```text
ESC ] 52 ; c ; BASE64(request_id) ESC \
```

A small Rust implementation using `base64 = "0.22"`:

```rust
use base64::{engine::general_purpose::STANDARD, Engine as _};
use std::io::{self, Write};

fn copy_request_id(
    terminal_output: &mut impl Write,
    id: &str,
) -> io::Result<()> {
    // Conservative limit: terminal clipboard limits vary.
    if id.len() > 32 * 1024 {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "Request ID exceeds clipboard limit",
        ));
    }

    write!(
        terminal_output,
        "\x1b]52;c;{}\x1b\\",
        STANDARD.encode(id.as_bytes())
    )?;
    terminal_output.flush()
}
```

Run this once on `y` in log-navigation mode, using the selected entry’s full ID. In search/text-entry mode, `y` should remain text. Write through the TUI’s serialized terminal-output path, outside the render closure; never insert the escape sequence into a Ratatui `Span`.

Crossterm 0.29 also provides OSC 52 clipboard support. If using Ratatui, import Crossterm through `ratatui::crossterm` to avoid version mismatches.

Terminal clipboard writes can be disabled and have no portable success acknowledgment. Report **“Clipboard write sent”**, handle actual output errors, and offer a selectable full-ID view if nothing reaches the clipboard. Don’t query the clipboard to verify it.

### Make tmux forward the clipboard

Document this user configuration:

```tmux
# Allow applications inside tmux to set the outer clipboard.
set -s set-clipboard on
```

The default `external` setting allows tmux itself to write the clipboard but excludes applications inside panes.

Tmux also needs to recognize clipboard support in the **outer terminal**. Check:

```sh
tmux info
```

Look for `Ms`. If it is missing and the outer terminal supports OSC 52, declare its capability, matching its actual terminal name:

```tmux
# Example for an outer terminal advertising xterm-256color:
set -as terminal-features ',xterm-256color:clipboard'
```

Recent tmux versions can also learn this from terminal device attributes. The terminal emulator must permit clipboard writes; nested tmux sessions need forwarding configured at each layer.

**OSC 52 is handled natively by tmux. It does not require `allow-passthrough` or a DCS wrapper.**

### Open paths where the files exist

OSC 8 creates terminal hyperlinks:

```text
ESC ] 8 ; id=source-42 ; file:///absolute/path ESC \
visible path
ESC ] 8 ; ; ESC \
```

But the **local terminal** activates that URI. Over SSH, `/srv/app/main.rs` exists on the remote host; a `file://` link cannot reliably open it locally. Even locally, the terminal’s URI handler decides which application opens it.

For reliable editor opening:

- Track each visible path’s screen rectangle and underlying full path.
- Handle clicks with Crossterm mouse events; bind `Enter` or `o` to the same action.
- Launch the configured editor, falling back to `$VISUAL` / `$EDITOR`, on the host running the TUI.
- Pass the path as a process argument, without shell interpolation. Support editor arguments through a configured argument list.

Before launching a terminal editor, pause the TUI input reader, disable owned input modes, leave the alternate screen, and restore cooked mode. After the editor exits, re-enter TUI modes, restart input, reload affected data, and force a full redraw—even when launching fails.

With SSH, this opens the **remote editor in the existing session**. Opening a local GUI editor against remote files requires an explicit integration, such as a configured remote-editor URI or user-defined path mapping.

If you use Ratatui, don’t embed OSC 8 inside `Text` or `Span`: its cell-buffer model doesn’t natively support hyperlink metadata. App-handled clicks avoid that issue. Reserve OSC 8 for supported rendering paths and URLs such as `https://…`; tmux supports native hyperlinks from 3.4 onward.

Keep one contextual hint: `Enter open file · y copy request ID`. Test directly, over SSH, and over SSH inside tmux, including clipboard-disabled behavior and editor failure/resume.
