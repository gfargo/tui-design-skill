Use **application mouse handling to open paths**, and **OSC 52 to copy IDs to the user’s local clipboard**. Both work over SSH, subject to terminal and tmux support.

**1. Clicking a path: open the editor where the TUI runs**

Handle the click inside your app and dispatch the same `OpenFile` action as an `o` keyboard shortcut.

For Ratatui/Crossterm:

- Enable mouse reporting and hit-test the path’s rendered cell range. Account for scrolling, truncation, and Unicode cell widths.
- Retain the full path in your model; don’t reconstruct it from displayed text.
- Launch the configured editor, falling back through `$VISUAL`, `$EDITOR`, then a default. Pass the path as a separate process argument; don’t interpolate log contents into a shell command.
- Before launching: stop and await the input reader, disable extra terminal modes such as mouse capture, and restore the terminal.
- Wait for the editor, then reinitialize the TUI, restore enabled modes, restart input, refresh externally changed data, and force a full redraw. Reenter even when spawning the editor fails.

Over SSH, this opens the **remote editor on the remote file**. Opening a remote file in a local GUI editor requires an explicit integration such as a configured remote-editor command.

OSC 8 hyperlinks are useful for URLs, but aren’t a general solution here: the local terminal handles them, so a remote `file://` path usually points at the wrong filesystem. Also, **don’t embed OSC 8 escape sequences in Ratatui `Span`/`Text`**; they interfere with its cell-buffer rendering.

**2. Pressing `y`: send OSC 52**

OSC 52 travels through SSH to the local terminal, which sets the local clipboard. No remote `pbcopy` or `xclip` process is needed.

The wire format is:

```text
ESC ] 52 ; c ; BASE64_OF_REQUEST_ID ESC \
```

For example, using the `base64` crate:

```rust
use base64::{engine::general_purpose::STANDARD, Engine as _};
use std::io::{self, Write};

fn copy_id(out: &mut impl Write, id: &str) -> io::Result<()> {
    write!(out, "\x1b]52;c;{}\x1b\\", STANDARD.encode(id.as_bytes()))?;
    out.flush()
}
```

Call this through the terminal’s serialized output path, outside the render callback, so it cannot interleave with a frame. Crossterm 0.29 also provides OSC 52 clipboard support.

Bind `y` to copy the **full ID from the selected record**, only while navigation owns focus; typing `y` into search should still type a character.

**3. tmux: use its native clipboard forwarding**

Document this configuration:

```tmux
# ~/.tmux.conf
set -s set-clipboard on
```

tmux’s usual `external` setting allows tmux itself to set the clipboard but prevents applications inside it from doing so. `on` permits your TUI’s OSC 52 writes.

tmux also needs to recognize clipboard support in the **outer terminal**. Diagnose with:

```sh
tmux show-options -s set-clipboard
tmux info
```

Look for the `Ms` capability. If missing, configure clipboard support for the actual outer terminal—for example, when it identifies as `xterm-256color` and supports OSC 52:

```tmux
set -as terminal-features ',xterm-256color:clipboard'
```

Older tmux versions may need an `Ms` terminfo override. Every layer of nested tmux must support forwarding.

**OSC 52 does not require `allow-passthrough` or a `DCS tmux;…` wrapper when using tmux’s native clipboard handling.** The local emulator must also permit clipboard writes.

**4. Make failure honest and recoverable**

OSC 52 generally provides no success acknowledgment. Show “Copy sent to terminal,” rather than claiming verified clipboard success. Keep writes user-triggered, bound payload size, and avoid clipboard-read queries.

Provide a selectable full-ID view when copying is blocked; optionally offer `arboard` or local clipboard commands for local sessions. Include `o open · y copy ID` in the footer, a `--no-mouse` option, and instructions for the terminal’s selection-bypass modifier.

Verify direct-terminal, SSH, and SSH-inside-tmux flows, plus blocked clipboard writes and editor spawn failure. A small PTY test should cover terminal restoration and editor return; clipboard arrival needs testing with real terminal emulators.
