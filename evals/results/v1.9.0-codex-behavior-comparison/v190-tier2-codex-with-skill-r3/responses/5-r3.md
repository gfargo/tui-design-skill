Use **OSC 52 for copying** and **an app-handled click for opening files**. Both work over SSH, but they act on different machines: the clipboard belongs to the user’s local terminal; the editor should run where the file lives.

### Copy request IDs with OSC 52

OSC 52 sends base64-encoded text through the terminal connection to the local clipboard. No remote `pbcopy` or `xclip` process is needed.

With the Rust `base64` crate:

```rust
use base64::{engine::general_purpose::STANDARD, Engine};
use std::io::{self, Write};

fn copy_request_id(
    terminal_output: &mut impl Write,
    id: &str,
) -> io::Result<()> {
    // OSC 52, clipboard selection "c", terminated by ST.
    write!(
        terminal_output,
        "\x1b]52;c;{}\x1b\\",
        STANDARD.encode(id.as_bytes())
    )?;
    terminal_output.flush()
}
```

Call this on `y` for the selected log entry, outside text-entry mode. Send it through the same serialized terminal writer your renderer uses, between frames. Don’t put these bytes in a Ratatui `Span` or print them into redirected output. Crossterm 0.29 also provides OSC 52 clipboard support.

A successful write means **the request was sent**, not that the clipboard changed: terminals can disable or ignore it, and there is no dependable success acknowledgment. Show “Copy sent” and offer a selectable request-ID detail view as a fallback. Avoid clipboard-read queries.

For tmux, document:

```tmux
# ~/.tmux.conf
set -s set-clipboard on
```

The default `external` setting allows tmux itself to update the clipboard but blocks applications inside it from doing so. Forwarding also requires tmux to recognize the outer terminal’s clipboard capability—through its `Ms` terminfo capability or newer terminal detection.

Users can inspect that with:

```sh
tmux show -s set-clipboard
tmux info
```

If `Ms` is missing, configure the actual outer terminal appropriately. For example, for an outer terminal known to support clipboard writes:

```tmux
set -as terminal-features ',xterm-256color:clipboard'
```

Match that pattern to the real outer terminal; don’t blindly declare support for every terminal. Each layer of nested tmux must permit forwarding.

**Native OSC 52 handling does not require `allow-passthrough` or a DCS wrapper.**

### Open paths where the files exist

OSC 8 creates terminal hyperlinks:

```text
ESC ] 8 ; ; URI ESC \ visible path ESC ] 8 ; ; ESC \
```

That works well for HTTPS links and can work for local `file://` links. However, the terminal opens the URI **on the user’s local machine**. A remote `/srv/app/main.rs` will not magically open in their local editor.

For consistent file opening:

- Hit-test clicks against the visible path’s screen cells.
- Bind `Enter` or `o` to the same action for the selected entry.
- Resolve the path against the log source’s configured project root.
- Launch the configured editor on the machine running the TUI.

For Ratatui, perform a temporary terminal handoff: stop the input reader, disable extra input modes, restore the terminal, launch and wait for the editor, re-enter terminal modes, reload changed data, clear, and redraw. Handle child-process and re-entry errors without skipping cleanup. Pass paths as process arguments rather than interpolating them into shell commands.

If users specifically want a **local GUI editor for remote files**, offer an explicit remote-editor integration, such as a configured VS Code Remote SSH URI. That requires a matching client setup.

Ratatui does not natively support OSC 8 links in its cell buffer; embedding escape sequences in `Text` or `Span` breaks width accounting. App-handled clicks avoid that problem. Native terminal hyperlink activation also usually requires a modifier-click, especially with mouse capture enabled.

Keep discoverability to one footer—`Enter open file · y copy ID`—including in a 60-column tmux split. Truncate displayed paths by terminal-cell width while retaining the complete path and request ID in application state.

Verify direct terminal, SSH, and SSH-inside-tmux flows, plus clipboard-disabled behavior and editor failure/re-entry. Those checks exercise the boundaries that determine whether these features actually work.
