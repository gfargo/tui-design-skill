user
My Go CLI needs an API key before it can do anything. What should happen the very first time someone runs it with no key configured — and once I have huh set up for the prompt, where should I store the key?

codex
On first run, make setup a short, explicit flow:

1. Look for a key in an environment variable (for example, `MYCLI_API_KEY`), then in saved credentials.
2. If none exists and the terminal is interactive, explain why it’s needed, link to the page where users create one, and show a masked `huh` input.
3. Validate the key with a lightweight API request. Let users retry an invalid key; distinguish that from a network failure.
4. Save it only after validation, then continue the command they originally ran. Cancellation should exit cleanly without saving anything.

**In scripts or CI, never open the prompt.** Return a nonzero exit code with an actionable message:

```text
No API key configured. Set MYCLI_API_KEY or run `mycli auth login`.
```

**Store the key in the OS credential store**, using a Go package such as `github.com/zalando/go-keyring`:

- macOS: Keychain
- Windows: Credential Manager
- Linux: Secret Service, when available

`huh` handles input; it doesn’t provide secure storage. Keep ordinary preferences in your config file and the API key in the credential store.

If the credential store is unavailable, support the environment variable and explain the limitation. If you offer file storage as a fallback, make it explicit opt-in, use a private directory (`0700`) and file (`0600`) on Unix, and state that the key is stored in plaintext. Don’t silently fall back.

Also provide `mycli auth login`, `mycli auth status`, and `mycli auth logout`. Never print the saved key or include it in logs or errors.
