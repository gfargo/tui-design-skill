**Your Rust process cannot directly change its parent shell’s working directory.** `std::env::set_current_dir()` changes only your process’s cwd; launching `sh -c 'cd …'` changes only that child shell.

The standard solution is a **shell function that launches the TUI, reads its chosen directory, then runs `cd` in the current shell**. Yazi uses `--cwd-file`; ranger has `--choosedir`.

For your picker, expose something like `--cwd-file PATH`. Here’s a Bash/Zsh wrapper, assuming your app writes an absolute path followed by a NUL byte:

```bash
# Add to ~/.bashrc or ~/.zshrc; invoke with `p`.
p() {
    local tmp cwd rc
    tmp=$(mktemp "${TMPDIR:-/tmp}/picker-cwd.XXXXXX") || return 1

    if command mypicker --cwd-file "$tmp" "$@"; then
        rc=0
        if IFS= read -r -d '' cwd < "$tmp" && [[ -n "$cwd" ]]; then
            builtin cd -- "$cwd" || rc=$?
        fi
    else
        rc=$?
    fi

    command rm -f -- "$tmp"
    return "$rc"
}
```

Define the app’s contract clearly:

- **Accept:** restore the terminal, write the selected absolute directory to the file, and exit successfully.
- **Cancel:** leave the file empty, so the shell stays put.
- **Error:** restore the terminal and exit nonzero; the wrapper skips `cd`.

On Unix, write the path’s original bytes rather than `path.display()` or a lossy UTF-8 conversion. NUL termination preserves filenames containing newlines. Keep the file as path data—never `eval` it.

You can also return the path on stdout and capture it in a wrapper, provided all TUI rendering goes to stderr or `/dev/tty`. A dedicated result file lets the TUI retain its normal terminal streams.

The user gets the desired experience: **run `p`, choose a directory, quit, and find their existing shell there.** The shell integration performs the final `cd`.
