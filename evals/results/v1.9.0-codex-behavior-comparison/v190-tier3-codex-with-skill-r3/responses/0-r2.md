**Your Rust process cannot directly change its parent shell’s working directory.** `std::env::set_current_dir()` changes your process and the directory inherited by future children. Running `sh -c 'cd …'` changes only that child shell.

**Ship a shell function that launches your TUI, reads the chosen directory, and calls `cd` in the current shell.** This is the pattern behind yazi’s `--cwd-file` and ranger’s `--choosedir`.

For example, define your binary’s contract as:

- `--cwd-file PATH`: write the chosen **absolute path followed by NUL** on acceptance.
- Cancellation: leave the file empty; errors: return nonzero.
- Restore terminal modes before exiting.

Then provide this Bash/Zsh wrapper in the user’s shell configuration:

```bash
pick() {
    local tmp cwd rc
    tmp=$(mktemp) || return 1

    command mypicker --cwd-file "$tmp" "$@"
    rc=$?

    if [ "$rc" -eq 0 ]; then
        if IFS= read -r -d '' cwd < "$tmp" && [ -n "$cwd" ]; then
            builtin cd -- "$cwd" || rc=$?
        fi
    fi

    command rm -f -- "$tmp"
    return "$rc"
}
```

The NUL delimiter preserves paths containing newlines; quoting handles spaces and glob characters. In Rust on Unix, write the `OsStr`’s raw bytes rather than using `to_string_lossy()`.

Users invoke `pick`, and the function’s `cd` affects their actual shell. Executing that wrapper as a separate script would introduce another child process and lose the effect.

A stdout-based picker also works—`dir=$(mypicker)` followed by `cd -- "$dir"`—provided UI output goes to stderr or `/dev/tty`. The dedicated result file keeps full-screen rendering independent of the result channel and avoids command substitution stripping trailing newlines.

For convenient installation, offer `mypicker init bash` / `init zsh` to emit the wrapper. **Pass paths as data; don’t `eval` selected paths or generated `cd` commands.**
