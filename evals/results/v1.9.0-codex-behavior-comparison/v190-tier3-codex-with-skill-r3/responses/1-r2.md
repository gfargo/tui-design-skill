**Use a short inline setup prompt on the first interactive run, and save the key in the OS keychain.** Huh handles collecting the key; your application handles validation and storage.

The first-run flow should be:

1. Look for `MYTOOL_API_KEY`, then a saved credential. An environment key overrides storage and should never be persisted automatically.
2. If neither exists, explain why the key is needed, where to create one, and where you’ll save it.
3. Prompt with a **masked Huh input**. Allow paste; Enter submits and Ctrl+C cancels without saving.
4. Reject empty input locally, then validate with a lightweight API request and a timeout. Keep network work outside the field validator. Distinguish an invalid key from a network failure.
5. Save the accepted key, confirm the storage location, and continue the command the user originally requested.

Keep `--help`, `--version`, and authentication commands usable without credentials.

A simple layout works at both wide and narrow sizes:

```text
80 columns                         60 columns
Connect mytool                     Connect mytool
Create a key: https://…             Create a key: https://…
Saved in your OS keychain.          Saved in your OS keychain.

API key: ********                  API key: ********
Enter submit · Ctrl+C cancel       Enter submit · Ctrl+C cancel
```

No borders, welcome banner, or multi-step wizard are needed. At 80×24 and in a 60-column split, keep the same single-column flow and wrap explanatory text.

**For storage, use [`zalando/go-keyring`](https://github.com/zalando/go-keyring)**, with a stable service name and an account/profile identifier. It supports macOS Keychain, Windows Credential Manager, and Linux Secret Service. Keep ordinary preferences and credential identifiers in config; keep the secret in the keychain.

On headless Linux, a keychain may be unavailable. Offer an **explicit opt-in plaintext fallback**, never a silent one. Use a dedicated credentials file under your user config directory, create its directory with Unix mode `0700`, explicitly enforce file mode `0600`, and write atomically. Use appropriate Windows ACLs there.

For automation:

- Never launch Huh when there’s no interactive terminal. Check stdin and stdout before ordinary stdio prompting, or test your explicitly opened terminal channel.
- Support `MYTOOL_API_KEY` and a command such as `mytool auth login --key-stdin`.
- If credentials are missing, print an actionable error to stderr and exit nonzero.
- Keep prompts and setup messages off stdout, which belongs to command results.
- Avoid `--api-key VALUE`: it exposes secrets through shell history and process arguments.

Also provide `auth status` with a redacted credential source and `auth logout` to remove the saved key.
