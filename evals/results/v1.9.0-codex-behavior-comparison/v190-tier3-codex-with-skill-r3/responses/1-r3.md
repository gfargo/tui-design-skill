**Make the first run a short, inline setup flow, then continue the command the user originally requested. Store the key in the OS keychain.** Huh handles collecting input; your application handles validation and persistence.

The flow should be:

1. Check `MYTOOL_API_KEY` first, then the saved credential. An environment key bypasses setup and should never be persisted automatically.
2. If no key exists and the session is interactive, explain why it’s needed, show the real key-creation URL, and prompt with masked input.
3. Reject empty input locally; validate against the API with a timeout. Distinguish “invalid key” from network failure and allow retry or cancellation.
4. Save successfully, confirm the storage location without showing the key, and resume the original command. Cancellation saves nothing and exits nonzero—130 for prompt cancellation.

Keep help, version, and authentication management available without a key.

At 80 columns and in a 60-column split, the same simple layout works:

```text
80 columns                          60 columns
Set up mytool                       Set up mytool
An API key is required.              An API key is required.
Create one: <provider URL>           Create one: <provider URL>

API key: ********                   API key: ********
Saved in your OS keychain.           Saved in your OS keychain.

Enter continue | Ctrl+C cancel      Enter continue | Ctrl+C cancel
```

Wrap long URLs and horizontally scroll the input at narrower widths. Use no borders or repeated status markers. Send prompts and setup messages to stderr; reserve stdout for command results. Offer Huh’s accessible mode through an explicit setting.

**For Go storage, use [`zalando/go-keyring`](https://github.com/zalando/go-keyring)** with a stable service name and an account/profile identifier:

```go
err := keyring.Set("mytool", profileID, apiKey)
key, err := keyring.Get("mytool", profileID)
err = keyring.Delete("mytool", profileID)
```

This uses macOS Keychain, Windows Credential Manager, or Linux Secret Service. Keep ordinary preferences and profile metadata in your config file.

Linux headless environments may lack a keychain. Support an **explicit plaintext-storage opt-in**, with a credential file explicitly restricted to `0600` on Unix and a private directory. Never silently downgrade storage or report “saved” after a failed write.

For CI or piped input, skip prompting and return an actionable error:

```text
error: no API key configured.
Set MYTOOL_API_KEY or run `mytool auth login` interactively.
```

Check both stdin and stdout are TTYs before ordinary interactive setup; honor CI and your documented prompt-disable setting. Also support an explicit stdin credential path for automation. Avoid `--api-key VALUE`, which exposes secrets through shell history and process arguments, and redact keys from logs and config inspection.
