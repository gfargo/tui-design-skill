**Make Nerd Font icons an explicit opt-in, and treat polling timeouts as a recoverable stale-data state.**

For icons:

- Default to ordinary Unicode symbols with text labels; offer an ASCII mode too.
- Provide a persistent setting such as `icons = "none" | "unicode" | "nerd-v3"`.
- Don’t infer font support from `$TERM`, terminal brand, or a TTY check. There’s no reliable terminal query for active Nerd Font coverage.
- Document the supported Nerd Font version: v3 changed some codepoints.
- Centralize your glyph mappings and measure terminal cell widths. Test alignment in a real terminal; width calculations cannot prove a font renders a glyph correctly.

Keep labels such as `Settings` and `Retry` meaningful without their icons.

For API polling, **keep the last successful data visible when a refresh times out**:

| State | UI behavior |
|---|---|
| First fetch | Show the layout immediately with “Loading…”; offer cancellation. |
| Background refresh | Keep existing rows, focus, selection, and scroll position. Use a small refresh indicator. |
| Timeout with cached data | Show `STALE`, age since last success, the failure reason, and retry controls. |
| Timeout without cached data | Show “Couldn’t load data: request timed out” with `r retry`. Don’t present it as an empty result. |
| Recovery | Replace data, clear the stale indicator, and preserve selection by stable item ID. |

In Ratatui, run network work in a Tokio task and send results into the application event loop through a channel. Rendering should read state without waiting on the network. Keep data, last-success time, in-flight status, and the latest error separate.

Use a bounded request timeout and capped exponential backoff with jitter after failures. Allow `r` to retry immediately, prevent overlapping requests, and reset backoff after success. Repeated failures should update one persistent status and a message log, rather than produce a new modal or toast every few seconds.

A compact layout could look like this:

```text
Wide / 80×24
Resources
NAME                 STATUS          UPDATED
api                  Running         12:04
worker               Running         12:04

STALE 38s | Refresh timed out | Retry in 8s
r retry | l log | q quit | ? help

60-column split
Resources
NAME                 STATUS
api                  Running
worker               Running

STALE 38s | Timed out | Retry in 8s
r retry | l log | q quit | ? help
```

At 60 columns, drop secondary columns before hiding freshness or recovery controls; expose full row details on demand. Below your measured minimum, show a truthful “terminal too small” message and keep quit working.

This needs no nested borders, repeated warning icons on every row, or duplicate error banners: one shared stale status is enough. Verify timeout → stale → recovery transitions, and use Ratatui’s `TestBackend` for frames at 80 and 60 columns, including ASCII and monochrome modes.
