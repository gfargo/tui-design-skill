Make Nerd Fonts an explicit opt-in, and treat polling timeouts as a normal stale-data state.

**Icons**

There’s no reliable terminal query for whether a Nerd Font is active. `$TERM`, terminal brand, and TTY detection don’t establish font support.

- Default to ordinary Unicode symbols or text; provide an ASCII fallback.
- Offer a persistent setting such as `icons = "none" | "unicode" | "nerd-v3"`. Pin the Nerd Font generation: v3 moved some codepoints.
- Keep labels meaningful without icons. A missing glyph must never hide an action or status.
- Centralize glyph choices and measure terminal cell width for layout. Check alignment in actual terminals; buffer snapshots can’t verify font rendering.

If you expose `--icons=auto`, document that TTY detection alone cannot detect Nerd Fonts. `NO_COLOR` should independently disable color, with status still expressed in words.

**Polling and timeouts**

Keep the last successful data visible, preserve selection and scroll position, and show its age. A timeout should update a status line without interrupting the user.

| Situation | UI behavior |
|---|---|
| First fetch | Show the layout immediately with “Loading…”; delay any spinner about 100–200 ms. |
| Background refresh | Keep existing rows visible; use a small refresh indicator. |
| Timeout with cached data | Show `STALE 42s — request timed out; retry in 8s`. |
| Timeout before any success | Show “Could not load data: request timed out” with retry. Don’t call this empty data. |
| Some sources fail | Keep successful results and mark the affected source. |
| Recovery | Replace data, clear the stale marker, and briefly confirm reconnection. |

Provide `r retry now` and access to error details. Keep the warning visible while unresolved; deduplicate repeated failures in a timestamped message log.

For Ratatui, run network work in a Tokio task and deliver results through a channel. Keep rendering synchronous and driven by state changes. Use a bounded request timeout, capped exponential backoff with jitter after failures, and one request in flight per source. Manual retry should bypass the wait without starting duplicates. Resume normal polling after success.

A compact layout works at both widths:

```text
Wide
Resources                         STALE 42s
NAME          STATUS          UPDATED
api-7d        Running         14:32:01
Request timed out; retry in 8s
r retry now | l messages | q quit | ? help

60-column split
Resources                         STALE 42s
NAME          STATUS
api-7d        Running
Timeout; retry in 8s
r retry | l messages | q quit | ? help
```

At 80×24, retain useful columns; at 60 columns, hide secondary columns before truncating names. Below your declared minimum, show the required dimensions and keep quit working.

Keep the chrome lean: no nested borders, per-row stale icons, or modal for every timeout. One shared stale marker, age, and recovery message suffice.
