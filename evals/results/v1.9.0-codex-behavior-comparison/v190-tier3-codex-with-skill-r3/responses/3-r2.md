### Textual with 50k rows

`DataTable` already virtualizes rendering. That doesn’t eliminate the cost of loading, measuring cells, sorting, filtering, or repeatedly updating its data.

1. Separate the symptoms: initial population, scrolling, sorting, filtering, and live updates. Reproduce each with the same dataset and terminal size.
2. Capture a CPU profile while performing the slow action:
   ```sh
   py-spy record -o profile.svg --pid <pid>
   ```
   Stop recording after reproducing it, then open the SVG flame graph. Attaching may require elevated privileges. If a quiet capture contains almost nothing, retry with `--idle`; py-spy normally excludes idle threads.
3. Use the hot stacks to choose the next experiment:
   
   | Hot work | Experiment |
   |---|---|
   | Fetching, parsing, sorting, filtering | Time those stages separately from table updates |
   | Cell formatting or width measurement | Compare plain strings and fixed column widths |
   | Repeated population or refresh work | Batch updates; avoid rebuilding the table for small changes |
   | Synchronous work in event handlers | Move blocking work off the UI event loop |

An `async def` handler still blocks the UI when it performs long synchronous work. For blocking work, Textual’s `@work(thread=True)` is an option; marshal UI changes back through `self.app.call_from_thread(...)`. Pure Python CPU work may warrant a process.

`textual console` helps inspect logs, and `textual diagnose` reports the environment. **Neither measures performance**, and Textual has no built-in FPS overlay. Keep profiling diagnostics in a file or the separate console.

### Ink render performance

**No—the React DevTools you already connected won’t provide profiling.** Ink’s reconciler doesn’t enable the flags React’s Profiler requires. Keep DevTools for component-tree and props inspection.

Use Node’s CPU profiler instead:

```sh
node --cpu-prof dist/cli.js
```

Reproduce the slowdown, then exit normally so Node writes the `.cpuprofile`. Open it in Chrome DevTools or speedscope.

Look for unnecessary component renders, Yoga layout work, large mounted lists, and timers or spinners driving continuous updates. In particular, clipping an Ink list doesn’t virtualize it: mount only the visible slice.

For both projects, change one suspected cause at a time and repeat the same interaction. CPU profiles identify computation hotspots; pair them with elapsed timings when the visible delay may involve I/O or terminal output.
