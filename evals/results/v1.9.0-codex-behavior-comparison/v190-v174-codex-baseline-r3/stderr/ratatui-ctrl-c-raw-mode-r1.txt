My Ratatui app quits on `q`. Users report that Ctrl+C does nothing. Why, and what should the key handling be?

codex
Ratatui apps typically enable **raw terminal mode**, which disables the terminal’s normal Ctrl+C → `SIGINT` behavior. Ctrl+C arrives as a key event instead, so your app must handle it explicitly.

With Crossterm, match `Char('c')` plus the `CONTROL` modifier:

```rust
use crossterm::event::{
    self, Event, KeyCode, KeyEventKind, KeyModifiers,
};

if let Event::Key(key) = event::read()? {
    if key.kind == KeyEventKind::Press {
        let quit = match key.code {
            KeyCode::Char('q') => key.modifiers.is_empty(),
            KeyCode::Char('c') => {
                key.modifiers.contains(KeyModifiers::CONTROL)
            }
            _ => false,
        };

        if quit {
            break;
        }
    }
}
```

Ctrl+C is **not** `KeyCode::Char('\x03')` in Crossterm’s decoded key events. Checking `Press` also avoids acting on release events reported by some terminals.

Exit through your normal loop and restore the terminal—disable raw mode and leave the alternate screen—rather than calling `process::exit()`, which skips destructors and cleanup.
