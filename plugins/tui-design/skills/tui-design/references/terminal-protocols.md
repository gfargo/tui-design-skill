## How modes work

Full-screen apps switch terminal modes on with DECSET (`CSI ? n h`) and must switch each one off (`CSI ? n l`) on every exit path, including errors, panics, and suspend. That is the lifecycle contract in `SKILL.md`. Frameworks restore what they enable, but nothing you enable yourself: Ratatui's `restore()` undoes only raw mode and the alternate screen. Treat every capability query as optional. A terminal or multiplexer may answer late or never, so render a working default first and wait for replies with a timeout. OSC sequences travel in-band, so they work over SSH, containers, and nested shells: the emulator on the user's local machine interprets them. xterm's [control sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) define the classic modes; newer ones have their own specs, linked below.

## Modes and sequences

| Mode | Enable / disable | Detect | Support floor | Gotcha |
|---|---|---|---|---|
| **Bracketed paste (2004)** | `CSI ? 2004 h` / `l`; a paste arrives between `CSI 200~` and `CSI 201~` | DECRQM | Near-universal | Without it, kitty and Ghostty turn a pasted newline into Enter. Decide per field what a multi-line paste means; a single-line field keeps the first line or refuses, never submits. |
| **Kitty keyboard** | Push flags `CSI > flags u`; pop `CSI < u` on exit ([spec](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)) | `CSI ? u` | kitty, foot, Alacritty 0.13+, Ghostty, iTerm2, Rio, Warp, xterm.js, Windows Terminal 1.25+, WezTerm with `enable_kitty_keyboard` | Flag 1 makes Shift+Enter, Ctrl+Enter, Ctrl+Tab, and Ctrl+I distinct and sends plain Esc as its own code; flag 2 adds key release. Treat the extra keys as accelerators (see *Notes*). xterm's `modifyOtherKeys` (`CSI > 4 ; 2 m`) covers some of the same keys. |
| **Mouse (1000, 1002, 1003, plus 1006)** | `CSI ? 1000 h` (press, release), `1002` (adds drags), `1003` (adds every move); add `1006` (SGR encoding) | — | Universal | 1006 reports coordinates past column 223 and which button was released ([xterm](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Mouse-Tracking)). Enable the smallest mode the UI needs; crossterm's `EnableMouseCapture` turns on all of them. Any mouse mode takes over text selection (see *Mouse support* in `interaction-patterns.md`). |
| **Focus reports (1004)** | `CSI ? 1004 h`; the terminal sends `CSI I` and `CSI O` | — | Broad | Pause animation and polling when unfocused and refresh stale data on return. tmux forwards them only with `focus-events on`. |
| **Synchronized output (2026)** | Wrap each frame in `CSI ? 2026 h` … `l` ([spec](https://github.com/contour-terminal/vt-extensions/blob/05050a11e793c8f4362bf4e34a59ed3f7e5105fe/synchronized-output.md)) | DECRQM `CSI ? 2026 $ p` | kitty, WezTerm, foot, Alacritty, Ghostty, iTerm2, Windows Terminal 1.23.20211+, tmux 3.7+ | Always send the end sequence, error paths included; a stuck frame is released only by the terminal's own timeout (150 ms to 2 s). Without it, write each frame in one `write`, send only changed cells, and hide the cursor while drawing, then re-show it on the focused row or field (*Accessibility* in `visual-patterns.md`). |
| **Grapheme clusters (2027)** | `CSI ? 2027 h` ([spec](https://github.com/contour-terminal/contour/blob/b719d05aed54f29ee7d629f5dd7d760b2f4b4320/docs/vt-extensions/unicode-core.md)) | DECRQM | Reported by the terminal; Bubble Tea enables it, the other frameworks don't | With it on, emoji sequences and combining marks take the width the app computed. Where it is off, app and terminal can still disagree (kitty segments graphemes without 2027). Test emoji-heavy rows on the terminals you support. |
| **Cursor shape (DECSCUSR)** | `CSI n SP q`; reset with `CSI 0 SP q` on exit | DECRQSS `DCS $ q SP q ST`, reply `DCS 1 $ r Ps SP q ST` (xterm, tmux 3.6+) | Broad | Pair shapes with modes (`interaction-patterns.md` → *Keybinding philosophies and modal vs modeless*). `0` means the user's cursor in Windows Terminal, foot, and Ghostty but a blinking block in xterm, where patch 411+ restores the user's choice with `CSI 7 SP q`. Bound the DECRQSS wait and fall back to the reset. Ratatui's `restore()` doesn't touch the shape. |
| **Window title (OSC 2)** | Save `CSI 22 ; 0 t`, set `OSC 2 ; text ST`, restore `CSI 23 ; 0 t` | — | The save stack exists in xterm, kitty, foot, iTerm2, Alacritty, tmux; WezTerm, Ghostty, and Windows Terminal ignore it | Set a title only when it helps users find the window (open file, remote host). Where the stack is ignored the user's title is lost. Bubble Tea clears the title on exit rather than restoring it. |
| **Progress (OSC 9;4)** | `OSC 9 ; 4 ; state ; percent ST`: 0 remove, 1 normal, 2 error, 3 indeterminate, 4 paused ([ConEmu](https://conemu.github.io/en/AnsiEscapeCodes.html#ConEmu_specific_OSC), [Windows Terminal](https://learn.microsoft.com/en-us/windows/terminal/tutorials/progress-bar-sequences)) | — | Windows Terminal, Ghostty 1.2+, kitty, iTerm2, tmux 3.7+ | A terminal that knows only OSC 9 notifications may pop it up as one, so send it only where supported, and clear it with state 0 on every exit. Bubble Tea's view-level progress bar sends it unchecked. |
| **Prompt marks (OSC 133)** | `A` prompt, `B` input, `C` output, `D;exit-code` end ([proposal](https://gitlab.freedesktop.org/Per_Bothner/specifications/-/blob/6b555699e41ab47ce210610d1a17cfc1662ec8d7/proposals/semantic-prompts.md)) | — | Shell-integration terminals | Lets a terminal jump between prompts and select one command's output. A REPL marks its own prompts, adding `aid=` inside a shell that marks them too; a full-screen TUI should not. |
| **Color depth** | `COLORTERM=truecolor` or `24bit` ([convention](https://github.com/termstandard/colors/blob/caf0bb949ad64307d938a055f7fbec76ce65d91e/README.md#truecolor-detection)) | Env; XTGETTCAP `RGB` | Most modern terminals | `TERM` alone proves little. Libraries differ (see *Notes*). The variable is the first thing lost over SSH. |
| **Background color (OSC 11)** | Query `OSC 11 ; ? ST`; reply `rgb:rrrr/gggg/bbbb` | Follow with DA1 (`CSI c`) or `CSI 5 n` | The Linux console, PuTTY, mosh, GNU Screen, and ConEmu never answer; tmux 3.4+ answers with the attached client's colors | If the sentinel reply arrives first, no background reply is coming. Cap the wait anyway (Neovim 100 ms, lazygit 500 ms), render a default palette meanwhile, and switch when the answer arrives. |
| **Dark/light changes (2031)** | `CSI ? 2031 h`; reports `CSI ? 997 ; 1 n` (dark), `; 2 n` (light); `CSI ? 996 n` asks ([spec](https://github.com/contour-terminal/contour/blob/ab57ab3288c3dca5ff727311cb3f1401bac30549/docs/vt-extensions/color-palette-update-notifications.md)) | DECRQM | kitty 0.38.1+, Ghostty, foot 1.23+, iTerm2 3.7+; tmux 3.6+ (guesses from the background; 3.8 forwards the outer terminal's theme); not WezTerm | Re-query OSC 11 on each report rather than trusting it alone (lazygit and Neovim do), and turn the mode off before handing the terminal to a child. Bubble Tea passes reports through without enabling it; Textual, Ink, and Ratatui don't handle it. |
| **Hyperlinks (OSC 8)** | `OSC 8 ; params ; URI ST` text `OSC 8 ; ; ST`; `id=` joins one link across wrapped lines | — | iTerm2, kitty, WezTerm, Ghostty, foot, Windows Terminal 1.4+, Alacritty 0.11+, tmux 3.4+ | Unsupported terminals show the plain text, but strip the sequence when stdout isn't a TTY. Simple filters skip ids; full-screen apps set them. |
| **Clipboard (OSC 52)** | `OSC 52 ; c ; base64 ST` | — | Most terminals; some disable it | Write-only by design; keep payloads to tens of KB (about 75,000 decoded bytes is the common ceiling). Details in *Notes*. |
| **Notifications (OSC 9, 777)** | `OSC 9 ; message ST`; `OSC 777 ; notify ; title ; body ST` | — | OSC 9: kitty, WezTerm, Ghostty, iTerm2, foot. 777 with a title: WezTerm, Ghostty, foot | Never start an OSC 9 message with digits and a semicolon (it collides with `9;4` progress); prefix the text or use 777. tmux needs DCS passthrough. |

## Notes that change a decision

- **Keyboard fallback.** Every action still needs a binding that works in the legacy encoding, which is what reaches you inside tmux, whose `extended-keys` option is off by default. Rust apps that enable extra modes also own their teardown (`ecosystem-rust.md`).
- **Color depth libraries.** chalk 6 accepts only `truecolor` (with `24bit` it falls back to whatever `TERM` suggests); crossterm consults `TERM` only when `COLORTERM` is unset. OpenSSH forwards no environment variables by default, and only recent Debian and Ubuntu send and accept `COLORTERM` at both ends. tmux 3.6+ sets it in its panes and downsamples for the outer terminal. To recover truecolor remotely, ask the terminal (XTGETTCAP `RGB`, which Bubble Tea's capability request sends) or let users set it; otherwise fall back to 256 colors over the 16-color theme from `visual-patterns.md` → *Color in depth*.
- **Links over SSH.** The link opens on the user's local machine, so a `file://` URI for a remote path won't resolve. For "open this file", suspend and spawn `$EDITOR` remotely; keep OSC 8 for `https://` URLs. Lipgloss v2 has `Style.Hyperlink(url)` and Rich/Textual use the `link` style. Ratatui has no native support: escape sequences inside `Text` or `Span` break its per-cell width accounting (open issue #1227), and the `hyperrat` crate and `tui-link` repo only work around the buffer model.
- **Clipboard security and fallbacks.** Reads are how a malicious remote exfiltrates data, so most terminals disable or prompt on them (kitty prompts, WezTerm ignores queries, Alacritty disabled paste-back by default in 0.13). Alacritty also ignores writes from unfocused windows since 0.11, so a background job can't count on the write landing. Design for write-only, treat it as best effort, and keep a local fallback (`pbcopy`, `xclip`, `wl-copy`, Rust's `arboard`). In tmux, `set-clipboard on` lets inner apps set the outer clipboard (`external`, the default since 2.6, reserves it for tmux); forwarding needs an `Ms` terminfo entry or, in tmux 3.6+, the terminal's device-attributes reply. tmux handles OSC 52 natively and doesn't need `allow-passthrough`. crossterm 0.29 added OSC 52 copy; Bubble Tea v2 ships `tea.SetClipboard`.
- **Notification etiquette.** Notify only when long-running work finishes or fails while the user is likely elsewhere. Fire once, keep it short, and prefer in-UI status when the app has focus. Never notify for routine events or things the user just did. A reasonable strategy is OSC 777 where you know it works, else OSC 9.

## Terminal environments

The same app runs inside multiplexers, over SSH, and on Windows consoles. Each changes which keys arrive and which modes work:

| Environment | What breaks | Detect | Fallback |
|---|---|---|---|
| tmux | The prefix `Ctrl+B` never reaches the app. A lone Esc waits `escape-time` before delivery (500 ms before 3.5, 10 ms since). Since 3.8 the `mouse` option defaults to on: unless the app enables mouse reporting, a plain drag starts tmux's copy-mode selection and the wheel enters copy mode (except on the alternate screen), while Ctrl-drag, Alt-drag, and Alt+right-click always belong to tmux | `$TMUX`, `TERM_PROGRAM=tmux` | Never make `Ctrl+B` the only path to an action; document the `tmux.conf` options below |
| GNU screen | The prefix `Ctrl+A` never reaches the app. Truecolor is dropped unless `truecolor on` (5.0+); OSC sequences other than titles and colors are discarded; the alternate screen is off by default. The default flow control (`auto`) still passes Ctrl+S and Ctrl+Q to raw-mode apps on Linux, but `flow on` swallows them | `$STY`, `TERM=screen*` | 256-color theme; no OSC-dependent feature without a fallback; clear the screen on exit |
| Zellij | Its default mode captures `Ctrl+G/P/T/N/H/S/O/Q/B` and many Alt keys. The Unlock-First preset (0.41+) frees the Ctrl keys but keeps its Alt bindings | `$ZELLIJ` | Keep a non-Ctrl, non-Alt path to every action; point users at Unlock-First |
| SSH | Every capability query costs a network round trip; `COLORTERM` usually doesn't arrive; the remote may lack terminfo for the local terminal (kitty's `xterm-kitty`, Ghostty's entry); OSC 52 is the only clipboard path | `$SSH_TTY`, `$SSH_CONNECTION` | Bounded query timeouts, truecolor from a query or a user setting, `TERM=xterm-256color` when terminfo is missing (kitty's `kitten ssh` and Ghostty's SSH integration copy it over) |
| Windows | No SIGTSTP, SIGWINCH, or SIGCONT: no job-control suspend, and resize arrives as console events. The legacy console has no VT processing before the Windows 10 Anniversary Update. Windows Terminal sets no `TERM` or `COLORTERM` | `WT_SESSION` (Windows Terminal) | A non-suspend path to the shell; target Windows Terminal, the default since Windows 11 22H2. Go, Rust, and Python write Unicode through the wide console API, so no `chcp 65001` is needed |
| CI, pipes | No TTY: no prompts, no full-screen UI | `CI`, stdout not a terminal | `cli-basics.md` → *Interactivity* and *Output design* |

Sources: [tmux.1](https://github.com/tmux/tmux/blob/3.8/tmux.1) and [CHANGES](https://github.com/tmux/tmux/blob/3.8/CHANGES) at 3.8, [screen.1](https://git.savannah.gnu.org/cgit/screen.git/tree/src/doc/screen.1?h=v.5.0.2) at 5.0.2, [Zellij's keybinding presets](https://zellij.dev/documentation/keybinding-presets.html), [Microsoft's console VT notes](https://devblogs.microsoft.com/commandline/new-experimental-console-features/), and the [Windows 11 default-terminal announcement](https://devblogs.microsoft.com/commandline/windows-terminal-is-now-the-default-in-windows-11/).

**tmux options.** tmux answers or forwards most of these itself: synchronized output and progress (3.7+), hyperlinks (3.4+), the clipboard (`set-clipboard`), focus reports (`focus-events on`), extended keys (`extended-keys`), and the dark/light theme (3.6+). Notifications and image protocols need DCS passthrough (`ESC P tmux; … ESC \` with every inner ESC doubled) and `allow-passthrough on` (tmux 3.3+), which is off by default ([tmux.1](https://github.com/tmux/tmux/blob/3.8/tmux.1)). Several of these depend on options that are off by default, so document the `tmux.conf` lines your app needs.
